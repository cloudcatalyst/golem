## Problem

The cache-prefix lookback-window prediction (lines 288-302) uses a heuristic: `appendedBlocks >= LOOKBACK_WINDOW_BLOCKS && next.breakpoints <= 1` to decide "append" vs "bust". The decision is based on Anthropic prompt-caching docs from one point in time. If upstream caching behavior changes, the binary `append` claim becomes a misleading "hit predicted" that actually missed.

The `CachePrefixVerdict` type is `"first" | "append" | "bust"` — no room for "uncertain" or "probably-append". The PipelineEvent downstream reports it as a fact.

## Fix

Two options:

**Option A:** Add an `"uncertain"` verdict to the type, used when the lookback window's prediction does not meet confidence thresholds.

**Option B:** Document the limitation on the `CachePrefixVerdict` type and in the `CachePrefixObserver` class doc, so future readers know it's a prediction.

## Out of scope

- Removing the lookback prediction (it's still useful for the common case)
- Adding a proper confidence score or probability
