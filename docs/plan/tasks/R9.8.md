## Goal

Decision 53(h) shipped an opaque `compression.headroom_config` bag so upstream
Headroom options arrive without a Golem release. It does not go far enough: the
worker filters the bag against **`CompressConfig.__dataclass_fields__` only**
(`_supported_config_fields`), and `headroom.compress()` in turn forwards exactly
eight kwargs to `pipeline.apply()`. Everything nested below that is unreachable.

## What this actually costs (found 2026-08-09, dogfooding)

Working an editing-heavy session at slider 3 produced a loop: tool output came
back rewritten — `<<ccr:c97094e0ac95,string,270B>>` refs, a markdown table
crushed to `[17]{record:string,what:string,when:string}`, and
`[Read content stale: X was modified after this read …]` markers — so an
exact-match `Edit` built from what the model *saw* failed against the file's
real bytes. **At level ≥2 the model's view of a file can differ from disk**, and
the agent has no way to ask for marker-free output short of dropping the level.

Headroom 0.30.0 has the exact switch for this, and it is unreachable:

- `SmartCrusher.lossless_only: bool = False` (`config.py`) — *"any path that
  would emit a CCR marker (lossy row-drop OR opaque-blob offload) leaves the
  content uncompacted instead, so the output is always marker-free and
  byte-recoverable … with this on, no `<<ccr:…>>` markers are produced
  regardless of CCR settings."* Lossless tabular compaction still runs, so the
  saving is largely kept.
- `ReadLifecycleConfig` (`enabled`, `compress_stale`, `compress_superseded`,
  `min_size_bytes`) — declared in `config.py` and **not consumed anywhere in the
  Python package**; the transforms live in the Rust core. Establish where it is
  actually configurable before designing against it.

**Consider whether `lossless_only: true` should be Golem's DEFAULT.** Golem's
flagship client is a coding agent that does exact-match edits; a marker in a tool
result is precisely the thing that breaks one. That is a Decision, not a config
tweak — argue it in the ADR/spec rather than flipping it quietly.

## The silent-drop half

`.golem/settings.local.json` in this repo carries
`headroom_config: {"plugins":[{"name":"openrouter-context-compression"}]}`.
`plugins` is not a `CompressConfig` field, so it is filtered out and never
applied. The adapter has the machinery to say so (`headroom-adapter.ts:455`
builds the "this Headroom ignored …" warning) — verify it actually reaches a
surface the user reads. A setting that does nothing and says nothing is the
failure mode 53(h) exists to prevent.

For reference, the eight reachable fields today: `compress_user_messages`,
`compress_system_messages`, `protect_recent`, `protect_analysis_context`,
`target_ratio`, `min_tokens_to_compress`, `kompress_model`, `savings_profile`.

## Also worth deciding

Golem's level-3 preset sets `compress_user_messages: true` (`headroom-worker.py`
`_MODE_PRESETS["aggressive"]`). Headroom's own default is `False`, documented as
*"skip them for coding agents"* — and tool_result blocks ride inside `user`
messages in the Anthropic Messages API. Level 3 therefore opts a coding agent
into exactly the compression Headroom says coding agents should skip. Measure
before changing; it may be deliberate, but it is not currently written down.

## Hard constraints

- Unknown keys stay **reported, not passed** — forwarding one raises inside
  `CompressConfig` and takes the request down. Widening reach must not weaken that.
- The Headroom pin is governed by the T-C4 upgrade playbook; this task does not
  move it.
- Redaction ordering is untouched. This is a compression-config surface only.

## Out of scope

Vendoring or patching Headroom. Rewriting the sidecar protocol. Turning the
semantic stage on for caching upstreams — that is `force_semantic_on_caching`
(off by default for the §103 reason) and a separate question.
