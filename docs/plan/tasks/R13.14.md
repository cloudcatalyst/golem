## Why this is separate from R13.12

R13.12's brief scoped the removal into itself. Splitting it out is a sequencing
call, not a change of mind:

1. **The replacement is not yet confirmed end to end.** R13.12 verifies that
   `golem init` writes a correct definition, that the frontmatter matches the
   shape verification-notes §114 quotes, and that the `coder` tool declines and
   names the subagent. What no test in this repo can verify is the part that
   matters — that Claude Code actually honours `model: claude-sonnet-5` in a
   generated agent, runs the delegation, and routes it through
   `ANTHROPIC_BASE_URL` so Golem still sees it. That needs one real delegation in
   a live session.
2. **`claude-cli` currently works.** Deleting a working mechanism before its
   replacement is confirmed inverts the safe order, and this repo has a name for
   the alternative discipline: verify, don't assume.
3. **One workstream per PR.** The removal touches nine files and deletes two,
   with a migration path of its own. It is not a footnote to a feature.

## Why it goes

Its own module header states the disqualifying property:

> "`ANTHROPIC_*` goes, so the child talks direct to Anthropic on its own OAuth
> rather than looping back through Golem's own proxy via `ANTHROPIC_BASE_URL`"

That is correct for a spawn and it means **Golem sees none of that traffic** — no
redaction stage, no compression, no telemetry. Add the rest of what the spawn
deliberately is, from the same header:

> "It is a TEXT CALL, not an agent: no session persistence, no MCP, no file or
> exec tools, and a temp working directory, so no `CLAUDE.md`, no hooks and no
> project state are discovered."

…plus a full CLI cold start per draft and a 180s timeout. A subagent on a routed
model gets real tool use, its own context, and stays inside the pipeline. There is
nothing left that the spawn does better.

## The one check that gates this

Set `inference.default_coder = "claude-sonnet-5"`, run `golem init`, then delegate
a real coding task to the `golem-coder` subagent in a live Claude Code session and
confirm:

- it runs (the frontmatter model is accepted, not rejected as unknown);
- it is served by Sonnet, not the parent's model;
- Golem saw the traffic — per-target attribution in `golem status`, or a telemetry
  row. **This is the load-bearing half**: it is the difference between the
  subagent route and the thing being removed.

Recording the result belongs in verification-notes either way. If it fails, this
task does not proceed and R13.12's brief needs revisiting instead.

- `golem gateway add --provider` help text and the provider enum in the CLI.

## Decide while doing it

- **What happens to `isSpawnProvider` and R13.13's fix?** With `claude-cli` gone
  there are no spawn providers, so `isSpawnProvider` returns false for everything
  and R13.13's `&& !isSpawnProvider(...)` guard becomes vestigial — and its test,
  which registers a `claude-cli` gateway, stops compiling. Two options: delete the
  predicate and revert that half of R13.13 (simpler, but re-creates the defect for
  the next non-translating non-forwarding provider), or keep the predicate as an
  empty set with a comment saying why. **Do not decide this by tidiness** — R13.13's
  debrief records the general lesson, and the point of the guard was that
  `!isTranslatingProvider` is the wrong question, whatever the provider list
  happens to be today.
- **Migration shape.** A `claude-cli` gateway in existing settings must fail
  closed with a message naming `inference.default_coder` as the replacement. Note
  that the schema validates `provider` against an enum, so removing the member
  makes the settings file fail to *parse* — which would break `golem status` and
  every other command, not just the coder. That is worse than a targeted error;
  the enum may need to keep the value as a deprecated-and-rejected case rather
  than dropping it outright. Work this out before deleting the enum member.
