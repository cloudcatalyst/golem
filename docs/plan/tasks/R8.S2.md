## Goal

Pi attributes part of its token efficiency to a minimal system prompt, and Golem *can*
rewrite `system` — Decision 52 already appends to it. Measure whether trimming it pays.

## Expect the answer to be no

The system prompt was **3,350–3,365 tokens** in both ledger captures (§95, §100) —
1.1–2.4% of the request. It sits in the cached prefix, so removing bytes saves
cache-*read* at 0.1×, while the removal itself costs **one full re-prefill**. Net
positive only over a long session, and the behaviour risk is high: `system` is where
the client puts the instructions that make it work.

`golem stats --context` already reports the number, so this spike is cheap: read it,
do the arithmetic, write the finding.

## Why run it at all

Because §100's lesson is that the arithmetic is the deliverable. "We measured the
system prompt at ~3.4k, 2% of the request, and declined" is a publishable sentence and
stops the idea recurring. Compare R8.S1: promoted twice before anyone attributed the
tokens.

## Hard constraints

If it somehow does pay: brevity's marker-fenced, **byte-stable** append is the only
precedent for touching `system` (Decision 52), and any change must be byte-stable
across turns or it busts the prefix every request.

## Definition of done

A `verification-notes.md` section with the measured net and a verdict. A rejection is a
complete outcome.
