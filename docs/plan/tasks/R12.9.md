## Why this is a separate task, and `owner: user`

R12.8 delivers a relay anyone can run. This is the decision to run one *for other
people*, which is a different kind of act: it creates uptime, abuse and
incident-response obligations Golem has never had, and it means holding account
records belonging to strangers. An agent must not stand that up, the same way an
agent must not publish to npm (R7.5) or point DNS at a host (R7.6-infra).

## What it involves

- **An identity/PII ADR first.** The account is the first time Golem stores
  anything about a person on a server it operates. ADR-0003 is the shape: what is
  stored, where, who can read it, what an attacker gets, what deletion means.
  ADR-0006 §3c bounds the *authority* an account carries; it says nothing about
  the data, and that gap is this task's first deliverable.
- **The account system.** Own auth or a provider, with **mandatory 2FA** — §3c
  makes that non-optional, because the account fronts a channel to a developer's
  machine.
- **Deployment**: the host, DNS, TLS, monitoring, and a runbook for the relay being
  down (which is safe — silence denies — but is still someone's blocked afternoon).
- **Abuse and ToS.** A relay is a general-purpose byte pipe between two consenting
  endpoints. Decide what the terms say and what happens on report, knowing the
  relay is blind by design and therefore *cannot* inspect content to adjudicate.
  That tension is the interesting part and it should be written down, not
  discovered later.
- **The pricing question**, which Decision 20e already flags as the hosted-tier
  candidate. A relay account is the first thing a user could plausibly be billed
  for. ADR-0006 deliberately does not decide it.

## The standing obligation this creates

ADR-0006 §3b keeps Alternative 4 "adopted" only while **self-hosting stays a
tested path**. Operating a public relay creates the gravitational pull toward
"just use ours" that would make golem.run load-bearing for the product and break
the local-first positioning (Decision 32). So part of this task is the mechanism
that keeps the self-hosted path honest — a test, a documented recipe, or a
periodic check that someone actually runs it.

## Out of scope

The protocol and the reference server (R12.8). Anything that would make the relay
able to read traffic, approve a request, or enrol a device — those are forbidden by
ADR-0006 §8 and no operational convenience unlocks them.

## Gate

An accepted identity/PII ADR, then a public relay that a second machine reaches
with an account and 2FA, with the self-hosted path still demonstrably working. And
one honest sentence in the docs about what the operator can see.
