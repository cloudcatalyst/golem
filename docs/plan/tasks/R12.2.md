## What is thin about it today

`SessionState` is `{ blocked, reason?, sessionId?, ts }` and `reason` is whatever
string the Notification hook happened to receive. That is enough for a dot on a
status line. It is not enough for a human 20 minutes away deciding whether to
approve something: **"waiting on your input" is not an approvable question.**

## What it must carry

Enough for a remote human to make a *correct* decision, and no more:

- **Which project and which session** — a phone may be watching more than one, and
  `sessionId` alone does not name a working tree.
- **What the block actually is** — a permission request, a plain question, or an
  idle turn. These are different decisions and today they collapse into one flag.
- **For a permission request: the tool and the argument the human must judge.**
  A `Bash` command, a file path, a URL. This is the whole point — and it is also
  the reason redaction is not optional here (below).
- **Since when**, so a stale block is visibly stale rather than silently current.
- **Whether it is still open.** Today the file's `blocked: false` depends on a
  later hook firing; establish what happens when the session dies mid-prompt, and
  make a reader able to tell "unblocked" from "nobody ever wrote again".

## Redaction is a hard requirement, not a later pass

This file is about to become the payload of a remote surface, and it is the first
Golem-written artefact whose *purpose* is to carry a verbatim tool argument.
Anything written here goes through the redaction stage first
(`src/pipeline/redaction.ts`) — the same rule as everything else, with no new
exception. A `Bash(curl -H "Authorization: Bearer …")` prompt must land in the
file already redacted, because R12.5 will put it on a phone screen and R12.4 will
put it on a wire.

## Out of scope

Any network listener, any binding beyond `127.0.0.1`, any *write* path (approving
is R12.3), and the phone UI (R12.5). This task deliberately ships value with no
remote channel at all: a better local "blocked" indicator, and a contract the
guarded step can be built against. It is safe to do **before** ADR-0006 for
exactly that reason.
