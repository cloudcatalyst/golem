## Goal

Route an individual request to a provider based on capability or availability, rather
than switching the whole account.

## Why this is a decision, not a task

R6.2 shipped **account switching** (Decision 21d, ADR-0003 ACCEPTED) with the user's ToS
scope explicitly limited to *legitimate switching only*. **Quota evasion is OUT.**

Per-request routing sits close to that line, and route-on-exhaustion sits on it: "this
account is out, use the next one" is the exact behaviour ADR-0003 rules out. So the
blocking artifact is a Decisions Log entry that says which of these is legitimate, not
code.

What is already built and can be reused once the line is drawn: the `proxy.accounts`
registry, `resolveActiveUpstream` (fail-closed, no silent cross-account fallback), the
OS-store credential chain (Decision 46/47), and the provider translators (R6.1).

## Out of scope

Implementing route-on-exhaustion before the decision. Anything that makes exhaustion of
one account automatically consume another.

## Update 2026-08-01 — the decision was made, and it splits this task

The user asked for per-request routing by name across local and upstream backends
("use Fable 5 to plan …", "Opus 4.8 via OpenRouter", "Kimi K3 on my Moonshot AI
subscription"). Every one of those is **named by the user**, which is the same act as
`golem account use` scoped to one request rather than a session — ADR-0003's
"legitimate switching" column, not arbitrage.

So this task splits:

- **21e-a — explicit, user-named per-request routing.** Unblocked. Carried by
  **[R8.19](R8.19.md)**, gated on ADR-0005 (the reach question is now *prompt-directed
  spend*, not credential storage).
- **21e-b — automatic route-on-exhaustion / rotate-on-429.** **Still blocked, still out
  of scope.** The user did not ask for it and ADR-0003 rules it out. It must stay
  *absent* rather than built-and-disabled (ADR-0004's precedent: the guarantee is the
  absence of the mechanism). A 429 from a named upstream is reported; a human names the
  next one.

This file remains open for 21e-b only. Do not implement it without its own Decisions
Log entry.
