## Goal

Grant permissions and steer a session from a phone or a locally-hosted web UI — a
self-hosted relay, mTLS, default-deny when the link drops.

## Why it is deferred rather than scheduled

It is the highest-severity item on the roadmap: it opens a remote path to *approving
tool calls*, which is the exact capability the autonomy gate exists to constrain. The
R6 design memos deliberately **excluded** it at the user's direction — every other R6
task got a memo, this one needs a threat model.

## The gate is the deliverable

Write the ADR first, in the shape of ADR-0002 (autonomy) and ADR-0003 (credentials /
ToS): assets, adversaries, trust boundaries, failure modes, and what happens on link
loss. Only then decide whether to build.

Non-negotiables to carry into it:
- **Default-deny on link loss.** A dropped connection must never mean "approve".
- Self-hosted relay only — no Golem-operated service in the path.
- mTLS, not a bearer token in a URL.
- The autonomy gate stays the authority; remote approval is an input to it, never a
  bypass.

## Out of scope

Building anything before the ADR is accepted. A hosted relay. Push notifications as a
substitute for a trust model.
