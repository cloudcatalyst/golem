## Goal

Make Golem's own local path survive the ways small models actually fail, independently of
whether R8.16's harness ever ships. These are the mechanisms little-coder ships as pi
extensions, re-implemented as Golem's own code against Golem's own surfaces —
`tier-3b` in the `src/ext/manifest.ts` sense: cite the source, copy nothing.

## Why

`coder` currently returns whatever the drafter emitted. Small models routinely emit:

- **pseudo-tool-calls as prose** — a ` ```tool ` fence, a `<tool_call>` block, or bare
  JSON where code was asked for. Golem hands that straight back as a "draft".
- **empty or degenerate completions** — nothing, or the same three lines repeated until
  the token cap. `refineDraft` judges *quality*; it has no notion of *degeneracy*, so a
  loop can pass a judge that is looking for correctness.
- **runaway thinking** — reasoning models burning the whole budget before any output,
  which on this path shows up as `InferenceTimeoutError` (§66) and reads to the user as
  "the endpoint is broken" when it is not.

The repo has already paid for the general form of this once: the 2026-07-17 judge bug,
where a failure disappeared into a silent `catch` and looked like a prompt problem for
weeks. The rule that came out of it — **no silent zeros, report the failure** — is what
this task applies to the drafter's output rather than to its availability.

## What to do

- **Output repair.** Recognise and unwrap the common malformed shapes before the result
  is returned. Pure function, unit-testable, no model call. Repair must be *reported*
  (the result says it was repaired and how), never silent — a repair that is wrong is
  worse than a draft that is visibly broken.
- **Degeneracy detection.** Empty, truncated-mid-token, and n-gram-loop detection on the
  completion. A detected degenerate result gets one bounded retry, then is **reported as
  degenerate** rather than returned as prose. Reuse the explicit-status pattern
  `RefineStatus` already established in `coder-refine.ts`.
- **Thinking budget.** Cap thinking tokens per local turn where the backend exposes the
  control, and retry once with thinking off on a timeout instead of surfacing
  `InferenceTimeoutError` as the whole answer. The existing
  `inference.request_timeout_ms` semantics stay; this is what happens *before* giving up.
- **Read-before-edit as an invariant.** `coder-edit.ts` validates the *result* (it still
  parses, no definition vanished). The cheaper guard little-coder ships is refusing to
  edit a file the caller has not read this session. Add it as a precondition, not a
  second validation.

## Out of scope

- **Anything that costs definition tokens.** These are behaviours behind the existing
  `coder` schema. If a mechanism needs a new input property, it does not belong here —
  §100's arithmetic applies (Golem's whole tools contribution is 1,130 tokens).
- **A new judge or reranker model call.** Repair and degeneracy detection are pure; only
  the bounded retry costs a call.
- **little-coder's `skill-inject` / `knowledge-inject`.** Golem's KB grounding is the
  better version of that idea and this task must not regress it.
- **The agent loop.** That is R8.16.

## Gate detail

Measured on real output, not synthetic strings: run `golem bench` (or a recorded corpus of
actual drafter completions from this machine) before and after, and report how many
responses changed class — repaired, flagged degenerate, or unchanged. **REGRESSED is an
acceptable answer** (§89/§100 precedent) and must be recorded as such in
`verification-notes.md` rather than quietly re-tuned until it isn't.
