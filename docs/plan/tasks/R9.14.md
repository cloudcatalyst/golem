## Goal

Found while wiring `coder` to an Anthropic Sonnet 5 target, 2026-08-09: the tool
returned **401 Unauthorized** for `sonnet-5` *and* for `openrouter-qwen3`, a
target `golem target list` truthfully reported as `key set — DPAPI-encrypted`.

Decision 47 hands a credential to a process the CLI **spawns** — that is why
`credentialEnvForProxy` is called from the proxy start paths, `golem account`
and `golem init`. Claude Code spawns the MCP server itself, from `.mcp.json`,
which carries no `env` block. So the MCP process inherits no
`GOLEM_UPSTREAM_API_KEY__*` at all, `target-dispatcher.ts` read `undefined`,
`makeAuthMapper` returned `undefined`, and the request went out with **no auth
header whatsoever**. Every credentialed target was unreachable from `coder`,
not just Anthropic ones.

## What the work is

- **`resolveKey` on `TargetDispatcherOptions`** — an optional
  `(accountId: string | null) => string | undefined | Promise<…>`. When absent,
  the existing env lookup is used unchanged, so the proxy path and every
  existing test keep their behaviour.
- **`golem mcp serve` installs one**, backed by `credentialEnvForProxy` so the
  store-id mapping (active account versus a named one) has exactly one
  implementation. Lazy and cached: a session that never dispatches remotely
  never touches the credential store.
- **Secrets stay in the closure, never in `process.env`** — which is the reason
  to prefer a resolver over injecting env at startup. The MCP server spawns
  capability probes and Ollama calls; env would be inherited by all of them.
- **Fail by name.** A target whose resolved auth scheme is not `inherit` and
  whose credential does not resolve now throws naming the target and the
  account, instead of dispatching unauthenticated to earn a 401 that names
  nothing. `auth_scheme: inherit` still dispatches with no header — that is a
  deliberate configuration, not a missing credential.

## Out of scope

- Changing Decision 47's env handoff for the proxy daemon. It works there
  because the CLI does the spawning.
- Storing credentials (`golem account login` is `owner: user`).
- Adding an `env` block to `.mcp.json` — that would put secrets in a committed
  file, which is the thing the credential store exists to avoid.
