## Where this sits after Decision 56

Decision 56 retired the "default local coder with a defined model" framing, and this task
is the other half of that: the coder stops being *a model* and becomes **a harness** —
one that may be handed to an agent, pointed at a local endpoint, with **no remote upstream
in its reach at all** (ADR-0005 §5 makes that an enforced property rather than a
configuration habit). R8.18 supplies the model it runs on; R8.19 supplies the lane it is
named in.

## Goal

Give `coder` a second mode that hands a task to a **real agent loop** — multi-turn,
tool-using, able to run a test and read its own failure — instead of the single-shot
draft it does today. Back that mode with
[little-coder](https://github.com/itayinbarr/little-coder) (Apache-2.0), **spawned beside
Golem as an ext**, never linked into the process.

## Why

`coder` today is one `inference.chat("drafter", …)` at `src/mcp/server.ts:1810`, plus
optional KB grounding, plus an optional judge→revise pass, plus R8.7's `edit` mode over
one small file. It cannot iterate, run a test, read a second file, or recover from its own
malformed output. Every one of those is a turn of an agent loop it does not have.

little-coder is that loop, tuned for exactly the model class Golem runs. Its headline
result is not the absolute score — **19.11% → 45.56% on Aider Polyglot at a fixed 9.7B
model**, i.e. scaffold–model fit, measured on 8 GB of laptop VRAM. Full benchmark table
in the design doc; the numbers are modest in absolute terms and that is not the point.

## The ADR is the precondition, and the hazard is egress

**No spawn code lands until ADR-0005 is accepted.** This is R8.11's ordering applied to a
different risk class, and the task states it for the same reason that one did.

Every ext in the registry today is local-only: Headroom is a local sidecar, Ollama is
local, `typescript-language-server` is local. **little-coder speaks `anthropic/*` and
`openai/*` natively.** A spawned session pointed at a cloud model leaves the machine
without ever transiting Golem's proxy or its redaction stage. That is the first ext with
an egress capability of its own, and the CLAUDE.md hard rule — never weaken redaction —
is not satisfied by documenting it. The ADR must decide how the provider set is
constrained to local-only **at spawn**, not by advice.

The other questions the ADR owes an answer to:

1. **Filesystem writes.** The harness writes to the user's repo. Is that ADR-0002's
   autonomy gate, a checkpoint-and-diff like `coder-edit.ts`, or a worktree? Do not invent
   a fourth approval concept.
2. **What the harness is told.** Its prompt carries project code. Local-only egress makes
   that survivable; anything that changes the egress answer changes this one too.
3. **Absence, failure, and hang.** Criterion 3 of the ext admission bar — a missing or
   broken binary is a described no-op, never an error path. A hung child needs a bound.
4. **Concurrency.** Their own docs: sub-coders run **serially by default**, because two
   contend for one local inference server and finish slower than one. Any Golem fan-out
   onto local inference inherits that.
5. **What Golem is NOT delegating.** The harness does not get Golem's KB, its wiki writes,
   its credentials, or its settings writer — the ADR-0004 §5 narrow-context principle,
   restated for a process boundary.

## What to do, after the ADR

- **An `ext` row** in `src/ext/manifest.ts`: `tier-2`, `callable`, upstream + Apache-2.0
  licence recorded, an exact `pin`, spawn-free `{kind: "command"}` detection, an `install`
  string Golem prints and never runs, `enabledBy`, and the single adapter file that
  quarantines the invocation.
- **A mode of `coder`, not a new tool.** `mode: "agent"`, declared only when the setting
  is on *and* the binary resolves — R8.6/R8.7 discipline, because a second tool definition
  is ~300 tokens on **every** request (§100 rejected a workstream over less). With it off,
  `coder`'s definition must be byte-identical to what R8.15 leaves behind, and a test
  should assert that rather than trusting it.
- **Headless only.** Drive it through pi's `--mode rpc`; never a TUI. Golem's own
  `benchmarks/rpc_client.py` equivalent already exists upstream as a reference for the
  event/UI-request demux.
- **Point it at Golem's own resolved provider** (R8.15), so "which local model" has one
  answer on the machine, not two.
- **Report honestly:** which model actually ran, how many turns, what it wrote. The
  R4.4 lesson — a silent zero is worse than a reported failure.

## Out of scope

- **pi as a dependency.** Spawn only. Golem's runtime-dependency ceiling (R8.10, ≤5)
  is untouched and `verify:deps` must still pass.
- **Vendoring, mirroring or auto-installing little-coder.** Decision 53: Golem ships none
  of its bytes. If R8.14 lands `golem ext install`, this one may use it — at a pin, with
  consent — and never on first use.
- **Their `skill-inject` / `knowledge-inject`.** Keyword scoring over markdown files;
  Golem's vector KB plus wiki-title/one-hop-wikilink matching is strictly better. Adopting
  theirs is a regression, not an uplift.
- **Their status line, compaction watchdog and cache-hit tracking.** That is the R8
  context-economy workstream. Two competing context economies is the failure mode.
- **Replacing `coder`'s draft or edit modes.** This is a third mode for work the other two
  cannot do, not a migration.
- **The small-model robustness mechanisms** — those are R8.17 and must not be smuggled in
  here.

## Gate detail

`ADR-0005` accepted first. Then: the enabled-off definition is byte-identical; a spawn
with a cloud provider configured is **refused, not warned about**; a missing binary
produces a described no-op; and one real agent-mode run on this repo is recorded in
`verification-notes.md` with the model, turn count and wall-clock.
