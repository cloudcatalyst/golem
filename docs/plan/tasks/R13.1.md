## Why this exists, and why it is first

ADR-0007's primary mechanism is a session Golem hosts: spawned locally, in a
project root, through Golem's own proxy, with a device as its chat client. The
whole design rests on one unverified assumption — that the `claude` CLI can be
driven as a **long-lived, multi-turn conversation** rather than a one-shot
`-p` invocation.

This is the task that finds out. It is deliberately the only R13 task that is
not blocked on the ADR's acceptance, because measuring a runner commits nobody
to anything, and because a negative result changes the ADR rather than the
schedule.

## What to establish

Record the client version (`claude --version`) with every finding. Label each
one **OBSERVED** (you ran it) or **DOCUMENTED** (the docs say so, you did not
run it). Do not simulate a run and present it as one.

1. **Multi-turn input.** Can a spawned process accept a *second* user message
   after the first turn completes, without exiting — e.g. streaming JSON on
   stdin? Establish the exact flag spelling and message envelope from the live
   CLI reference, then run it.
2. **Streamed output, structured.** Does the process emit assistant text, tool
   calls and tool results as separable events (not just final text)? ADR-0007 §2
   promises visible tool calls, so this decides whether that promise is
   deliverable.
3. **Interruption.** Can a running turn be cancelled without killing the
   session? If only process-kill works, say so — §2's "interrupting a running
   turn" then needs rewording.
4. **Resume and identity.** Does `--session-id` / `--resume` give a stable
   handle across process restarts, and does that handle survive a machine
   reboot? `src/tasks/types.ts` already records `sessionId` for this purpose.
5. **Working directory and project scope.** Is cwd enough to bind a session to a
   project root, and does the project's `.claude/` settings, hooks and MCP
   wiring load the same way as for an interactive session? Golem's own hooks
   must fire in a hosted session or invariant 2 is unenforceable.
6. **Permission behaviour.** What happens to a call that would prompt? R12.11
   (§141) already observed that headless `-p` cannot open a dialog and
   auto-denies when no `PermissionRequest` hook is registered. Establish what a
   *hosted* session does, with Golem's hooks present, for each ADR-0002 class.
7. **Proxy interposition.** Confirm the spawned session honours the proxy
   (base-URL env), so redaction/telemetry/limits apply — ADR-0007 invariant 8.
8. **Cost and lifetime.** Roughly what does an idle hosted session cost in
   tokens and processes, and what happens at the usage-limit park?

## The fallback to price, not to build

If the CLI cannot be driven this way, the alternatives are: the Claude Agent SDK
(a new dependency — weigh against CLAUDE.md's five-dep pin and the no-heavyweight
rule), or Golem running its own agent loop directly against a target via
`src/providers/` (no new dependency, but Golem then owns tool execution, which
is a much larger surface). **Price both in the note; build neither here.**

## Out of scope

Building the session host (R13.3). The device transport, pairing or UI. Any
write path. Persisting transcripts (R13.2). Changing `src/tasks/resume.ts`
beyond what a throwaway probe needs — and delete the probe before committing, or
land it as a test.
