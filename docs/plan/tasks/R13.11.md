## The defects, as reported

Two symptoms, one report:

1. **"The openrouter qwen model seems to frequently loop and reanswer the same
   question but not actually fix the problem."**
2. **"When I don't have a coder worker configured, it doesn't seem to default all
   the way to the out of the box Claude model. It launches Golem coder, but that
   fails with 401."**

Both reproduced live on the reporting machine before anything was changed.

## Defect A — the 401 was structural, and step 4 had never worked

R10.8's chain is `explicit → worker_targets[worker] → default_target → harness
default`. With `worker_targets = {}` and `default_target` unset, `coder` lands on
step 4: the synthetic target over `proxy.upstream_*`. `golem status` reported that
correctly (`coder: anthropic (target anthropic) — via the harness default
upstream; nothing routes coder`), and the dispatch still failed:

- `anthropic` resolves to `auth_scheme = "inherit"` (`defaultAuthScheme`), which
  is **correct for the proxy** — Golem is a transparent passthrough there and
  forwards the client's own headers.
- `dispatch()` does not proxy. It **originates** a request to
  `api.anthropic.com`, so there are no client headers to forward, and Golem never
  holds the Claude Code credential that serves that account.
- The guard before the request read
  `if (mapper === undefined && target.authScheme !== "inherit") throw` — it
  **exempted `inherit`**, so the POST went out with no auth header at all and
  came back `401 Unauthorized`.

So step 4 was a guaranteed failure on the commonest configuration Golem has. It
shipped green because R10.8's gate was *"provable from the audit record and
`golem status`"* — and routing and reporting were both correct. Nothing in that
gate ever completed a request.

A second, latent defect surfaced next to it: `makeAuthMapper("inherit", key)`
returns `undefined` **whatever key is passed**, so a credential the user had
genuinely stored with `golem gateway login anthropic` could never reach a
dispatch either. The scheme discarded it before the key was consulted.

## Defect B — a dispatch carried one prompt, so iteration was impossible

`DispatchRequest` carried a single `prompt` string and dispatch sent
`messages: [{role: "user", content: prompt}]` — no history, no system message.
Every remote `coder` call was therefore turn one of a fresh conversation. A caller
that disliked a draft and called again re-asked a near-identical question and
necessarily got a near-identical answer. Confirmed live against
`openrouter:qwen/qwen3.7-flash`, which replied:

> "I'd be glad to fix it, but I don't have visibility into your previous attempt
> or the failing test."

That is not a looping model; it is a stateless transport. Three contributing
defects rode along:

- `dispatchOpenAI` set **no `max_tokens`** while the Anthropic path pinned 4096,
  so the same draft had a different unstated ceiling per provider.
- It ignored `reasoning` / `reasoning_content`, so a reasoning model that left
  `content` empty surfaced as "unexpected response shape" — naming the wrong
  problem.
- `refine: true` always critiques and rewrites on the **local** tiered model even
  for a remote draft, and the reply reported the *remote* model's name. A local
  7B rewrite was attributed to `qwen3.7-flash`.

## What shipped

**Origination auth.** New `originationAuthScheme(provider)` answers a different
question from `defaultAuthScheme`: *which header would Golem have to set to
authenticate itself here?* `anthropic`/`custom` → `x-api-key`, `azure-foundry` →
`api-key`, `openrouter`/`openai` → `bearer`, and `undefined` only where no header
would do it (`ollama`, `llamacpp` keyless; `gemini`'s `?key=`; `claude-cli`
authenticating as itself). Deliberately not derived from `defaultAuthScheme`,
which returns `inherit` for four providers and answers the proxy's question.

**The decline.** `NoDrafterConfiguredError extends TargetDispatchError`, raised
only on the harness step when no credential resolves. `coder` catches it and
returns an **ordinary, non-error** result telling the caller to do the work
inline. Steps 1–3 still fail closed with the target named: those were configured
deliberately, so a missing key there is a real fault worth reporting.

R10.8's rule is untouched — there is still no silent slide to the local model.
"Decline and hand the work back" is the honest fourth outcome, and it is what the
reporting user expected ("default all the way to the out of the box Claude
model").

**Real iteration.** `DispatchRequest` gained `system` and `attempts`
(`DispatchAttempt = {draft, problem}`), rendered by `buildDispatchMessages` into
`system → user → (assistant, user)*` so the final turn is always the user's. The
`coder` tool exposes it as `previous_attempts`. With no attempts the conversation
is byte-identical to the single user turn it always was.

**Redaction across turns.** New `redactReversibleTexts` shares ONE
`PlaceholderTable` across every message, and `redactReversibleText` is now
implemented in terms of it so the two cannot drift. This was not optional:
per-message tables would give the same secret different numbers in different
turns, and one `restore` map could then only put one of them back — silent
corruption, not a leak. Redacting only `prompt` would have made `attempts` a hole
straight through the egress boundary.

**Quick wins.** `REMOTE_MAX_TOKENS = 4096` shared by both transports;
`reasoning_content`/`reasoning` read as a fallback (never a preference); the
Anthropic transport hoists system turns into the top-level `system` field, which
the Messages API requires; `RefineOutcome.revisedBy` carries the local reviser's
real model so a locally-revised remote draft is attributed honestly.

**Honesty surfaces.** The `coder` tool description no longer claims "local tiered
Ollama inference" / "Nothing leaves the machine" / "omit for the local model" —
all false since R10.8 wired the dispatcher unconditionally — and now states that
where it runs is a routing decision, that it may decline, and that each call is a
fresh conversation. A stale comment claiming the no-target path was "exactly the
previous call" is corrected, and the now-unreachable-in-practice `inference.chat`
branch says what still reaches it. `golem status` stops implying the harness step
is an assured destination. `golem target list`'s keyless exemption gains a note
that it describes the proxy path only.

## Notes for whoever touches this next

- The harness step is **not** an assured destination. Anything predicting where a
  draft goes must also ask whether Golem can authenticate there.
- `golem status` deliberately does not read the credential store to predict the
  decline — that would add a DPAPI-backed lookup to every statusline render. It
  states the dependency instead and points at `golem target list`.
- `previous_attempts` is caller-supplied. The tool counts repeat asks in-process
  and says so when the same task arrives again with no attempts, but it cannot
  make a caller pass them.
