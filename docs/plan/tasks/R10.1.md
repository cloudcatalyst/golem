## The method (read this first)

"The first pancake" — the first release of a project is expected to be the
throwaway pancake: the **ingredients** (stack, deps, data model, architecture) and
the **method** (the approach, the invariants) are good and proven, but the
**execution** is what's burnt. Nobody ships the first pancake. So: keep the
recipe, scrap the scaffolding that was written to *prove the method works*, clean
the pan, and build pancake #2 — the first real release — right.

The `/golem/first-pancake` skill (added this session) is the review playbook for
exactly this: **Pass 1** settle the keep-list (recipe + ingredients), **Pass 2**
eat the first pancake critically (scrap list: dead code, scaffolding,
proof-of-concept residue, half-integrated seams), **Pass 3** clean the pan and
reset for pancake #2 (delete / consolidate / harden). It writes nothing — it
decides, then `/golem/develop` acts.

## Priorities (user decision, this session)

- **Do not touch `src/interfaces/` blindly** — see priorities; any change is gated.
- **Do not regress the CI sharding** (#97) or the `/golem/first-pancake` skill
  (unmerged branch `feat/first-pancake-skill`, commit b2d19a6 — land it with this
