## Goal

Run the cache-safe bypass A/B against real traffic to measure what the lossy semantic
stage is actually worth.

## Why it is blocked rather than open

Decision 23 is the whole context: compression is **situational**. The only place this
measurement means anything is a **non-caching upstream** — which needs a real provider
key. R6.1 shipped the adapters (OpenAI, Ollama-LAN, Gemini translators, §73–§77) but
the cloud paths are **live-unverified** because there were no keys in-session.

The infra is already built and tested (R2.6, 2026-07-11). This task is the *run*, not
the build.

## What §103 changed (2026-07-31) — read this before running it

The Anthropic half of this question is **settled offline, and the old framing here was
wrong**. This task used to say cached traffic is "~0%". It is not ~0%: forcing the
semantic stage on a caching upstream is **net 8.7×–11.3× MORE expensive** than not
compressing, because Headroom's `read_lifecycle` diverges from the original history at
message 6 of 4,631 and forfeits a prefix billed at a 98.4% hit rate. Gross savings are
meanwhile *larger* than previously recorded (7.08% / 21.69%, scaling with session
length).

Two consequences for this task:

- **Do not spend real tokens confirming the caching side.** `scripts/measure_headroom_cache.py`
  answers it for free. If the live run is ever done on Anthropic, it is to validate the
  cost *model*, not to look for a win.
- **Pre-screen the non-caching run offline first.** That script reports gross savings and
  first-divergence for any transcript, so the expected result is known before a key is
  spent. The live run then measures what the offline model cannot: latency and quality.

## What a good result looks like

Saving **and** cost in one view: tokens saved net of cache, plus added latency, plus any
quality delta. Decision 23 exists because an earlier version of this project quoted a
saving without its cost.

## Out of scope

Re-running it on Anthropic and reporting ~0% as news. Building more A/B infra.
