## Problem

`src/cli/program.ts` is 3,617 lines — every command's option parsing, argument validation, action handler, and error handling is inline in a single commander file. At this size it's hard to verify the correctness of any single command without reading the whole file, and it makes the file a merge-conflict magnet.

## Goal

Refactor `program.ts` into:
- `src/cli/program.ts` — commander `program` setup + command registration (importing handler modules)
- `src/cli/commands/wiki.ts` — the `wiki` command group handlers
- `src/cli/commands/checkpoint.ts` — the `checkpoint` group (note: a `src/cli/checkpoint.ts` renderer already exists)
- `src/cli/commands/proxy.ts` — the `proxy` group
- `src/cli/commands/account.ts` — the `account` group
- `src/cli/commands/bench.ts` — the `bench` group
- `src/cli/commands/models.ts` — the `models` group
- Plus: config, local, ollama, guidance, prompt, hook, task, autonomy, mcp, status, slider, stats, update, statusline, note

Each handler module exports a function that takes the commander `Command` and registers its subcommands, keeping the registration in program.ts while the action logic lives in the module.

## Out of scope

- Any behavioral change to the CLI surface
- Adding new commands
- The mcp/server.ts split (separate task R8.28)
