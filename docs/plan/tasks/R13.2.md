## Why this exists

The chat surface needs scrollback that survives a reconnect, and continuing a
conversation (R13.8) needs the earlier turns as the agent's context. Both require
prompt content on disk — which this project has so far refused: `session-tree.ts` says so in its
own header, storing *content hashes, no prompt content*, on purpose.

So this task is a **deliberate, argued exception**, not an oversight being
corrected. It should read that way in the code comment too: say what changed
(ADR-0007 §6, a user decision), what is stored, and what still is not.

## What to build

1. **A frozen contract** in `src/interfaces/` for the store: append a turn, read
   a conversation, list conversations, forget one. `src/interfaces/` is frozen
   contract territory — add the file, update tests, and flag dependent
   workstreams (R13.3, R13.5, R13.8 all consume this).
2. **Redaction before write, structurally.** The store must not be *able* to
   persist unredacted text — take already-redacted material, or run redaction
   inside the write path so there is no branch that skips it. A test must place
   a runtime-generated secret in a turn and assert the stored bytes carry the
   placeholder, not the secret (per the standing fixture rule: build the secret
   at runtime; a literal secret gets redacted out from under you and a literal
   placeholder passes vacuously).
3. **Bounded, with eviction.** Count and age limits, oldest evicted first, both
   configurable with honest defaults. `web-cache.ts` is the precedent for shape.
4. **Local-only and private.** Under `.golem/` (gitignored — verify, do not
   assume the pattern covers a new subdirectory), readable by the OS user only
   where the platform allows it. State plainly in the wiki page what the file
   contains, because "everything you said to the agent" deserves a sentence.
5. **Forget, and forget everything.** `golem session forget <id>`, plus a
   documented path that removes the whole store. A retention promise nobody can
   execute is not a retention promise.
6. **Identity that agrees with what exists.** Key conversations the way
   `session-tree.ts` does (`cachePrefixFingerprint`, as fixed by R8.13) so one
   conversation has one id across both, and a worktree does not fork into two —
   `ccr-ref-scope`'s lesson, and `canonicalProjectId`'s.

## Out of scope

The session host (R13.3), the transport (R13.5), the device-facing continue and
start flows (R13.8). Branching, which ADR-0007 Revision 1 dropped — size the
bounds for continuation and scrollback, not for an indefinite archive. Indexing
transcripts into the vector KB — a searchable archive of every conversation is a
larger privacy question than this ADR asked. Syncing anything anywhere. Changing
what `session-tree.ts` stores; it keeps recording hashes and this store sits
beside it.

## Gate detail

Tests at the seam, not only the unit: write turns through the real path, restart,
read them back byte-identical. Plus the redaction assertion above, the eviction
assertion, and a check that a fresh clone of the repo contains no store. Wiki
page stating what is retained, for how long, and how to delete it — that page is
part of the gate, because retention the user cannot find is retention they did
not agree to.
