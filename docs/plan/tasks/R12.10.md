## Why this exists

R12.7 was asked to re-verify Decision 37's "a phone cannot resume a session" and
found the reason had expired. Claude Code `2.1.235` ships **channels**: "a channel
is an MCP server that pushes events into your running Claude Code session". Golem
is already an MCP server, so the seam Decision 37 called structurally impossible is
now a documented protocol Golem could speak. R12.7 declined to act on it — that was
the right call for a task whose deliverable was a sentence on a screen — and filed
this so the finding is not lost in a verification note.

Read `docs/plan/verification-notes.md` §136 first, whole. It carries the quotes, the
dates, the five objections and the URLs; this brief does not restate them.

## The two questions, smaller one first

**1. May a phone enqueue a durable task?** (the safe half, and it needs no new
protocol.) R5.1 already stores tasks and `claude --resume <id> -p …` already runs
them. The question is authority, not mechanism: a phone that can enqueue a prompt
can enqueue *any* prompt, which the next headless resume executes with the local
session's permissions — capability 2's blast radius without capability 2's
held-open hook. So it needs its own opt-in, its own ADR paragraph, and the naming
rules R12.7 fixed: label **"Add a task for later"**, sub-line **"Nothing runs until
your laptop picks it up."**, never grouped with Approve/Deny, no progress state.
The word "continue" is banned outright.

**2. Should Golem become a channel at all?** (the larger half.) Five objections
stand in §136 and any yes has to answer each: per-session launch-flag opt-in
("being in `.mcp.json` isn't enough"), the Anthropic-curated allowlist (today only
reachable via `--dangerously-load-development-channels`), no delivery
acknowledgement, an explicitly unstable contract, and Anthropic auth via claude.ai
or a Console key — which does not compose with Golem's multi-account/gateway
routing (ADR-0003, R6.1). The deepest one is not on that list: **authoring a turn
is a larger authority than answering one**, and ADR-0002's class line constrains
tool calls the model proposes, so injected free text routes around it rather than
sitting behind it. "Wait for the research preview to stabilise" is an acceptable
answer, and probably the right one.

## The adjacency worth reporting even if the answer is no

Anthropic now relays permission prompts to a channel:
`notifications/claude/channel/permission_request` with `request_id`, `tool_name`,
`description`, `input_preview`, the local dialog held open in parallel, first
answer wins. That is ADR-0006 capability 2, built first-party, with a design close
to R12.3's. Someone should say plainly whether R12.3 is still worth building, or
whether Golem's version earns its place only on the redaction and class-line
guarantees Anthropic's does not make. Do not silently keep building past that
question.

## Untested, and worth one observation

Does Remote Control (and the channel transport) work when Claude Code is pointed at
Golem via `ANTHROPIC_BASE_URL` — and does Golem's pipeline see remote-originated
turns as ordinary requests? Nobody has looked. The changelog notes "brief HTTP 403
refusals from a network edge, VPN, or proxy are now tolerated for up to 3 minutes",
which hints the path is proxy-sensitive without settling anything. One local
experiment answers it; it gates nothing here but it bears on R12.8.

## Out of scope

`tmux send-keys`, keystroke injection, PTY wrapping, screen scraping — still
rejected, still not reopened. Building a headless orchestration surface. Rewriting
ADR-0006 or Decision 59 without the user (both already carry dated pointers to
§136; the amendment itself is the user's).

## Gate

A written answer to both questions, and a user decision on question 2 recorded
where the last one was — an ADR revision or a new ADR, not a verification note.
"No channel, and here is what would have to change for that to flip" is a complete
and successful outcome; so is "enqueue only, under R12.7's three naming rules".
