## Goal

`golem local disable` and `golem coder disable` should **actually** disable the local coder, not silently write a value that a higher-precedence layer shadows. When the user runs the disable command without `--scope`, it should write to the scope that is currently supplying the effective `true` value — so the disable takes effect on the first try.

## The bug

The enable/disable commands default to `--scope project`, but the precedence ladder is
`default < user < project < local < env < override` (see `src/config/loader.ts:42` and
`:100`). When a user has `inference.local_coder_enabled: true` in `.golem/settings.local.json`
(the `local` scope), running `golem local disable` writes `false` to `settings.json`
(the `project` scope). The `local` scope wins, the value stays `true`, and the command
prints a passive note about the override instead of doing the right thing.

The same applies to `golem coder disable` (program.ts:3434, same default).

## The fix

Two-part change in `src/cli/local-config.ts`:

1. **`setLocalCoderEnabled` gains an `"effective"` scope.** When the caller passes
   `--scope` explicitly, write to that scope as before (unchained). When the caller
   omits it (the default), resolve the currently-winning layer for the key and write
   there — so a disable lands on whichever layer is actually `true`.

2. **The renderer distinguishes "shadowed"** (the write landed in a lower layer than the
  one that's winning) from "done" — so the user knows whether they need to act further.

The CLI surface (`program.ts`) changes the default `--scope` from `"project"` to
`"effective"` on the enable/disable commands. `config set` / `config unset` keep their
explicit `project` default — this is scoped to the `local`/`coder` disable commands only.

## Out of scope

- Changing the `--scope` choices for `golem config set` / `golem config unset`.
- Touching the precedence ladder or the env-var override chain.
- Anything about brevity (a separate concern the user also raised).

## Outcome

Fixed: golem local disable / golem coder disable now write to the currently-winning scope (via new 'effective' scope default) instead of silently writing to project scope where it gets shadowed by local scope. Added resolveEffectiveScope + parseLocalScope, 2 new tests, all 26 local-config tests + 43 config tests pass. Pre-existing build errors in local-model.ts/status.ts/statusline.ts are unrelated.
