## Goal

Golem now ships **13 MCP tools** and **19 skills**. Several names appear on both
surfaces (`expand` the tool and `/golem/expand`; `stats` and `/golem/stats`;
`level` and `/golem/slider`). The user asked, 2026-08-09, whether the tools would
be better served as skills with packaged scripts.

The answer, from reading the code, is **no** — and the current layering is
already correct. What is missing is that the rule is nowhere written down and
nothing enforces it, so the next contributor has no way to know which surface a
new capability belongs on.

**The rule to record: skills orchestrate, tools execute. A skill never
reimplements a tool.**

## Why tools stay tools

Four properties of MCP tools that a skill-plus-script cannot reproduce:

1. **Portability.** §R6.1 extends the pipeline past Claude Code. MCP tools work
   in any MCP client; `SKILL.md` is one client's file format. Shelling out to
   `golem search` from a skill binds a core surface to Claude Code.
2. **Hook enforcement keys on tool names.** Snooze (Decision 45) denies every
   non-`snooze` *tool call*; the local-coder PreToolUse gate distinguishes
   `coder` from a hand-written Write/Edit; the CCR PostToolUse hook emits refs
   that `expand` consumes. A Bash-invoked script is a `Bash` call — every one of
   those gates would have to parse command lines instead.
3. **The context-cost argument is largely dead.** The usual case for skills is
   that MCP schemas sit in context permanently. Claude Code now defers them
   (names listed, schemas fetched on demand). Converting would pay skill-shaped
   costs for tool-shaped work.
4. **Round-trip and typing.** Skill path = read SKILL.md → Bash spawn → node cold
   start → re-load the vector index → parse stdout prose. Tool path = one stdio
   call into a warm server already holding the index, Zod-validated in and
   structured out. `search`/`fetch`/`expand` are called reflexively many times a
   session; this is the whole latency budget. Separately, `wiki_upsert` as a tool
   carries its own allow/deny — as a script it collapses into blanket Bash
   permission, which is strictly worse.

## What the work is

- **Record the rule in the spec** (§4 alongside the MCP surface, or a short
  Decision if a Decision is what makes it binding here). One sentence plus the
  four reasons above, compressed. Include the converse: a capability that is
  rare, procedural, and needs prose about *when* belongs in a skill that calls
  the tool.
- **Audit `P0_SKILLS` against the registered tool names.** Today the skills
  delegate correctly — `slider` calls the `level` tool (`src/cli/skills.ts:19`),
  `stats` calls `stats` (:34), `expand` calls `expand` (:51), `research` climbs
  `wiki_read` → `search` → `fetch` (:89-98). Nothing keeps them that way.
- **Make it checkable.** A test that, for each installed SKILL.md, flags a
  `golem <verb>` Bash invocation where `<verb>` is also a registered MCP tool
  name. The `slider` skill is the deliberate exception (it tells the user to run
  `golem slider 0` in their *own* terminal precisely because the tool refuses
  level 0) — the check must allow a marked exception, not be defeated by one.

## The demotion question — measure before cutting

The audit will raise "should any tool become skill-only". Do not answer it by
taste. Candidates, weakest first:

- **`level`** — near-redundant with `/golem/slider`, which already routes around
  the tool for level 0.
- **`ingest`** — rare, long-running, needs prose about *what* to ingest.
- **`devices`** — diagnostic; CLI plus skill would cover it.
- **`stats`** — rare and human-facing, but the `slider` skill calls it
  programmatically to read the current level. Removing it breaks that.

"Honest observability" is a project pillar: pull per-tool call counts from
telemetry and cut on the number, or cut nothing. With schemas deferred, removing
three tools saves close to nothing — the reason to do it would be discovery
confusion, not context.

## Out of scope

27/35 settled the names). Revisiting the `wiki_read`/`wiki_upsert` split
(Decision 28 considered and accepted the tool-count pressure). Changing the
skill install mechanism or the `/golem/<cmd>` naming (Decision 14).
