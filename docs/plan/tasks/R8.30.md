## Problem

Two related issues in the Headroom sidecar's lifecycle management:

1. **No worker-respawn backoff (line 270).** `#cleanup` resets `#startPromise`, so every request that sees `!isRunning()` after a worker death calls `start()` immediately. A flaky Python environment produces repeated spawn-attempt log noise, and each attempt burns the startup timeout.

2. **Startup timeout hides the stderr tail (line 136).** `child.stderr.on("data", ...)` captures stderr but only logs it on unexpected exit. A startup timeout logs a generic message WITHOUT the stderr tail, so a "uv couldn't find Python 3.13" error is not shown to the user. The user sees only "Headroom sidecar failed to start" with no actionable diagnostic.

## Fix

1. Add an exponential backoff (e.g., 1s → 2s → 4s, capped) between respawn attempts, reset on successful start.
2. Include the captured stderr tail in the startup-timeout error message (truncate to ~2KB).

Added exponential backoff (base→2×→4×, capped 30s) to worker respawn, reset on successful start. Startup timeout now includes stderr tail. New test acks off on unexpected worker death (13 total, all pass).
