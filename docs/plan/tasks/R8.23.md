## Problem

The messages path regex is anchored only at the end, not at the start:

```ts
const MESSAGES_PATH_RE = /\/(?:v1\/)?messages(?:\?.*)?$/;
```

This matches `/v1/messages` anywhere in the path, not just at the start. `POST /foo/bar/v1/messages` would match, potentially processing non-messages requests through the compression pipeline. The spec says provider-prefixed paths should work (e.g., `/anthropic/v1/messages` for Azure Foundry), which means the pattern should be start-anchored: `/^\/(?:v1\/)?messages(?:\?.*)?$/`.

## Fix

Add `^` anchor at the start:

```ts
const MESSAGES_PATH_RE = /^\/(?:v1\/)?messages(?:\?.*)?$/;
```

This correctly matches:
- `/v1/messages` — standard Anthropic
- `/v1/messages?query=1` — with query string
- `/anthropic/v1/messages` — provider-prefixed

And correctly rejects:
- `/foo/bar/v1/messages` — should not be processed
