## The defect (first diagnosis was WRONG — corrected before the fix)

**What was originally written here:** *"Claude Code supplies a different `session_id` on
each tool call."* That is false, and it was inferred rather than measured — from two
consecutive denied Edits writing two different ids into
`.golem/state/coder-first-nudge.json` (`60075f82-…`, then `c1c58b70-…`).

**What a payload probe actually showed.** A temporary dump of every PreToolUse payload
across Bash and Write calls:

```
{"tool":"Bash", "session_id":"60075f82-…","transcript_path":"…\\60075f82-….jsonl"}
{"tool":"Write","session_id":"60075f82-…","transcript_path":"…\\60075f82-….jsonl"}
distinct ids: 1
```

`session_id` is **stable** within a session and matches the transcript filename. The key
was never the problem.

**The real defect: the state is a single global slot.** It held one
`nudgedSessionId` for the whole project, and a project routinely has more than one session
in it — a second window, a parallel agent, a headless `claude -p`. Every new session
overwrote the slot, so the previous session's one-shot was forgotten and it got nudged
again at its next code write, indefinitely. The two ids that looked like rotation were two
*different sessions* taking turns: this project's transcript directory shows several
sessions active in the same window, and the foreign id `c1c58b70-…` was still sitting in
the state file long after the session that wrote it had gone.

## Why the unit tests missed it

`decideCoderFirstNudge` is pure and correct, and the tests pass it the same id twice.
Nothing exercised **two sessions interleaving**, which is the only case that fails.

## The fix

- The state remembers a **set** of nudged sessions (`nudgedSessionIds`), capped at
  {@link MAX_REMEMBERED_SESSIONS} = 50, newest kept.
- The pre-R9.17 `{nudgedSessionId}` shape is still read, so upgrading does not re-nudge a
  session that was already nudged.
- Regression tests: two sessions interleaving are nudged exactly once each; a second
  session does not evict the first; the cap evicts oldest-first; the legacy shape migrates.
- Guidance re-enabled (`golem guidance enable local-coder`) and verified live: the first
  non-trivial write in this session nudged, the next two went straight through.

## Watch for

- Read-modify-write is not atomic, so two sessions nudging in the same instant can lose one
  append — worth at most one extra nudge, deliberately preferred over a lock file.

## Outcome

shipped: one-shot state now remembers a SET of sessions; the single slot was being overwritten by concurrent sessions. Verified live.
