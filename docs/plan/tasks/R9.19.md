## The gap

R9.12 ships trust detection with two of its three signals: the endpoint must be published,
and `NODE_EXTRA_CA_CERTS` in the hook's own environment must name our CA, verified by a TLS
probe from the hook. §125 then measured that a hook's environment reflects the **settings
file**, not necessarily what Claude Code's TLS stack honours — they happened to agree in a
terminal session, and the doc says they will **not** agree in cloud and Desktop-app-managed
sessions, where a repository's settings `env` is ignored for TLS (§121-A).

In such a session the hook rewrites, and the fetch fails with an opaque TLS error. Nothing
is lost — §122 established that `additionalContext` still delivers the page — but the
transcript shows a failure where the deny floor would have shown Golem's own
`NOT AN ERROR —` framing. That is strictly worse than R9.7 in appearance, which is the one
thing R9.12 promised not to be.

## What to build

The third signal, described in R9.12 and not implemented: **positive evidence that a real
WebFetch reached the endpoint.**

- The endpoint records a hit on `/w` (it already serves that path) somewhere the hook can
  read — a small file it owns, not the shared serve state.
- The hook keeps a verdict: unknown → rewrite **once**, optimistically, recording the
  attempt; on the next serve, if no hit was recorded after that attempt, the verdict
  becomes "not trusted" and every later serve in that window takes the floor.
- A "not trusted" verdict must expire (a short TTL, ~10 minutes), because the condition it
  records is fixed by a restart and the latch must not outlive the problem. Note the
  session id cannot key this: R9.17 records that it rotates per tool call.

## Watch for

- The first fetch of a trusted session must stay green — a latch that requires evidence
  before the first rewrite can never obtain it. Optimistic-once, then decide.
- A "trusted" verdict should be tied to the endpoint's `startedAt`, so a proxy restart with
  a regenerated CA re-probes rather than trusting a stale yes.
- This cannot be reproduced from a terminal session. Either find a way to simulate the
  mismatch (force the hook's env while serving a cert Claude Code will reject) or verify in
  a real Desktop-app-managed session before claiming the gate.
