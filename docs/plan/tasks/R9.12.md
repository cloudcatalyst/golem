## Goal

Make R9.7's red dot **optional**. A user who turns this on gets a normal green
WebFetch; a user who does not gets exactly what R9.7 shipped. Default stays OFF.

R9.7 declined the loopback design outright. §121 then withdrew its main reason —
the cert is far cheaper than believed — so what remains is a genuine trade rather
than a blocker, and a trade belongs behind a flag rather than in a decision.

## What §121 already established (do not re-derive)

- `updatedInput` + `permissionDecision: "allow"` **is honoured** and renders green.
  It replaces the **entire** input object, so `prompt` must be carried through.
- WebFetch upgrades `http`→`https` and validates the cert. `file://` and `data:`
  are rejected as `Invalid URL`. HTTPS on `127.0.0.1` is the only reachable shape.
- A self-signed **`CA:FALSE` leaf** in `NODE_EXTRA_CA_CERTS` validates (measured,
  with a failing control). It **appends to** the default store — public TLS still
  works — and cannot sign for any other host, so there is no MITM blast radius.
  **Ship a leaf, never a CA.**
- Claude Code documents `NODE_EXTRA_CA_CERTS`, settable via settings `env`, read
  **once at startup**, and verifiable in `claude --debug` (`CA certs: Appended
  extra certificates from NODE_EXTRA_CA_CERTS (<path>)`) and in `/status`.

## Scope

- **Cert lifecycle.** Generate a leaf (SAN `DNS:localhost,IP:127.0.0.1`,
  `basicConstraints=critical,CA:FALSE`, `extendedKeyUsage=serverAuth`) into
  `.golem/`, key permissioned as tightly as the platform allows. No `openssl`
  dependency — cross-platform means a pure-JS generator, which is a **new runtime
  dependency** in a project that currently has five, exact-pinned: justify it or
  find another way. Handle expiry and regeneration.
- **The endpoint.** HTTPS on loopback, serving `?u=<url>` with a per-run
  unguessable nonce from `.golem/state/` (it is reachable by any process on the
  machine). Hit → serve from cache; miss → fetch + redact + cache + ingest + serve.
  Redaction before storage is the hard rule and does not bend here.
- **The hook** becomes a URL rewrite plus `allow` — and nothing else.
- **The fallback latch** (the part that decides the gate, see below).
- **`golem init` wiring** behind explicit opt-in, plus a `golem status` row saying
  whether the cert is trusted *in the session that is actually running*.

## The two hazards that must be designed for, not discovered

1. **A failed rewrite is worse than a red dot.** Today's failure mode is "works,
   looks red". Rewriting in a session where the cert is not trusted produces a
   **genuinely failed fetch**. The hook must therefore rewrite only on positive
   evidence that a real WebFetch previously reached the endpoint (a latch in
   `.golem/state/`), and fall back to deny-and-serve otherwise. First fetch of a
   session, or any doubt, takes the safe path.
2. **The wiring is silently inert in two session types.** Cloud sessions ignore
   `NODE_EXTRA_CA_CERTS` from a settings `env` block, and Desktop app-managed
   sessions ignore a *repository's* settings files — which is exactly where
   `golem init` writes. A project-scope install does nothing there. Writing to
   `~/.claude/settings.json` instead is a broader footprint and needs consent.

## Out of scope

- Changing the default. R9.7's deny-and-serve stays the shipped behaviour.
- Installing anything into the **OS** trust store. That is a machine-level act
  (`owner: user` territory), and the leaf + `NODE_EXTRA_CA_CERTS` route avoids it.
- Any form of CA. If a design needs signing power, it is the wrong design.
- The proxy-side summarizer short-circuit (§120 part (b)) — it puts the raw page
  in context whole, which is a worse regression than the red dot it fixes.

## Watch for

- **`NODE_EXTRA_CA_CERTS` is a single path and someone else may own it.** A user
  behind a TLS-inspection proxy already has it set. Do not clobber it; concatenating
  their bundle with ours creates a copy that goes stale when theirs rotates. Set it
  only when unset, otherwise print instructions and stay off.
- **The token and fidelity cost does not go away and must be stated at the toggle.**
  WebFetch's summarizer runs per fetch (measured: 551 in / 9 out for a 1.2 KB page,
  uncached), and bounding it means the model receives a prompt-specific summary of a
  *truncated* page instead of today's prompt-independent raw text — Decision 42's
  thesis in reverse. Anyone turning this on should be told they are buying a colour
  with tokens and fidelity.
- A restart is required for the env to take effect (§112), so the enable path must
  say so rather than appearing to work immediately.
