## Why this exists

The user asked for something "most similar to conversing via a harness's chat
window". This is that screen. ADR-0007 §2 is deliberately explicit about the
line: streamed replies, visible tool calls, scrollback, interruption and
in-place permission answers are all promised; **mirroring the developer's TUI is
not**, and a UI that looks like it is doing that is the specific dishonesty this
task must avoid.

## What to build

1. **The conversation, streamed.** Assistant text as it arrives, tool calls and
   their results as distinct blocks (collapsed by default — a phone screen is
   small and a `Read` result is not), and a clear turn boundary.
2. **A send box, only where authorship is permitted.** Per ADR-0007 §3c: if the
   target session's tool calls are not subject to a decision Golem can make, the
   send box is **absent and the reason is stated**. Not greyed out with a
   tooltip — absent, with a sentence.
3. **Which session am I talking to.** A header that names the session, its
   project, and whether it is a *hosted* session (Golem's own) or a *joined*
   live one (R13.7). Two different things with two different capabilities, and
   the user must never have to guess which they are in.
4. **Permission questions answered in place**, honouring the class line: a
   `destructive`/`outward` question does not appear here as answerable, because
   in a hosted session it was already refused (invariant 2) — show the refusal
   and why, not a button that cannot exist.
5. **Interrupt.** A stop control that actually stops the turn (R13.1 establishes
   whether that is cancellation or process-kill; say which in the UI copy if it
   is coarse).
6. **Connection state, loudly.** "Not connected" replaces content; it does not
   sit in a corner while stale turns look live. Same rule as the observe view.
7. **Installable and phone-shaped**, inheriting R12.5's shell rather than
   forking it.

## Out of scope

A native app or an app store (unchanged from R12.5). Push notification (R12.6).
Editing files from the phone (ADR-0007 §10). Starting or branching sessions —
that is R13.8, and it lands as a second screen on top of this one. Any
control affordance for a session the device is not paired to.

## Gate detail

The manual demonstration in the gate line, on a real phone, recorded with
screenshots in the debrief. Plus: an automated check that the send box is absent
for an unpaired device and for an unenforceable target; a check that scrollback
rehydrates from R13.2's store after a reconnect; and the `vscode-extension`
render tests extended if the shared render path is touched. Wiki page describing
the two session kinds as a user sees them — hosted versus joined — because that
distinction is the one users will get wrong.
