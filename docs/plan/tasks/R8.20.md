## Goal

Make "I am not spending upstream tokens" a **state Golem holds and shows**, rather than
an outcome the user infers from having configured two lanes carefully.

> "I really want to get to a point where I can operate effectively without needing
> upstream tokens, even if the results take longer and might need to be pre-planned"
> — user, 2026-08-01

Decision 56 makes this a product goal (goal 7) and R8.19 makes it *reachable* — both
lanes pointed at local endpoints. This task makes it **legible and enforceable**, which
is a different thing: a mode you have to audit is not a mode.

## Why it is its own task

R8.19 is about *choice* — any model, either lane, per request. This is about the one
configuration of those choices that has a hard guarantee attached, and guarantees need a
mechanism:

- **Refusal, not routing.** With local-only on, an upstream request is an error the user
  sees, not a silent forward. That is the only version of the claim that is worth making
  (ADR-0004's rule: the guarantee comes from the mechanism, not the intent).
- **Visible everywhere the money question is asked** — `golem status`, the statusline,
  `golem devices`, the MCP `stats`/`level` surfaces. The precedent is level 0's
  redaction-off warning (Decision 30): a mode with consequences announces itself on every
  surface that could mislead.
- **Honest about the trade.** Local-only is slower and it rewards pre-planned work.
  Turning it on should say so once, plainly, rather than letting the user discover it.

## What to do

- A single explicit state (`golem local-only on|off|status`, backed by one setting) that
  pins both lanes to declared local endpoints and **fails closed** — if no local endpoint
  can serve a role, the answer is a refusal naming the role, not a quiet upstream call.
- Proxy behaviour: an upstream forward while the mode is on returns a clear local error.
  Level 0's full bypass and this mode are mutually exclusive by construction — a bypass
  that reaches the network is the opposite of this guarantee.
- Status surfaces carry it, and `golem status` gains a line that answers the money
  question directly.
- One-time narration on enabling: what is now local, what will be slower, and what
  "pre-planned" means in practice (batch the work, expect fewer round trips).

## Out of scope

- **Choosing the models.** That is R8.18's ladder and R8.19's routing.
- **Making local fast.** Speed comes from the model and the offload flags, not from here.
- **Queueing or scheduling long local runs.** A real question (a pre-planned batch that
  runs for an hour), and a separate one — capture it in `BACKLOG.md` if it grows teeth.
- **Any automatic fallback to upstream when local fails.** That is exactly the behaviour
  this mode exists to forbid; a failure is reported.

## Gate detail

Live, on the machine, with the proxy running and a llama.cpp server serving both lanes:
one prompt that would normally reach Anthropic must be refused with a message naming the
mode, and `golem status` must state the mode without being asked. Record the measured
latency difference for one representative task — a slower number is a result, not a
failure (§89/§100).
