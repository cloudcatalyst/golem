## Problem

`OllamaNativeClient` constructor defaults to `requestTimeoutMs = 5_000`:

```ts
this.#timeoutMs = options.requestTimeoutMs ?? 5_000;
```

This timeout is used as `headersTimeout` for the `/api/pull` POST request (line 140). On a busy Ollama instance (cold start, queue, or LAN machine), `/api/pull` can take longer than 5s to start streaming the NDJSON response. The `bodyTimeout: 0` correctly allows streaming, but the 5s headers timeout causes the pull to fail with `OllamaUnreachableError` even though Ollama is running.

## Fix

Use a more generous timeout for `/api/pull` specifically, independent of the general `requestTimeoutMs`. The pull operation is inherently long-running (model download, quantization). Options:

**Option A:** Override `headersTimeout` to 30s for `/api/pull` while keeping the general timeout for `/api/tags` (listModels) and `hasModel`.

**Option B:** Document that callers must pass a larger `requestTimeoutMs` when using `pull()`, and add a constructor overload for separate connect/read timeouts.

## Out of scope

- The general request timeout for chat completions (that's a separate concern)
- Any changes to the Ollama client's body timeout (already 0 for pull, correct)

## Verification
