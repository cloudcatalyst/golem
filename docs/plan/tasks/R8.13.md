## Goal

`golem stats --cache`'s prefix-verdict half is a bad metric. Replace the identity
heuristic so the prediction stops contradicting the ground truth printed beside it.

## The finding (§99)

With the read path fixed, the real distribution is **142 `bust` / 3 `first` /
0 `append`** — ~98% of classified requests called cache busts — while the **billed**
numbers over the same period report a **98.4% hit rate** with cache-write at 1.5% of
input. The billed number is ground truth, so the verdict is wrong ~98% of the time.

**Most likely cause: the conversation key.** `cachePrefixFingerprint` groups requests
by a hash of `messages[0]`, and a real client multiplexes many short conversations
through one proxy — subagent runs, title/topic generation, WebFetch summarisation,
quota probes — a large share of which open with an identical or near-identical first
message. They collide onto one key and read as each other's busts.

**The documented caveat was wrong about severity.** `cache-prefix.ts` says a collision
"costs at most one misattributed verdict, and never a wrong bill". The first clause is
false — collisions are the dominant case, not the marginal one. The second clause
holds, which is the only reason this is a bad metric rather than an incident.

## Three candidates (§99), in the order worth trying

- **A — prefix-chain identity.** Keep a bounded set of seen `messages[0..k]` hashes and
  classify a request as `append` when *any* prefix of it was seen before, regardless of
  which conversation it belongs to. Removes the conversation key entirely. Most
  promising.
- **B — require growth.** Only report `bust` when the message count is at least the
  previous request's; a shorter or equal-length divergent request is more likely a
  different conversation than an edit. Cheap, partial.
- **C — a client-supplied id.** Re-check whether Claude Code sends anything stable (a
  `metadata.user_id`, a header) that the proxy could key on instead of guessing.

## What this must preserve

- **Billed and predicted stay separate and never blend into a "cache health score."**
  That was R8.1's central design call and it is the only reason the contradiction was
  visible at all — a blended number would have averaged a correct measurement with a
  98%-wrong prediction and looked plausible.
- Hash-only fingerprints, bounded observer, no prompt content.
- **The §99 standing rule:** a new `TelemetryEvent` field needs a `parseEvent` line in
  `jsonl-store.ts` **and** a round-trip test. `parseEvent` is an allow-list, so an
  aggregator unit test cannot catch a field that never survives the read — see
  `tests/integration/cache-verdict-roundtrip.test.ts` for the pattern.

## Definition of done

Either a verdict distribution that is explicable against the billed rate, or — if no
heuristic survives contact — **remove the verdict section** and say why. A metric that
is wrong 98% of the time should not ship as diagnostics indefinitely.
