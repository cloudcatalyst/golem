## The defect

R9.8's gate was *"an unreachable key is REPORTED, never silently dropped"*, and
it shipped `#reportIgnoredConfig` to do exactly that. The report only happens
when the Headroom adapter actually compresses something.

On a prompt-caching upstream the lossy semantic stage is gated off before the
adapter is ever reached (`upstreamAssumesCaching("openrouter") === true`,
Decision 31). So the adapter never runs, never validates, and never warns.

Measured live on 2026-08-14. A duoop project carried, for weeks:

```json
"headroom_config": { "plugins": [{ "name": "openrouter-context-compression" }] }
```

`plugins` is not a `CompressConfig` field — R9.8 documented this exact key as the
motivating example of the silent-drop failure. Occurrences of the warning in that
project's proxy log: **zero**. The user reasonably believed OpenRouter-side
context compression was active. Nothing was.

So R9.8 closed the case where Headroom runs and closed it well; the case where
Headroom is switched off — which is *every OpenRouter and every Anthropic
target*, i.e. most real usage — still fails silently.

## What to build

Validate the config where it is READ, not where it happens to be used.

- Check `compression.headroom_config` keys against the installed Headroom's
  `supported_config` at startup (or at `golem status` time), independently of
  whether the stage will run this session.
- `golem status` is the natural surface: it already renders the slider, the dials
  and the "level 3 is inert here" warning, and a user checking why compression
  did nothing is already looking at it. A key that can never apply belongs
  beside the note that the stage is off.
- Say both facts together, because either alone is misleading: *this key is not a
  Headroom field* AND *the stage it would configure is off on this upstream
  anyway*.

## Watch for

- The `supported_config` probe requires the worker; do not start a Python
  process just to render `golem status`. Cache the capability, or gate the check
  on a sidecar that is already running, and degrade to a name-only check
  otherwise.
- Do not imply the key would have worked if the stage were on — `plugins` would
  still be filtered. Two independent reasons, both worth saying.
- Keep it a diagnostic. Nothing here should change what is sent upstream.

## Out of scope

- Making `plugins` actually reach Headroom, or supporting OpenRouter-side
  compression as a feature. That is a design question about whether Golem should
  delegate compression to a gateway at all — argue it in the spec, not here.
- Revisiting Decision 31's fail-safe classification of OpenRouter as caching.
