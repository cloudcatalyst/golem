## Goal

`golem config set <key> <value>` parses booleans (`true/false/1/0/yes/no/on/off`)
and arrays ("JSON or comma-separated"), but not **objects**. So an
object-valued leaf cannot be written from the CLI at all:

```
$ golem config set compression.headroom_config '{"compress_user_messages":false}' --scope local
golem: invalid value for "compression.headroom_config": Expected object, received string
```

The string is never parsed as JSON, so it reaches the Zod leaf as a string and
fails validation. The only way to set it today is to hand-edit
`.golem/settings.local.json` — which defeats the point of having `config set`,
and is exactly the kind of hand-edit `golem config` exists to make unnecessary.

Found 2026-08-09 while trying to blunt the CCR-marker problem in R9.8; that task
is the motivating consumer, but this is an independent CLI defect.

## What to check

- The array path already accepts JSON. Reuse that seam rather than adding a
  second parser — the fix is likely "try JSON.parse first when the target leaf
  is an object/record, then fall back to the existing scalar handling".
- Enumerate the object-valued leaves in `SETTINGS_LEAVES` and confirm each is
  settable afterwards; `compression.headroom_config` (`z.record(z.unknown())`)
  is the one known case, but the fix should not be special-cased to it.
- Keep the error message honest when JSON parsing fails: "invalid JSON for
  <key>: <parser message>" beats "Expected object, received string", which
  describes the symptom and hides the cause.
- Windows quoting: PowerShell and cmd quote JSON differently from POSIX shells.
  Whatever the fix, document one invocation that works on each, and prefer a
  form that does not require embedded-quote gymnastics (consider accepting
  `--value-file <path>` or stdin as the escape hatch rather than telling users
  to fight their shell).

## Out of scope

Redesigning the settings schema. A general-purpose config DSL. Deep-merge
semantics for object leaves — set replaces the whole object, consistent with how
the existing scalar and array paths behave; if merge is wanted, argue for it
separately.
