## The ask

The user, reading the status bar after the R11.3/R11.5 deploy:

> the separator between the default worker's model and the other workers should
> be a `+`. Also, the workers should have the same format "[gateway] ([model])"

Before:

```
⬢ Golem → ◆ anthropic (claude-opus-5) · ✎ qwen/qwen3.7-flash · 🗜 lossless · ✂ full
```

After:

```
⬢ Golem → ◆ anthropic (claude-opus-5) + ✎ openrouter (qwen/qwen3.7-flash) · 🗜 lossless · ✂ full
```

## Why each half is right

**One format.** The chat model read `<gateway> (<model>)` while a worker read a
bare id (or `<gateway> <model>` when a gateway happened to be known). Two things
of the same kind, spelled two ways on one line, which also made the parentheses
look like they carried meaning.

**`+` between them.** These segments are the same kind of thing — models this
conversation uses — where `·` separates different kinds (models · dials ·
brevity). One glyph for both made the model list and the dial list read as a
single flat run of fields. It also restores the reading R9.4's `local + upstream`
had before either end could be any target: what changed then was *which* models
get named, not that they are added together.

## What it needed underneath

A worker had no gateway to print. `collectGolemState` was passing the raw
`accountId` as the gateway — so a target with no account rendered gateway-less
while the chat side happily said "ollama" for the identical provider — and
`golem status --json` had no `gateway` field on a worker row at all, which is
where the VS Code extension gets its data. Both now use `providerUpstreamLabel`,
the same function the chat segment uses, so the two cannot disagree about what to
call OpenRouter.

`MODEL_JOIN` is a named constant on both sides for the same reason `ROLE_MARKS`
is: the two renderers share no module, and a bare `" + "` in two languages is the
drift R10.24 existed to end.

## Out of scope

- The worker with no resolvable gateway still renders as a bare model id. An
  older CLI sends no gateway, and inventing one would be worse than omitting it.
- **The brevity-off divergence found here and deliberately NOT fixed:** the CLI
  prints `✂ off`, the status bar omits the segment, and
  `render.test.js`'s "statusBarText shows brevity only while it is on" pins the
  extension's behaviour on purpose (Decision 52's wording). Every parity fixture
  used `brevity: "full"`, so R10.24 never compared the off case. Which surface is
  right is the user's call, not a silent flip — raised, left alone.

## Gate

Standing verification bar. Parity: two new cases pin the format and the join on
both surfaces plus the gateway-less fallback; the extension suite gains its own
two; three CLI expectations and four extension expectations move from `·` to `+`.

## Outcome

shipped — `⬢ Golem → ◆ anthropic (claude-opus-5) + ✎ openrouter (qwen/qwen3.7-flash) · 🗜 lossless · ✂ full`,
identical on both surfaces, verified live on the user's own configuration.
