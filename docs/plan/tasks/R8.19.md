## Problem

`sniffRequestModel` uses a regex to extract the `model` field from the head of a JSON request body:

```ts
const MODEL_FIELD_RE = /"model"\s*:\s*"([^"\\]+)"/;
```

This matches ANY `"model": "value"` in the first 64KB, not just the top-level one. A tool description or function definition containing `"model": "gpt-4"` in the same window would return the wrong model id. The regex is documented as a deliberate trade-off (avoids parsing the full JSON body on the hot path), but it's a correctness gap.

## Fix

Two options:

**Option A (minimal):** Anchor the regex to the start of a JSON object: `/\{"model"\s*:\s*"([^"\\]+)"/`. This matches the first field only if `model` is the first key. But `model` may not be the first key in the JSON object (e.g. `{"stream": true, "model": "claude-3"}` would not match).

**Option B (correct):** Use a streaming JSON parser or a lightweight state machine that tracks nesting depth. Only accept the `model` key at depth 1 (top-level object).

## Out of scope

- Full JSON parsing of the request body (the whole point of the regex was to avoid this)
- Status display formatting

## Verification

- `npm run typecheck`, `npm run lint`, `npm run test`
- Test that a body with a nested `"model"` key in a tool description returns the correct top-level model id
