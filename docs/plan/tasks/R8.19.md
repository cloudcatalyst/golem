## Goal

One addressable set of model endpoints, usable in **either lane**, nameable **per
request**:

- **the thinker** — the brain a conversation or an agent plans with (today:
  `proxy.upstream_*` / `proxy.accounts`);
- **the coder harness** — the executor that drafts and edits (today: the `coder` MCP
  tool / `inference.providers`).

Both lanes must accept any backend: a local llama.cpp, a LAN Ollama, an Anthropic
account, OpenRouter, Moonshot. The lane is the *role*; the model is a *choice*.

## The shape, in the user's own examples (2026-08-01)

> "Use Fable 5 to plan the tasks for feature X to be developed by one or more agents
> using the default local coder"
> "I have coding challenge y which I'd like to use Opus 4.8 via OpenRouter to solve."
> "Can you task my lan's Ollama server to plan feature z using Gemma 4"
> "Please plan, task and deliver project xyz using Kimi K3 on my Moonshot AI
> subscription, using as many agents as you need"

Read those together and the requirement is precise: **thinker and coder are chosen
independently, by name, at the moment of asking.** Not a session-wide mode, not a
config edit — an instruction.

## This unblocks 21e's legitimate half, and only that half

`21e` has sat `blocked: needs a product/ToS decision, not an implementation` since
2026-07-30. ADR-0003 drew the line: *"legitimate account/provider switching only —
the automated quota-evasion half is OUT."*

**The user's request falls on the legitimate side, and the reason is structural:
every route above is named by the user.** "Opus 4.8 via OpenRouter" is the same act as
`golem account use openrouter`, scoped to one request instead of a session. It selects
among the user's own, separately-legitimate subscriptions by explicit instruction. It
is not rotation, not arbitrage, and not a response to a limit.

So 21e splits, and the split is the deliverable:

| | what | status |
|---|---|---|
| **21e-a** | explicit, user-named per-request routing | **unblocked by this task** |
| **21e-b** | automatic route-on-exhaustion / rotate-on-429 | **still out**, still needs its own decision |

21e-b must remain *absent*, not implemented-and-disabled. ADR-0004's precedent: the
guarantee comes from the absence of a mechanism, not from a flag that could be flipped.
A `429` from a named upstream is reported to the user, who may then name another — that
is a human deciding, which is the whole distinction.

## What ADR-0005 has to settle before any code

1. **Does one registry replace two, or do they federate?** `proxy.accounts` holds
   credentialed upstreams (ADR-0003, OS credential store); `inference.providers` holds
   local endpoints (R8.15, no secrets). Merging them puts a credential reach into a
   table that currently cannot hold one. Federating keeps the security boundary and
   costs a resolution layer. **Recommend federate**, for the same reason `golem ext`
   and `golem plugin` stayed separate.
2. **What may a named route reach?** A per-request name that can select any credential
   in the store is a bigger reach than R6.2 granted. Does naming an account in a prompt
   authorise spending it? The prompt is attacker-influenceable content in a way a config
   file is not — **this is the load-bearing question**, and prompt-injection-driven
   spend on the user's most expensive subscription is the threat to model.
3. **Where does the name get parsed?** If the model interprets "use Opus 4.8 via
   OpenRouter" then a hostile document can too. If Golem parses a structured surface
   (an MCP tool argument, a `/golem/route` prompt), the reach is auditable. **Recommend
   structured**, with natural language mapped onto it visibly, never silently.
4. **Byte-fidelity.** CLAUDE.md's proxy rule holds per-request as it does per-session:
   the Anthropic path stays byte-faithful, translated providers stay a separate code
   path, and a per-request switch must not smuggle a translated response onto the
   native path.
5. **Prompt-cache consequences.** Switching thinker mid-conversation discards the cached
   prefix on the old upstream. §104's arithmetic — a bust bills 3.3× an append turn —
   means the cost of a switch is real and must be *reported*, not discovered.
6. **What "no upstream at all" means.** The user's stated goal is operating without
   upstream tokens. That is a resolvable end state of this design (both lanes named at
   local endpoints), not a separate feature — but it needs an explicit, visible mode so
   "am I spending money right now?" is always answerable.

## What already exists and gets reused

`proxy.accounts` + `resolveActiveUpstream` (fail-closed, no silent cross-account
fallback), the OS credential chain (Decisions 46/47), the R6.1 provider translators
(`openai`, `openrouter`, `ollama`, `gemini` — `isTranslatingProvider`), and R8.15's
`inference.providers` + role resolution. This task is mostly **composition and consent**,
not new transport.

## Out of scope

- **21e-b**, in any form.
- **Multi-agent orchestration.** "using as many agents as you need" is a Claude Code
  capability; Golem's job is to make each agent's lanes addressable, not to schedule
  agents.
- **New provider translators.** Moonshot/Kimi is OpenAI-compatible and needs no new
  adapter (r6-multi-provider memo, 2026-07-24).
- **Implementing before ADR-0005.** The R8.11 precedent, and here the threat is spending
  the user's money rather than leaking a secret.
