## The defect

All five raised by the user in one message, on their own install:

> using the cli, claude shows the status items in the wrong order and in vs code
> the compression appears before the arrow to the model and the model label
> states the provider and not the gateway outside of the parentheses. I've also
> noticed there continue to be inconsistencies around showing when it's on and
> offline. I'm also not seeing the upstream model picker correctly when I use the
> vs code picker and I'm confused about what the slider means vs compression.

**1. The two surfaces had drifted, and each half-documented the other's shape.**

```
CLI:       ⬢ Golem · → ✎ qwen2.5-coder:7b · ◆ anthropic (claude-opus-5) · 🗜 lossless · ✂ full
status bar: ⬢ Golem · Lossless → ✎ qwen2.5-coder:7b · ◆ anthropic (claude-opus-5)
```

Three disagreements in one line: the dial sits between brand and arrow on one
and after the destination on the other; the arrow lands on the DRAFTING model
because `destinationLabel` printed diverging workers before the chat model; and
`statusline.ts`'s own module header and `renderStatusLine`'s doc comment gave two
different canonical shapes, neither of which was what the code emitted.

**2. The status bar labelled the destination with the model's vendor.**
`formatVendorModelStatus` parsed the vendor out of the model id, so an OpenRouter
target rendered `deepseek (deepseek-v4-flash)` — naming a vendor Golem never
talks to, and hiding which of the user's gateways was carrying the traffic. It
also preferred the CONFIGURED model over the last-served one, the opposite of the
CLI's precedence.

**3. "On" and "off" were told in two vocabularies, and one state was missing.**
The CLI had four states (running / unwired / bypass / off); the status bar had
two, no notion of `proxy.in_path` at all, and called a STOPPED proxy
"Passthrough" — the word level 0 uses for a deliberately-bypassing *running*
pipeline. Both surfaces also printed the configured dials in states where no
stage runs, which is the misreport R8.32 and Decision 56 each exist to prevent.
The CLI additionally drew the bypass shim as a filled green hexagon, identical to
a fully-running pipeline — found by the new parity test, not by hand.

**4. The picker could not pick a model.** It listed GATEWAYS, and a gateway that
fronts several models collapses to one row whose `model` was always `models[0]`.
With `openrouter` fronting both a qwen and a deepseek entry, deepseek was
unreachable from the picker entirely. Underneath, `useGateway` rejected target
ids outright — so `inference.default_target`, a leaf whose name says TARGET,
could only ever be set to a gateway. Every other piece of per-target routing
(R9.1 registry, R9.2 resolution, R10.8 fall-through) was already built; the verb
was missing.

## What was built

- **One canonical shape**, brand → destination → dials, chat model first:
  `⬢ Golem → ◆ openrouter (deepseek/deepseek-v4-flash) · ✎ qwen2.5-coder:7b · 🗜 lossless · ✂ full`
  and `tests/unit/cli/statusline-parity.test.ts`, which renders equivalent state
  through BOTH implementations and demands one identical string.
- **Gateway outside the parentheses**, model id verbatim inside (Decision 49),
  last-served preferred over configured — the CLI's precedence, now shared.
- **Four state words** — running (no word), `bypass`, `unwired`, `off` — on both
  surfaces, and dials shown only while they are in force.
- **`golem target use <id>`**, plus `useGateway` accepting a target id and
  preflighting the credential of the gateway BEHIND it. `collectGateways` gained
  `active_target` and per-row `models`, and marks the gateway backing a selected
  target as active.
- **The picker offers targets**, labelled by model with the gateway as
  description, falling back to `golem target list` and then to the old gateway
  picker on an older CLI.

## Deliberately NOT done

- **Retiring the slider** (the fifth point). It is a real design question, not a
  defect: `slider.level` is a PRESET over the compression and brevity dials
  (Decision 52), so two controls describe one thing and the status line has to
  show both. Worse, on a caching upstream — the default — Decision 31 gates the
  semantic stage off, so levels 2 and 3 are INERT: this user's machine reads
  `slider 3 (aggressive)` while the effective compression is `1 (lossless)`,
  which is exactly the confusion reported. 379 references across 63 files, a
  config leaf needing migration, the `level` MCP tool, and level 0's redaction
  bypass (a CLAUDE.md hard rule) all hang off it. It needs its own task and the
  user's decision on how far to go.
