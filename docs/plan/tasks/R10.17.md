## The defect

Found 2026-08-14 while asking why a 500 KB screenshot was never offloaded.

`findTextSlot` probes only TOP-LEVEL keys of `tool_response`:

```ts
const TEXT_KEYS = ["output", "stdout", "content", "text", "result"] as const;
```

`Read`'s payload nests its text one level down:

```
toolUseResult = { type: "text", file: { filePath, content, numLines, startLine, totalLines } }
```

The text is at **`file.content`**. No top-level key matches, so `findTextSlot`
returns `null` and the handler takes its "shape we don't understand" branch:

```ts
if (slot === null || slot.text.length <= maxInlineChars) {
  return 0; // below threshold or shape we don't understand — silent pass-through
}
```

So the oversized-output swap has **never fired for `Read`**, for any file — text
or image — despite `Read` sitting in the PostToolUse matcher in every project
`golem init` writes.

Measured across one project's transcripts:

| count | top-level keys | matches? |
|---|---|---|
| 270 | `interrupted,isImage,noOutputExpected,stderr,stdout` | `stdout` |
| 80 | `content,filePath,originalFile,structuredPatch,type,userModified` | `content` |
| 66 | `filePath,newString,oldString,originalFile,structuredPatch,…` | **no** |
| **62** | **`file,type`** ← `Read` | **no** |

62 `Read` results in one project, none of them ever eligible for offload.

## Why it went unnoticed

This is R9.12's bug again, verbatim in shape: `result` was missing from the same
list, so the swap "never once fired" for WebFetch either, and that was also
silent. The handler's fail-safe — unknown shape passes through — is correct
policy that doubles as perfect camouflage: a tool that never swaps is
indistinguishable from a tool whose output was never big enough.

Two lists of the same thing drifting apart, where nothing checks.

## What to build

- Probe nested payloads, not only the top level. `file.content` is the concrete
  case; prefer a small, explicit path list (`file.content`) over a recursive
  search, so the set of understood shapes stays readable and testable.
- Add a regression test built from the REAL recorded shapes above, not from an
  invented payload — the invented payload is what passed for two releases.
- Consider a diagnostic that makes "never fired" visible: a counter, or a debug
  line when a `tool_response` exceeds the threshold but matches no slot. The
  silence is the actual defect; the missing key is just this instance of it.

## Watch for

- **Do not offload images.** An image block has no head/tail excerpt worth
  taking, and R10.14 already replaces or hoists them at translation time. This
  task is about the TEXT that `Read` returns.
- Keep the fail-safe: an unrecognised shape must still pass through untouched
  rather than being mangled by a guess.
- The threshold check must stay after slot resolution, so a small `Read` is
  still left alone.

## Out of scope

- Changing the inline threshold or the CCR store format.
- R10.18's empty-completion guard, found in the same session.
