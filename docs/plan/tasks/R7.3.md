## Goal

Run the `bun build --compile` binaries once per OS before anyone relies on the binary
install channel.

## Why it is still open

`scripts/build-binary.mjs` and the tag-triggered Release workflow shipped with R7
(Decision 41d), but the binaries have **never been executed** — no Bun, no macOS, no
Linux in-session, and CI itself is billing-blocked so it cannot substitute. The install
one-liner's second rung is therefore untested (`install/install.sh` and `.ps1` fall
npm → binary → Node bootstrap).

## What to check

- The binary starts at all, and `golem --version` matches the tag.
- `golem init` works — it writes into `.claude/` and `.mcp.json`, which is the P0 bar.
- `golem proxy` starts and forwards.
- **The panel (`golem`).** This previously carried an extra risk: ink's `yoga-layout`
  WASM asset. With ink removed (Decision 51) `src/tui/` is plain TypeScript with no
  assets, so it *should* bundle cleanly — worth confirming rather than assuming.

## Why this is the user's

It needs hardware that is not available to an agent in this environment. Unblocking CI
is also an account/billing step.

## Out of scope

Making the binary channel the default. Fixing anything the smoke test finds — that
would be a follow-up task with a real reproduction.
