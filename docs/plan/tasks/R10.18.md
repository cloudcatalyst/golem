## The defect

Raised by the user during the R10.14 debrief: *"at least having a message back
would be better than nothing."*

Golem is what produces the nothing. Both translation paths convert an empty
upstream completion into a **valid, well-formed, empty answer**.

Non-streaming:

```ts
if (content.length === 0) content.push({ type: "text", text: "" });
```

Streaming, in `_flush`:

```ts
if (this.#current === null) {
  // No content at all — emit a valid empty text block.
  this.#switchTo({ kind: "text" });
}
```

The upstream said "I produced nothing". Golem says "here is a valid response
containing nothing" — HTTP 200, `stop_reason: end_turn`, `output_tokens: 0`.
A client cannot tell that from a model deliberately answering with silence, so
Claude Code injects `[Your previous response had no visible output…]` and loops
forever. That loop ran from 2026-08-13T06:23 to 2026-08-14 in one session.

R10.14 removed the biggest *cause* of empty completions. It did not touch the
part that makes any future cause equally undiagnosable.

## What to build

Treat "no content and no tool calls" as a failed response, not an empty one.

- Return a proxy error naming what happened: the serving model, and that it
  returned no content. It must be distinguishable from a network or auth
  failure.
- Streaming is the harder half: by `_flush` the headers and `message_start` have
  already gone out, so an HTTP status is no longer available. Emit the failure
  in-band as a final text block the user can actually read (Golem-prefixed, in
  the style of the local-answer rail) rather than closing an empty stream. Say
  which shape was chosen and why.
- `finish_reason: "length"` with zero content is a DIFFERENT case — the model hit
  `max_tokens` before emitting anything, which is worth its own wording.

## Watch for

- **Do not turn a legitimately empty answer into an error.** A model answering a
  tool-only turn produces no text but does produce `tool_calls`; that is not
  this case. Gate on "no content AND no tool calls".
- Golem must never appear to speak as the model. Anything injected is prefixed
  and attributed, per the honesty rail (Decision 25) and the local-answer
  precedent.
- The Anthropic passthrough must not be touched — it is byte-faithful, and an
  empty completion there is Anthropic's own business.

## Out of scope

- A preflight context-window guard. Worth considering separately: the catalog
  already has `contextTokens` and `contextWarning`, so the proxy COULD refuse a
  request that cannot fit before spending a round trip. Note that the failure
  which prompted this task was NOT an overflow — the conversation fit in the
  model's 1M window — so a context guard would not have caught it.
- R10.17's `Read` offload gap.
