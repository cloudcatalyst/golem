## The divergence

| | brevity off | brevity full |
|---|---|---|
| `golem statusline` | `🗜 lossless · ✂ off` | `🗜 lossless · ✂ full` |
| VS Code status bar | `🗜 lossless` | `🗜 lossless · ✂ full` |

R10.24 made these two surfaces render one canonical shape and added a parity test
to keep them there. It did not catch this, because **every fixture it wrote used
`brevity: "full"`** — a parity test only pins the states its fixtures visit.

## The decision, and why

**Show `✂ off` on both**, i.e. the extension changes.

- The bar is already internally inconsistent: it prints `🗜 off` for the
  compression dial at zero and omits `✂ off` for the brevity dial at zero. Two
  dials, one line, opposite rules.
- A dial's position is information. "No segment" is indistinguishable from "an
  older Golem that had no such dial" — the reader cannot tell a setting from an
  absence.
- R10.24's rule — dials describe transforms the pipeline is *applying* — is about
  the states where **no stage runs at all** (off, unwired, bypass), and it
  already suppresses both dials there. A single dial at zero while the pipeline
  is working is not that case.
- The CLI line is the one read every turn, and it already shows `✂ off`.

The competing option (hide it on both) was considered and rejected on the first
two points. Recorded here rather than in a commit message because
`render.test.js` asserted the old behaviour deliberately — "statusBarText shows
brevity only while it is on", Decision 52's wording — so this reverses a
deliberate choice and should say why.

## Out of scope

- The dial-suppressed states (off / unwired / bypass). Both surfaces already
  agree there, and R10.24's rule stands: nothing running, nothing advertised.
- Any change to what a dial DOES. This is one segment of display.
- Decision 52's text. It says brevity must be visible whenever it is on, which is
  still true; it does not require that off be hidden.

## Gate

Standing verification bar, plus a parity fixture at `brevity: "off"` — the state
that was never visited — and `render.test.js` updated to assert the new rule
rather than the old one.

## Outcome

shipped — both surfaces render `🗜 lossless · ✂ off`, and the parity test now
visits the brevity-off state so the gap cannot silently reopen.
