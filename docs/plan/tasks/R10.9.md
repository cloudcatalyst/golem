## The defect

`dispatch()` short-circuits a trusted-local target:

```ts
if (permitsUnredactedDispatch(target)) {      // trust === "local" && isLoopback(baseUrl)
  const result = await options.inference.chat(request.role, messages);
```

`options.inference` is the **Ollama-backed tiered service**. So the branch means
"local ⇒ Ollama", not "local ⇒ the endpoint this target names". Declare a
loopback `llamacpp` target on `:8080` and `coder` will silently draft on Ollama
at `:11434` instead — or fail, if Ollama is not installed.

This was ~true before R10.8, when `ollama` was the only self-hosted provider.
Adding `llamacpp` makes it wrong in a way a user can hit by following the
documented path.

## Why R10.8 left it

Fixing it means dispatching a loopback target through the direct OpenAI transport
**without redaction** — a NEW unredacted egress path. R10.8's rules reserved that
explicitly, and rightly: the unredacted branch is the one place context leaves
the pipeline untouched, so widening it is a deliberate act with its own review,
not a side effect of adding a provider.

## The workaround that exists today

Declare the target with an explicit non-local trust:

```json
{ "id": "llamacpp:qwen", "gateway": "llamacpp-local", "model": "qwen2.5-coder", "trust": "lan" }
```

`lan` skips `permitsUnredactedDispatch`, so the direct OpenAI transport runs
against the configured `base_url` — reaching the right server. It is redacted,
which for a loopback server is unnecessary but harmless.

## What to build

Make the local branch dispatch to the target it NAMES, not to a fixed service.
The honest shape is that `permitsUnredactedDispatch` decides *whether to redact*,
while the transport is chosen by the target's provider like every other target.

Decide, and record the reasoning:
- Should the unredacted local path use the OpenAI transport against
  `target.baseUrl` (uniform, but a second unredacted egress) or keep routing
  through `InferenceService` when — and only when — the target's `baseUrl`
  matches `inference.ollama_base_url` (narrow, but keeps the special case)?
- What happens to a loopback target whose provider is neither `ollama` nor
  `llamacpp`? Today `defaultTrustFor` gives it `third-party`, so it never
  reaches this branch — confirm that stays true.

## Out of scope

- Changing `permitsUnredactedDispatch`'s CONDITION. `trust === "local" &&
  isLoopback(baseUrl)` is correct and independently re-checked; this task is
  about what happens after it returns true.
- `inference.providers` (R8.15) is read only by status/probe surfaces and never
  by the chat path — do not repurpose it here without saying so.
