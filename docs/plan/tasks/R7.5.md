## Goal

Publish `golem-run` to npm and the extension to the VS Code Marketplace, and tag the
release.

## State of play

The machinery shipped with R7 (Decision 41) and is unused: `sync-version.mjs` wires
into the build, `release.mjs` bumps both `package.json`s in lockstep, the tag-triggered
Release workflow exists, `RELEASING.md` is written, and `scripts/make-shrinkwrap.mjs`
generates the `npm-shrinkwrap.json` a published tarball needs (R8.10 / §98 — npm
ignores `package-lock.json` inside a tarball, so without it consumers inherit none of
our pinning).

`v0.1.1` is tagged locally. **`golem-run` is still unpublished — npm 404.**

## Why this is the user's

Publishing is outward and credentialed. An agent must not push a package to a public
registry under the user's account.

## Before publishing

- `npm run verify:deps` green (enforces exact pins, the `.npmrc` posture, pin↔lockfile
  agreement, and the ≤5 runtime-dependency ceiling — R8.10).
- `npm-shrinkwrap.json` generated so consumers inherit the pinning.
- **R7.3 first**, ideally: the standalone binaries are build-wired but have never been
  run per-OS, and the install one-liner falls back to them.
- The `golem.run` front door is a separate user task (R7.6-infra) — a Vercel app,
  not the nginx box this originally said. The install one-liner degrades gracefully
  while it is absent, but the documented path assumes it.

## Out of scope

Anything an agent could do instead. This task exists to stay visible, not to be picked
up by an agent.
