## Why this is `owner: user`, not `owner: agent`

Everything mechanically checkable is green: 21 tests in
`tests/integration/chat-surface.test.ts` covering every claim the screen makes
about itself, plus live runs confirming the chat route answers an unpaired caller
`device:no-certificate` and the URL is printed by `golem session host serve`.

Three things can only be settled by a device:

1. **Client certificates from a mobile browser.** The page is served over mutual
   TLS. Whether a phone browser will present an installed client certificate to
   a LAN IP, and how it prompts for it, differs by platform and by how the
   certificate was installed. This is the single most likely thing to not work,
   and it cannot be simulated here. If it does not work, that is a real finding
   about the whole R13.4–R13.6 chain and should be written up before anything is
   built on top of it.

2. **Whether it reads as honest.** ADR-0007 §2 forbids a screen that implies it
   is mirroring the developer's terminal. The tests assert the disclaimer is
   present; they cannot assert it *works*. That is a judgement about how the
   screen reads on a small display, and only a person looking at one can make it.

3. **The disconnect and relock behaviour, in the hand.** "Not connected replaces
   the content" and "the send box disappears" are asserted as CSS rules. Whether
   they feel like an honest interface or a broken one when the Wi-Fi drops
   mid-turn is not something CSS assertions establish.

## How to run it

```
golem device enrol "my phone"      # prints a single-use pairing code
golem device passcode <passcode>
golem device unlock <passcode>
golem session host serve --lan "hello — introduce yourself"
```

The last command prints an `https://<lan-ip>:4655/session/<id>/chat` URL. Open it
on the phone.

## What to do with the answer

Record it in `docs/plan/verification-notes.md` with the date, the phone's OS and
browser, and which of the seven held, with screenshots in a debrief under
`docs/wiki/debriefs/`.

If (1) fails — no client certificate from the browser — **do not work around it
by weakening the gate.** The device claim is one of R13.4's two required claims,
and an exception for "browsers find this awkward" would be the exact degradation
ADR-0007 §7b forbids. Write it up; the answer is likely a native shell (R12.6's
question) or a different credential presentation, and either is its own task with
its own ADR paragraph.
