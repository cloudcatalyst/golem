## The defect

Found during R10.11 (2026-08-13), from the other end: the new
`status --json` field contract asked why `vscode-extension/render.js` reads
`st.proxy.bypass` when nothing emits it. Nothing emits it because **the state it
describes no longer exists.**

`stopProxy` (`src/cli/proxy-daemon.ts:274`) reads the pidfile, removes it, and
kills the process. That is all it does. There is no bypass shim keeping the port
bound, and no third desired-state:

- `ProxyDesired` does not exist anywhere in `src/` (Decision 56(b) introduces it).
- `src/cli/proxy-state.ts`, named in R8.31's `touches`, is not in the tree.
- `src/cli/commands/proxy.ts` contains no `stopped`/`desired` handling.
- `SessionStateReport.proxy.bypass` (`src/cli/session-report.ts:51`) is declared
  and zod-validated but **never assigned** by `collectSessionStateReport`.
- `collectStatus` has no `bypass` at all, so the VS Code surface can never show it.

So the exact defect R8.31 closed is open again: `golem proxy stop` from any
surface leaves `ANTHROPIC_BASE_URL` naming a port nothing is listening on, and
every subsequent Claude Code request fails with connection-refused until the
proxy is restarted or the user hand-edits `.claude/settings.json`. The user's
original words on the report were "that needs to be much more robust".

`golem proxy wire` / `unwire` (Decision 56(d)) **did** survive — those are in
`src/cli/commands/proxy.ts`. It is specifically the shim and the three-state
lifecycle that are missing.

## Why it regressed

R8.31 is `state: done` and its debrief stands; this is not a re-litigation of the
design. The likely mechanism is R10.1, the first-pancake rewrite, which split and
deleted modules wholesale — `src/cli/proxy-state.ts` among them — and carried the
`wire`/`unwire` half forward without the desired-state half. Confirm that from
the history rather than assuming it, because *how* a shipped decision fell out of
a rewrite is the reusable lesson here, and R10.1's own debrief should gain a line.

## What to build

Decision 56 already specifies all of it; implement it rather than redesigning it.
The load-bearing constraint is 56(c) and it is not negotiable:

> The natural way to build a passthrough is the existing `x-golem-bypass` /
> level-0 path, and it is **rejected**: that path forwards untouched, i.e. with
> redaction off.

The shim serves at **level-1 semantics — redaction on, byte-faithful, no
compression, no brevity, no local-answer.** A Stop button that routed unredacted
prompts upstream would make the redaction-off path reachable from a click that
says nothing about redaction, which is a CLAUDE.md hard-rule breach arriving as a
convenience feature.

Then close the reporting loop, which is how this was found and is the cheap half:

- `collectStatus` emits `proxy.bypass` (`status --json`).
- `collectSessionStateReport` actually assigns `proxy.bypass` instead of merely
  declaring it.
- Reclassify `proxy.bypass` in `STATUS_FIELDS_READ`
  (`vscode-extension/render.js`) from `unemitted: "R10.12"` to its real
  classification. `tests/contract/vscode-status-fields.contract.test.ts` FAILS
  until that is done, on purpose — it is the tripwire that says the gap closed.

The renderers need no work: `render.js` `levelLabel`/`dialsSummary`/
`statusBarText` already handle the bypass state correctly and are tested. They
have simply never had a `true` to render.

## Out of scope

- Re-opening Decision 56. The trade-off (a stopped proxy still holds a socket) was
  accepted with reasons; this task implements the accepted design.
- Reachability semantics for `proxy.reachable`. It answers "is something
  listening", which stays true under the shim — that is what makes a renderer
  reading only `reachable` degrade to the old display rather than an incorrect one.
- Anything about level 0. Full passthrough stays reachable exactly where it
  already is.
