## What was wrong

`golem init` wrote Claude Code's wiring into the **committed**
`.claude/settings.json`: the `env` block, the `mcp__golem__*` permission rule,
six hooks, the status line, the default permission mode. Every one of those
values is machine-local in practice —

* `ANTHROPIC_BASE_URL` names a per-project port assigned on *this* machine;
* the hooks shell out to `golem`, which only exists where Golem is installed;
* R9.22 had already moved `NODE_EXTRA_CA_CERTS` out on exactly this reasoning,
  because a machine-absolute path resolves on no other clone.

So the committed file carried wiring that no clone could honour, and churned in
everyone's diff whenever a port, a timeout or a matcher changed.

The same shape appeared one level down: `golem config set` defaulted to
`--scope project`, committing a personal dial into everyone's checkout.

## What shipped

`claude.settings_scope` (`local` | `project`, default `local`), resolved once in
`src/cli/claude-settings-target.ts` and consumed by every writer.

* **Writes** go to the file the scope names.
* **Reads** always walk BOTH files, local first — Claude Code's own precedence
  (verification-notes §13). The scope moves where Golem writes, never where the
  answer to "is this project wired?" comes from.
* **Init sweeps the other file** (ownership-guarded), so flipping the scope and
  re-running init MOVES the wiring. Hooks made this mandatory rather than tidy:
  Claude Code MERGES hooks across settings files, so a leftover duplicate does
  not shadow — it runs twice.
* **Uninit sweeps both**, so a project that has been through a flip (or through
  an older Golem) comes out clean.
* **`golem config set` / `unset` default to `--scope local`.**

## The bug the split surfaced

The existing rule was "never clobber a FOREIGN setting". Two files add a second
way to take one over: writing ours into `settings.local.json` leaves a user's
`statusLine` or `defaultMode` in `settings.json` byte-for-byte intact — and
completely inert, because the local file outranks it. `writeStatusLine` and
`writeDefaultMode` now check the other file too and skip. Not clobbering is not
the same as not overriding, and only one of the two is visible in a diff.
