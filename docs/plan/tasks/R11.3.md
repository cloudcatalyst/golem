## The fault

`golem off` POSTs to the running proxy's admin endpoint and flips an in-memory
flag. Nothing is written to settings. So the next `golem proxy restart` — or a
SessionStart hook re-launching the daemon, or a reboot — brings the pipeline back
up with redaction, compression and brevity all running, and the user is never
told that the thing they turned off is on again.

This is the same class of fault R11.1 was about: a control whose displayed
position and actual effect disagree. R11.1 found it while retiring the slider and
deliberately did not fix it there.

## The choice to make first

R11.1 gave the pass-through case a persisted home: `proxy.bypass_all` — CLI-only,
loudly surfaced, and (because the stage table no longer has a redaction-free row)
the only way to reach redaction-off. So there are two honest designs, and this
task should pick one **before** writing code:

1. **`golem on`/`golem off` become aliases for `proxy.bypass_all`.** One concept,
   one persisted setting, one loud surface. Costs the ability to bypass for just
   the current listener, and makes `off` a durable, committed-scope change to how
   the project's proxy behaves.
2. **`off` stays volatile and starts admitting it.** Keep the admin POST, but
   print that it lasts only until the proxy restarts, and give every status
   surface a way to show "off (this listener only)" distinctly from the persisted
   bypass. Costs a fifth proxy state on surfaces that R10.24 just finished
   reducing to four.

Prefer (1) unless a use for a listener-scoped bypass turns up that a persisted
setting cannot serve — but record the reasoning either way, because R10.24's
lesson is that a state which exists on one surface and not another drifts.

## Out of scope

- Re-opening ADR-0004. `proxy.bypass_all` is CLI-only and loud, and stays so.
- Any new dial. `compression.level` and `brevity.level` are the only dials
  (R11.1); this is about the master switch, not about them.
- Changing what the pipeline does when it is on.

## Gate

Standing verification bar plus: a test that restarts the proxy across the toggle
and asserts the state the chosen design promises, and (if design 2 wins) a
statusline-parity case for the new state — the R10.24 parity test is the pin that
keeps the two surfaces from drifting again.

## Outcome

**Design 1 was chosen**, with the reasoning the brief asked for: `golem on` /
`golem off` are now the writers of `proxy.bypass_all`. What decided it was not
durability but VISIBILITY. Every status surface reads that setting
(`status-collect.ts`, `statusline.ts`, `watch.ts`), so while the switch lived in
the proxy's memory a bypassed machine — redaction included in what it skipped —
rendered as a healthy pipeline with dials beside it, and `REDACTION_OFF_WARNING`
never fired. Design 2 would have needed a fifth proxy state on every surface
R10.24 had just finished reducing to four; design 1 needed none, because the
surfaces were already looking in the right place.

No use for a listener-scoped bypass turned up. `x-golem-bypass` already covers
the one-request case, which is the only genuinely transient need.

Persisting alone would have cost the instant apply, since the setting is read
where the proxy is constructed (`restart: "proxy"`). So the switch writes to the
`local` scope and then POSTs the same state to the live listener: durable AND
immediate, no restart. With no proxy listening the write still lands and the
output says when it takes effect.

Found on the way: nothing in the suite covered `golem on` or `golem off` at all —
which is why R11.1's otherwise thorough sweep missed them. The logic moved out of
the commander callback into `src/cli/pipeline-switch.ts` so that it could be
tested, including the wording, since "redaction is off" is the sentence this task
exists to make sure somebody sees.
