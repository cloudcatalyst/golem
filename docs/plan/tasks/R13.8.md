## Why this exists

"Ideally being able to start new sessions within projects using the proxy from
the companion app is also desirable" — and, from ADR-0007 Revision 1, the user is
content without forking, *provided* a device can continue a conversation, see the
previous messages, and start a new one. That sentence is this task's whole scope,
and it is deliberately smaller than the draft's.

## What to build

1. **A project list worth trusting.** Enumerate the projects Golem actually knows
   — from configured roots and from conversations already observed — and say when
   a root is stale or unreachable rather than offering it. A picker that offers a
   path that no longer exists is worse than a text field.
2. **Start a new conversation** in a chosen root, through R13.3, from the device.
   Subject to gate-map item 2 (which roots) and item 5 (re-authentication for
   origination) — read those from policy rather than hard-coding either.
3. **Resume an existing conversation.** Reattach to a live hosted session, or
   restart a hosted session for a conversation whose process has exited, with the
   stored history as its context. "Continue" must mean the agent has the earlier
   turns, not merely that the screen shows them.
4. **Read the previous messages.** Scrollback from R13.2's store, paged — a phone
   is not going to hold a long conversation in one DOM, and a request for
   "everything" on a large conversation must not be what teaches us that.
5. **One conversation, one identity.** Key conversations as `session-tree.ts`
   keys them (as fixed by R8.13) so the list, the store and the tree agree, and a
   worktree resolves the way `ccr-ref-scope` decided rather than forking into two.
6. **Sensible refusals.** No store entry, evicted history, a project whose
   `.claude` wiring is missing, a root that resolves elsewhere — each refuses with
   a reason naming what it looked for.

## Out of scope

**Forking a conversation at an earlier turn** — dropped by ADR-0007 Revision 1.
Do not build it, and do not leave a half-built seam implying it: the session tree
detecting a branch is an observation, not a feature. Non-Claude runners
(ADR-0007 §10). Editing files from the device. Rewinding or mutating a live
harness session — anything touching the developer's own session belongs to R13.7
and its visibility rules. Cross-machine sessions.

## Gate detail

Integration tests: start a conversation in a temp project root and observe it
live; stop the host process and resume the same conversation, asserting the agent
receives the earlier turns as context; assert scrollback paging returns turns in
order with no gaps or duplicates; assert each refusal names what it looked for.
Plus the manual device demonstration in the gate line, including the day-later
case (a fresh proxy, a fresh app). Wiki page covering what continuing a
conversation means here — and that a hosted conversation is not the session on
the developer's screen, which is the assumption users will bring and it is wrong.
