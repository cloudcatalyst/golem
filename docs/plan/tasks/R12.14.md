## Why this is `owner: user`, not `owner: agent`

Everything mechanical was verified in-repo and is green: 16 tests in
`tests/integration/dashboard-companion.test.ts`, plus a live run that bound
`0.0.0.0`, served the page over a real LAN address (`http://192.168.0.20:<port>/`),
returned the manifest as `application/manifest+json`, returned a 936-byte
decodable PNG for `/icon-180.png`, and answered `POST /api/stats` with 405.

None of that is the same as a phone. Three specific claims can only be settled by
one:

1. **`display: standalone` is a request, not a guarantee.** Whether a launched
   icon opens without browser chrome depends on the platform and, on Android,
   on install path. Over plain HTTP on a LAN there is no secure context, so no
   service worker can register and Chrome will not show its automatic install
   prompt — "Add to Home screen" from the browser menu still works, but whether
   the result is an app-shaped launch or a bookmark is exactly what needs
   looking at.
2. **iOS ignores the manifest entirely** and reads `apple-touch-icon` plus the
   `apple-mobile-web-app-*` meta tags. Those are shipped and asserted as present
   in the HTML, but "the tag is in the markup" and "iOS used it instead of
   screenshotting the page" are different facts.
3. **The disconnected state is a timing claim.** `STALE_AFTER_MS` is three
   missed polls (6s). Whether that reads as responsive or as a nuisance on a
   real phone walking out of Wi-Fi range is a judgement about a device, not an
   assertion about a constant.

## How to run it

```
golem dashboard --lan          # prints the URLs a phone can type
```

Then on the phone, same Wi-Fi: open one of the printed URLs, use the browser's
share/menu → **Add to Home Screen**, and answer the four questions in the gate.

## What to do with the answer

Record it in `docs/plan/verification-notes.md` with the date, the phone's OS and
version, and which of the four held. If (1) or (2) fails, that is a real finding
about the shell and worth a follow-up task — **not** a reason to reach for a
native app, which R12.5's brief already ruled out of scope and pointed at R12.6.
If (3)'s timing reads badly, `STALE_AFTER_MS` is one constant in
`src/dashboard/server.ts` and moving it is a one-line change with a test.
