## The decision

The user, 2026-08-20: *"I'm confused about what the slider means vs compression. I
feel we don't need the slider any more."* Asked how far to go, they chose **full
retirement**.

They are right, and the confusion is designed in. `slider.level` is a **preset
over two dials** (Decision 52) — compression and brevity — so two controls
describe one thing, and every status surface has to show both or lie by omission.

It is worse than redundant on the default upstream. Decision 31 gates the lossy
semantic and context-substitution stages OFF on a prompt-caching upstream, so
**levels 2 and 3 are inert there**. Live, on the user's own machine, mid-R10.24:

```
Slider: level 3 (aggressive) → effectively 1 (lossless)
Dials:  brevity full (pinned) · compression 3→1 (auto — follows slider 3)
  ⚠ level 3 (aggressive) is inert here: the lossy semantic and context-substitution
    stages are off on a prompt-caching upstream (Decision 31 …), so this behaves
    as level 1 (lossless)
```

Three rows and a warning to say "the number you set does nothing". `golem status`
is being scrupulously honest; the control is what is wrong. R10.24 made the
status LINE honest about the same thing (it shows the effective level, not the
configured one) — this task removes the need for the explanation.

## What to build

1. **An ADR in `docs/decisions/`** first, superseding the slider half of
   Decisions 21f and 52 and recording the reasoning above. This is a
   user-facing-concept removal; it needs the record, not just a commit message.
2. **Two dials, set directly.** `compression` (`off|1|2|3`) and `brevity`
   (`off|lite|full|ultra`) lose their `auto` "follows the slider" state, which
   only exists because a preset drives them.
3. **A migration** (`src/config/migrations.ts` already has the machinery R9.6
   built) that rewrites a `slider.level` into the two explicit dial values it
   currently resolves to — so no project changes behaviour by upgrading. Keep the
   old leaf readable-but-dead for one release cycle if that is cheaper than a
   hard cut; say which was chosen and why.
4. **Level 0's redaction bypass moves to its own setting.** Today level 0 is
   "full bypass, never default, surfaced loudly" — a CLAUDE.md hard rule and the
   single exception to redaction never being weakened. It must NOT become
   `compression: off`: compression and redaction are different guarantees, and
   collapsing them is how a user turns off redaction while believing they turned
   off compression. Give it an explicit name, keep it loud in every surface, and
   keep R8.33's rule that only the CLI can set it (never a tool call).
5. **Remove the surfaces:** `golem slider`, the `level` MCP tool (check
   Decisions 27/35 for the tool-name contract before deleting — the tool list is
   part of the MCP surface), `golem.setSlider` and its VS Code menu entry, the
   `slider` block in `status --json` (and therefore `STATUS_FIELDS_READ` +
   `tests/contract/vscode-status-fields.contract.test.ts`), and `slider`/`level`
   from telemetry events.
6. **Telemetry semantics.** `PipelineEvent.level` is recorded on every request
   and rolled up by `golem stats`. Decide whether historical rows keep meaning
   (they do describe what ran) and what replaces the field. Do not silently
   reinterpret old data.

## Watch for

- **~379 references across 63 files** (`grep -rn slider src/`). Most are
  display, tests and docs; the load-bearing ones are `policy.ts`,
  `effective-level.ts`, `schema.ts` and the pipeline's stage gating.
- **`resolveEffectiveCompression` (§103) must survive.** "The level you set" vs
  "the level that ran" is a real distinction that outlives the slider — a caching
  upstream still degrades level 2/3 to lossless, and both status surfaces must
  keep saying so.
- **No external users yet.** The first npm publish (R7.5) is still queued, so a
  clean break needs no deprecation window. Confirm that is still true before
  choosing a hard cut.
- **The wiki and spec reference the slider throughout**, including
  `docs/wiki/WIKI.md`'s index and the savings dashboard. `golem wiki check` must
  pass, and a stale page describing a control that no longer exists is worse than
  no page.

## Out of scope

- Changing what the stages DO. This is a control-surface change; compression,
  brevity and redaction behaviour must be byte-identical afterwards for an
  equivalent configuration.
- Revisiting Decision 31 (semantic gating on caching upstreams). It is the reason
  levels 2–3 are inert, but it is a separate, measured decision (~9× more
  expensive if forced, §103).
- The `brevity` dial's own values.

## Outcome

shipped — `slider.level` is gone from the schema, the CLI, the MCP surface,
telemetry and every status surface. `compression.level` (`off|1|2|3`) and
`brevity.level` are set directly and take effect within a second, with no
restart. The full bypass is `proxy.bypass_all`: persisted, CLI-only, loud, and —
because the stage table no longer has a redaction-free row — the ONLY way to
reach redaction-off. Existing projects migrate once, automatically, with a backup
and no behaviour change; verified on seven fixtures and on this repo's own
settings file. See ADR-0004 and verification-notes §132.

Left open (found here, not fixed here): `golem on`/`golem off` is in-process
only, so it silently reverts at every proxy restart.
