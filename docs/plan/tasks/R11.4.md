## How these were found

By deploying R11.1 and reading the output. `golem init` printed:

```
• `uv` detected — enable semantic compression: set compression.headroom_sidecar=true and slider ≥3.
```

A hint naming a control the same release had retired. Pulling that thread found
three kinds of leftover.

## 1. Strings that outlived the control

Four user-facing strings still said *slider*: the `uv` hint above, the proxy's
sidecar line (`slider ≥3`), `golem config get`'s example key (`slider.level` — a
setting that no longer exists), and `golem status`'s own description. All now name
`compression.level`, and the semantic gate is stated as `≥2`, which is what
`LEVEL_TABLE` actually does (level 2 is `stale_turns`). Stale *comments* were
refreshed in the same pass, except where they deliberately record the retirement.

## 2. A branch for a tool that cannot be called

`classifyAction` still routed `mcp__golem__level` to `classifyLevelTool`, which
graded level 0 as `outward` and 1–3 as `write`. The tool went with the slider, so
the branch was unreachable — and its tests passed vacuously against it. Removed,
with a note where it stood. An unrecognized tool already falls through to
`unknown`, which is **gated**, so the removal is strictly stricter than the
`write` a level call used to earn.

## 3. A skill that `golem init` claimed to prune, and did not

`BASICS_SKILLS` carried the comment "`golem init` prunes a managed skill that is
no longer in this table, so the old /golem/slider directory is removed on the next
init". `installSkills` does no such thing — it only ever writes the names in the
table — so `/golem/slider` survived R11.1 in the repo *and* in every project that
had ever run init, still telling agents to run `golem slider 3`.

`pruneRetiredSkills` now makes the comment true, guarded by the same provenance
rule as the install side (R9.5): a skill still byte-identical to what Golem last
wrote is Golem's to delete; one the user edited, or that Golem has no record of
writing, is reported as a `conflict` and left alone. The namespace holds the
user's own skills too — `uninit` may take the whole directory, `init` may not.

## Out of scope

- Pruning anything other than skills. The same "dropped from a table" question
  applies to guidance rules and MCP entries; neither was observed stale, and each
  has its own ownership rules.
- The `stats` skill this surfaced as a `conflict` in this repo: it has local
  edits, so init correctly kept it. Reconciling that text is a separate decision.
- Re-litigating ADR-0004 or any part of R11.1's design.

## Gate

Standing verification bar plus four new `cli-init` cases: the retired skill is
removed and its provenance record forgotten; an edited one is kept and reported;
a skill Golem never wrote is untouched; and `--dry-run` reports without deleting.

## Outcome

shipped — no user-facing string names the slider, `classifyLevelTool` is gone,
and `golem init` prunes retired skills for real (which removed `/golem/slider`
from this repo). Found by deploying the previous release and reading its output —
the cheapest review available, and the only one that catches a stale hint.
