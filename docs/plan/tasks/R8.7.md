## Goal

Add an `edit` mode to `coder`: the frontier model writes a ~50-token instruction, the
**local** model emits a search/replace block, **Golem validates it** (search text must
match exactly, tree-sitter parse must still succeed, optional formatter pass) and
applies it, returning a compact confirmation.

## Why this one is worth the risk

It attacks **output** tokens — never cached, ~5× the price of input — which is the
axis Decision 52 opened and the only axis where the arithmetic is still favourable
after §93 (cache) and §100 (tools block). A 300-line edit written by the frontier
model is thousands of output tokens; the instruction that describes it is fifty.

## The gate is the task

This repo's precedent is unambiguous: the tools-block shrinker was **rejected** on its
own harness (§89), and R8.S1 was **rejected** on arithmetic after its gate proved
insensitive (§100). Build the harness first, and be willing to publish a negative.

Specifically measure:
- **apply-success** — does the search text match, does the file still parse?
- **semantic correctness** — against hand-written edits, not against itself.
- **the edit format** as an independent variable. Aider treats format as measured, not
  assumed; so should this.

Beware the §100 failure mode: if the local model's behaviour is identical across
conditions, the *instrument* is insensitive and a flat result is not a pass. Say so.

## Hard constraints

- Validation is Golem's, not the model's. An unvalidated apply is a code-corruption
  path.
- Never engages automatically. The slider is a compression dial and must not reach
  the local model (Decision 31); this is `coder`, an explicit act.
- Applying an edit is a write — it obeys the autonomy gate (ADR-0002) like any other.

## Out of scope

Competing with Claude Code's own Edit tool. A full apply-harness product. Any path
where a failed validation silently falls back to writing the model's raw text.

## Outcome

Shipped 2026-07-31: harness first (golem bench edit), gate SHIP on whole-file only — 91.7% semantic / 100% apply vs 33.3% for both search-replace and udiff (§110). coder mode:edit ships opt-in behind inference.local_editor_enabled (default false: +313 definition tokens on, byte-identical to R8.6 off), proposes a validated diff by default and writes only on apply:true; four validation layers incl. a new definition-loss guard. Unmeasured: files >40 lines, non-tree-sitter languages (proposed, never written), and displacement.
