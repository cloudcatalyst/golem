## Problem

`CcrStore.putIfAbsent` has a classic TOCTOU (time-of-check-time-of-use) race:

```ts
async putIfAbsent(refId, envelope): Promise<boolean> {
  const exists = await this.#blobs.exists(refId);  // check
  if (exists) return false;
  await this.#blobs.put(refId, ...);                // use — but another call may have passed the check
  return true;
}
```

Two concurrent callers with the same refId both see `exists === false`, both write. Content-addressed so data is identical (same bytes for the same hash), but one write is wasted and the `rename` in `LocalDirBlobStore.put` (see R8.16) makes the second write destructive.

## Fix

Depends on the fix for R8.16. If R8.16 adds per-key locking to `LocalDirBlobStore`, this race is resolved at the store level. If R8.16 goes with the minimal fix (document + skip conflict), then `CcrStore.putIfAbsent` needs its own lock:

```ts
private readonly #putLocks = new Map<string, Promise<boolean>>();

async putIfAbsent(refId: string, envelope: CcrEnvelope): Promise<boolean> {
  const existing = this.#putLocks.get(refId);
  if (existing !== undefined) return existing;
  const promise = this.#doPutIfAbsent(refId, envelope);
  this.#putLocks.set(refId, promise);
  promise.finally(() => this.#putLocks.delete(refId));
  return promise;
}
```
