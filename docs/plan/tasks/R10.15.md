## The defect

Found 2026-08-14 while diagnosing a duoop session on
`openrouter:deepseek/deepseek-v4-flash-0731`.

`count_tokens` has no handler anywhere in `src/` — `grep -rn "count_tokens" src/`
returns nothing. On a translating upstream the proxy rewrites every request path
to the chat-completions path:

```ts
requestPath = translated.path ?? translate.path;
```

So `POST /v1/messages/count_tokens` is translated as if it were a normal
`messages` request, sent to `/v1/chat/completions`, and answered with a **full
assistant completion**:

```
{"id":"…","type":"message","role":"assistant","model":"deepseek/deepseek-v4-flash-0731",
 "content":[{"type":"text","text":"Hello! How can I help you today?"}],
 "stop_reason":"end_turn","usage":{"input_tokens":5,"output_tokens":99}}
```

The caller asked how many tokens a prompt would cost and got prose, a bill for 99
output tokens, and no `input_tokens` field in the shape it expected.

OpenAI-schema upstreams have no equivalent endpoint, so there is nothing to
forward this to — it has to be answered locally or refused.

## What to build

Answer it locally, in the providers layer so it is unit-testable, and let the
proxy do nothing but wire it.

- Add an optional `countTokens(body)` to `UpstreamTranslator`, returning the
  Anthropic-shaped `{"input_tokens": N}` body.
- Implement it for the OpenAI translator by summing `estimateTokens` over what
  actually goes upstream: system text, each message's text and tool_result text,
  and the tool definitions (name + description + schema).
- In `src/proxy/server.ts`, when a translating upstream is configured and the
  request path is the `count_tokens` route, respond with that body instead of
  making an upstream request.

## Watch for

- **This is an estimate, not a count.** `estimateTokens` is the ~4 chars/token
  heuristic (deliberately tokenizer-free — see its header). Say so in the code
  comment and in the wiki page, because a number that looks authoritative and is
  not is exactly the kind of thing Golem's honesty rail exists to prevent.
- **Do not touch the Anthropic path.** On a byte-faithful upstream `count_tokens`
  already works, because it is forwarded verbatim; this route must only engage
  when a translator is present.
- Keep the response body to `{"input_tokens": N}`. Extra fields invite a client
  to trust a shape Anthropic does not promise.
- The path check must tolerate a query string and the gateway base-path prefix
  that `basePath` may add.

## Out of scope

- A real BPE tokenizer. That is a heavyweight dependency the default install
  forbids, and the estimate is good enough for a context meter.
- Gemini's translator. Same gap likely exists there; fix it separately once this
  shape is settled.
