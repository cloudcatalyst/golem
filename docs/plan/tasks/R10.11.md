## The defect

`vscode-extension/render.test.js` is a real test suite that **nothing executes**:

- `vitest.config.ts` includes only `tests/**/*.test.ts`, so `npm test` never sees
  it (it is `.js`, and outside `tests/`).
- CI runs the same vitest command, so CI never sees it either.

It is run by `node --test vscode-extension/render.test.js` and by nothing else.
It was **4 tests red on `main`** before R10.10 touched anything.

## What that cost

The extension silently drifted four releases behind the CLI, and every symptom
was user-visible:

- It called `golem account list` / `golem account use` in five places. R9.23
  removed that command, so every poll's gateway list returned null and the
  "Switch upstream" picker was empty with a no-op switch. (Fixed in R10.10.)
- `render.js` read `local_model.coder_model`, a field the CLI never emitted — it
  is `local_model.model` — so the status bar showed a bare "local" instead of the
  model id. (Fixed in R10.10.)
- It gated on `local_model.coder_enabled`, deleted by R9.23. (Fixed in R10.10.)

The remaining 4 failures are a **third** drift: the tests assert
`m.localCoderEnabled` / `m.localCoderModel` while `buildModel` returns
`coderEnabled` / `coderModel`. So they would fail on names even against a correct
implementation — which is how you can tell nobody has run them in a long time.

## What to build

1. Fix the 4 failing tests against the REAL shapes `status --json` emits today.
   Check each assertion against live CLI output rather than against the existing
   expectation, since the expectations are the thing that rotted.
2. **Make them run in the standard command.** That is the actual fix — everything
   above is a consequence of them not running. Options: point vitest at
   `vscode-extension/*.test.js` too, or add a `test:extension` script that
   `npm test` and CI both call. Prefer whichever means a contributor cannot run
   "the tests" and miss these.
3. Consider a shape contract: the extension consumes `status --json` as an
   untyped blob, so a CLI rename is invisible to it until a human notices a
   wrong label. A test asserting the handful of fields `render.js` reads are
   present in a real `collectStatus` report would have caught all three drifts
   at their source.

## Out of scope

Rewriting the extension in TypeScript. It is plain JS on purpose (no build step
for the webview); this task is about the tests running, not the language.
