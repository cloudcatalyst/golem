## Goal

Reported by the user immediately after R9.3 landed: *"based on these changes, the
status line and status bar makes less sense."*

They were right. Both surfaces rendered `local (qwen2.5-coder:7b) + anthropic
(claude-opus-5[1m])` — a shape that hard-codes the assumption R9.1–R9.3 removed,
that **drafting is local and only the upstream is a real choice**. After R9.3 a
draft can run on any declared target, so "local" was describing a constraint that
no longer exists.

## What shipped

- Both surfaces name the **chat** model plus **only the workers whose model
  differs from it**, flattening to one segment when they agree.
- `inference.worker_targets` — a map of worker name → target id, so "the default
  coder model" is a real settable thing rather than permanently local.
- `KNOWN_WORKERS` + `unknownWorkerWarnings`: the map's one weakness (a typo'd key
  is silently ignored) bought back with validation.
- `golem status` lists every worker with its target, marks one that matches chat,
  and reports a worker whose target does not resolve as **FAILS CLOSED**.

## Decisions taken (USER, 2026-08-09)

1. **Symbols, not role words**, on the status line — glyphs left as placeholders
   for the user to choose, isolated in one `ROLE_MARKS` constant per surface.
2. **"chat", not "thinker"/"reasoner"** for the conversational model. Both
   rejected terms collide with this repo's existing narrow use of
   reasoning/thinking (`upstream_reasoning_effort`,
   `map_reasoning_to_thinking`, `reasoning_content` → `thinking` blocks), so
   either would read as a claim about reasoning traces. "chat" names the job, in
   the same style as the existing roles (`summarizer`, `drafter`, `judge`).
3. **A map keyed by worker**, not one settings leaf per worker — taken after the
   user flagged that more workers are coming (a `writer` for documents). A
   scalar each would grow a schema leaf, a UI-model entry, a status field and two
   status-surface branches per worker.
4. **Line policy: chat + only what diverges.** Workers that agree with chat
   collapse away, which is what keeps the line bounded as workers accumulate.

## Follow-ups

- Pick the final glyphs (both `ROLE_MARKS` copies; a test pins that they agree).
- A `writer` worker: add its name to `KNOWN_WORKERS`, give it a glyph, and have
  the tool pass `worker: "writer"` when it dispatches. Nothing in the config or
  status layers needs to change.
