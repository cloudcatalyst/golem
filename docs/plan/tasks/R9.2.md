## Goal

Make the proxy serve **many targets concurrently** instead of one upstream per
run, selected per request by an explicit, user-authored act. This is what lets a
**sub-agent branch off onto its own model** — the second half of the user's ask,
alongside R9.3's `coder` diversion.

Sibling of R9.3; both depend only on R9.1 and may land in either order.

## Verification gate: CLEARED

This task was gated on whether Claude Code forwards an arbitrary model string.
**It does** — `verification-notes.md §114`, verbatim from `/docs/en/model-config`:

> The check runs only on the Anthropic API. On Amazon Bedrock, […] and behind an
> LLM gateway or a custom `ANTHROPIC_BASE_URL`, your provider or gateway defines
> the model names, so **Claude Code passes any string through without checking
> it.**

Golem *is* a custom `ANTHROPIC_BASE_URL`, so the recognition check is disabled by
construction, and sub-agent frontmatter documents "a full model ID" as an
accepted `model` value.

**One residual empirical check before shipping** (§114 caveat 5): `golem/coder`
contains a slash, which was not empirically tested. Run one real request and
confirm the string reaches `sniffRequestModel` intact. If it does not, fall back
to a flat id (`golem-coder`) — the design is unaffected either way.

## Route resolution — three levels, all explicit

| # | level | authored by |
|---|---|---|
| 1 | virtual model id in body — `model: "golem/coder"` | user / sub-agent definition |
| 2 | header `x-golem-target: <id>` | hook / config |
| 3 | `proxy.default_target` | user config |

**No declarative rules engine, and no `x-golem-prefer` suggestion channel.** Both
were dropped when diversion moved out-of-band (see the proposal). Do not
reintroduce a rule that keys on a *per-turn* signal such as thinking-enabled:
that ping-pongs one conversation between targets and busts the prompt-cache
prefix on every switch. The design makes that class of rule inexpressible on
purpose.

## The three edits in `server.ts`

1. **`Pool` → pool registry.** `server.ts:70` builds one `Pool` from
   `upstreamBaseUrl` in the constructor. Replace with a lazy `Map<origin, Pool>`,
   bounded, all entries closed in `close()`. This is the *entire* structural
   blocker; per-origin pooling is what undici is designed for and concurrency
   across targets falls out for free.
2. **Resolve the route BEFORE the pipeline.** Order becomes *read body → resolve
   route → pipeline → translate → forward*, because the route determines two
   pipeline inputs: the redaction floor (from `trust`) and `assumeCachingUpstream`
   (from `upstreamAssumesCaching(route.provider)`, which gates the lossy semantic
   stage). Redaction still runs first *within* the pipeline — the hard rule holds.
3. **Read transport from the route, not `this.config`.** `basePath`,
   `mapUpstreamHeaders` and `translateUpstream` become fields of the resolved
   route (`server.ts:158-188`). The SSE byte pipe, usage sniffer, translating
   branch and error mapping are all untouched.

The provider capability helpers (`isTranslatingProvider`,
`upstreamAssumesCaching`, `upstreamChatCompletionsPath`, …) are already pure
functions of `(provider, baseUrl)` and **need no changes at all.**

## Keep it additive

`ProxyServerOptions.resolveRoute` is optional; **when absent the proxy behaves
exactly as today.** The existing single-upstream fields stay as the degenerate
one-target case. This is the difference between an additive change and a risky
rewrite — every existing recorded-shape and byte-fidelity test must pass
*unmodified*, and that is part of the gate.

`ProxyRequest` gains an optional `route` field so the pipeline can see the
decision — following the `respondDirectly` precedent (Decision 33) rather than
inventing a new seam.

## Also in scope

- `src/providers/routing.ts` — the precedence chain as a **pure function**
  returning `{ targetId, reason, sticky }`. No I/O, exhaustively unit-testable;
  `reason` is what the audit log records.
- Conversation binding via the existing `conversationKey()` (hash of the first
  message, shared by `session-tree.ts:101` and `cache-prefix.ts`). An
  optimisation only — level 1 is already stable across turns because the client
  sends the same id every turn. §99's key collision is benign here (both
  conversations land on the same default), so R8.13 is a nice-to-have, not a
  dependency.
- `served-model.ts`: the single `accountId`-keyed snapshot becomes per-target.
  Display surfaces must show *which target served what* — the spec's 21e
  correctness rail ("the responding model is always visible") is not optional.
- A clear proxy error for an unknown `golem/*` id. Claude Code will **not** catch
  it (§114 caveat 4), so Golem must.
- Per-target rows in `golem status`.

## Out of scope

- `coder` (R9.3).
- Failover / route-on-exhaustion — out per ADR-0003 and the 2026-08-08 scope
  decision.
- Rules engine, suggestion channel.
- Multi-port binding (proposal open question 4) — defer until a second client
  actually exists.

## Watch for

- **Per-target limit prediction.** `limit-prediction.ts` assumes one upstream and
  one rate-limit window. This is already observably broken with one target — the
  auto-park went blind during the design session because the active upstream
  emits no `anthropic-ratelimit-unified-*` headers. With N targets it is
  structural: track state per target, and show header-less targets as
  **unmonitored** rather than letting one silently drag the whole prediction
  dark. Snooze/park (Decision 45) inherits this.
- Byte-fidelity is a property of the **provider, not the proxy**. Restate it
  per-route: an Anthropic-protocol route is byte-faithful, a translating route is
  not and never was (R6.1 case b). Recorded-shape tests become a per-route matrix.
- `accounts.ts:8` says "There is NO per-request routing here (that is 21e,
  future)". Update the comment with the code.
