## Why this exists

This is the load-bearing task of the series: everything else is a surface on top
of it.

Note what Revision 1 changed and what it did not. Enforcement is no longer a
precondition for *sending* — authorship is unrestricted (ADR-0007 §3c) — but a
loop Golem owns is still the only place Golem can refuse rather than merely ask,
and that strength is what the gate map (§3d) spends. A host that can only `ask`
leaves item 4's routing and item 3's lock resting on the harness's own dialog,
which is exactly the weakness R12.11 found.

## What to build

1. **Spawn and supervise.** Start the runner R13.1 chose, in a given project
   root, with the proxy base URL in its environment (invariant 8: same
   redaction, same telemetry, same limits, no exemption). Supervise it the way
   `multiplex.ts` supervises local work — bounded, crash-tolerant, nothing lost
   silently, `lastError` recorded rather than thrown away.
2. **A real `deny`.** For `destructive` and `outward`, the host refuses the call
   outright and tells the conversation why. This is the first place in Golem
   where a `deny` exists at all, so it needs its own type change and its own
   argument in the code comment: `src/autonomy/gate.ts`'s `GateEmission` is
   `"allow" | "ask" | null` because a hook can only ever request a question.
   **Do not widen the existing hook's type to add `deny`** — that would change
   the meaning of the guest path. Model the host's decision separately and say
   in the comment why the two are not the same enum.
3. **`ask` still means a human.** For every other class that would prompt, the
   question goes to whoever is attached — the device if one is, the local
   dashboard if not. Nobody attached means nobody answers, which per invariant 3
   is a denial, not a wait forever.
4. **Attribution before delivery.** Device id (or "local"), timestamp, and the
   exact text appended to the action log *before* the turn is relayed
   (invariant 4). A turn nobody can attribute must not run.
5. **Lifecycle.** Start, list, attach, detach, stop, and a session that outlives
   the CLI invocation that created it. Sessions are per project root; two roots
   are two sessions; a worktree resolves like `ccr-ref-scope` decided.
6. **Park-aware.** A hosted session is subject to the usage-limit park like
   anything else (invariant 8). At the limit it parks and says so — it does not
   burn the window that the developer's own session needs, and it does not die
   silently the way a subagent does (the `subagent-park` lesson).

## Out of scope

Any device-facing transport, pairing or UI (R13.4–R13.6). Injection into a
*live* harness session (R13.7) — that is the other mechanism and it has its own
enforcement story. The device-facing start and continue flows (R13.8). Running a
non-Claude runner: one adapter,
and leave the seam obvious.

## Gate detail

An integration test at the seam that actually spawns a session (not a mocked
runner) and asserts: a `destructive` call is refused with a message; a `read`
call proceeds; the transcript lands in R13.2's store redacted; the action log
carries attribution; and a mid-turn kill leaves no half-applied state. Plus the
manual demonstration in the gate line above, recorded in the verification note
with the commands used. A wiki page describing what a hosted session is, and how
it differs from the session on the developer's screen — §2's honesty requirement
is a documentation obligation as much as a UI one.
