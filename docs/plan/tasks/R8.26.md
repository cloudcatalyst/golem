## Problem

The `KnownContentLookup` type is a function `hash → label` that the context-substitution stage uses to recognize content it has seen before. If the same hash maps to different labels on different requests, the marker text changes — which breaks the byte-identical prefix stability that Anthropic prompt-cache hits depend on.

The module doc (lines 13-28) explains why the stage is gated on non-caching upstreams, but the `KnownContentLookup` type itself carries no documentation about the purity requirement. A caller building a lookup from a mutable cache that grows between requests would produce different labels for the same hash without realizing the consequence.

## Fix

Add a JSDoc comment on the `KnownContentLookup` type:

```ts
/**
 * A pure function of content hash → display label.
 *
 * **Must be deterministic:** the same hash must always produce the same label.
 * This function is called across multiple requests, and varying labels produce
 * different marker text that breaks prompt-cache prefix stability.
 * Build the lookup from a stable snapshot, not a live/mutable cache.
 */
export type KnownContentLookup = (hash: string) => string | undefined;
```
