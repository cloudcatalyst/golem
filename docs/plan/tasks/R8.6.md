## Goal

Spawn user-provided language servers and expose `diagnostics` / `definition` /
`references` / `hover`. Start with `typescript-language-server` plus a config map.

## Why

From the OpenCode review: an agent that can ask "where is this referenced?" stops
grepping and stops reading whole files to find out. Complements R8.5 — the map says
what exists, the LSP says what refers to what.

## Tier and posture (Decision 53)

**Tier 2.** The user brings the server; Golem spawns it. Off by default. Absence
degrades to a no-op. No native deps, argument-array spawn (never a shell string),
cross-platform including `PATHEXT`-aware detection on Windows — the `src/ext/`
registry already does exactly this and is the right home for the manifest row.

## Hard constraints

- **One `code` tool with a `mode` parameter, not four tools.** §100 measured that
  every tool definition is a permanent per-request bill; four new ones is a standing
  cost on every request in every session. Measure with `golem bench tools` first.
- Lifecycle is the risk: a language server is a long-lived process with an
  initialize handshake. Bound it, and make a hung server a no-op rather than a hang.

## Out of scope

Shipping any language server's bytes. Editor integration. Anything that makes an LSP
required for a Golem install to work.
