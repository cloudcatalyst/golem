## Why this is less work than it looks

The hard part of mTLS in a five-dependency project is minting certificates without
adding a crypto library or shelling out to `openssl`. **That is already solved and
shipped.** `loopback-cert.ts` generates a CA and signs a leaf with hand-encoded
DER, and its tests parse every result back through `node:crypto`'s own
`X509Certificate` so a wrong encoding fails loudly instead of at handshake time.

This task extends that module from "one leaf for 127.0.0.1" to "a client
certificate per paired device", and puts a TLS server in front of the read model.

## What to build

- **`golem device pair|list|revoke`** (name to be settled against the existing
  `golem devices` inference surface, which is a *different* concept — resolve the
  collision rather than inheriting it). Pairing issues a client certificate for one
  device, once, with a visible fingerprint the human can compare on both screens.
- **Server side:** `requestCert: true`, `rejectUnauthorized: true`, Golem's own CA
  as the only anchor. No bearer token anywhere, including query strings — R6.3 is
  explicit.
- **Binding stays loopback by default.** Exposure beyond `127.0.0.1` is an explicit
  opt-in setting, loudly surfaced the way `proxy.bypass_all` is (ADR-0004), and
  `golem status` shows when the surface is reachable off-box.
- **Revocation that works offline.** A revoked fingerprint is refused by the server
  from local state, with no online check and no dependency on the phone
  cooperating. ADR-0006 decides whether anything more is required.
- **The private key never leaves the machine that generated it.** Whichever way
  enrolment transfers material, state which side generates what.

## Out of scope

NAT traversal, the relay, and the account — **this task builds the direct LAN
transport only.** Internet reach is ADR-0006 §3b's relayed mode, and it is R12.8
(client half) plus R12.9 (the service). Keep the two apart deliberately: the mTLS
session this task establishes is the same session the relay later carries
end-to-end, so getting it right *without* a relay in the picture is what makes the
relay blind. Also out: push (R12.6), discovery (mDNS) unless the ADR asks for it.

## Gate

A paired phone on the LAN reaches the read model over mTLS; an unpaired client is
refused at the handshake; a revoked device is refused while offline; the default
binding is unchanged and off-box exposure cannot happen without an explicit,
surfaced setting. Verified against a real phone on the real LAN, not only in tests.
