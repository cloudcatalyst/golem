## Goal

Golem sees every request, so it can reconstruct a conversation's shape — including
where it branched after a rewind. Ship the **recording** plus a `golem session tree`
view. Pi's `/tree`, minus the half Golem cannot do.

## The line that must not be crossed

**Decision 37: a proxy cannot drive Claude Code's interactive TUI.** Auto-resume was
built, reverted, and abandoned unbuilt for exactly this reason. So: record and display;
leave relaunch to `claude -p --resume <session-id>`, which R5.1 already builds a
command for (§65).

## Hard constraints

- **Store no prompt content.** Same standard as `cache-prefix.ts` and the context
  ledger: hashes, counts, timestamps, block types. A conversation tree keyed on
  content hashes is useful; one holding the content is a new liability.
- §99 is a live warning for this task: `cachePrefixFingerprint` groups by a hash of
  `messages[0]` and **that key collides badly** — a real client multiplexes many short
  conversations (subagents, title generation, WebFetch summarisation) through one
  proxy, and ~98% of its verdicts were wrong as a result. A session tree needs a
  *better* identity than the one that already failed. See R8.13.
- Bounded storage; latest-N, not forever.

## Out of scope

Any actuation. Session sharing or gists. Replacing Claude Code's own resume.

## Outcome

New src/session/session-tree.ts module: SessionTreeRecorder (observe->hash->branch/fork detection), persistence (.golem/state/session-tree.json), CLI renderer. Wired into pipeline via sessionRecorder option, persisted from onEvent handler. New golem session CLI command. 10 unit tests.
