## The defect

Found by dogfooding 2026-08-06: stopping the proxy from the VS Code UI leaves
`ANTHROPIC_BASE_URL` pointing at a port nothing is listening on, so every
subsequent Claude Code request fails with connection-refused until the proxy is
restarted or the user hand-edits `.claude/settings.json`.

The path is short and there is no bug in it — the behaviour was simply never
designed:

- `vscode-extension/extension.js` `setProxy(false)` runs `golem proxy stop --dir <cwd>`
  and nothing else.
- `golem proxy stop` (`src/cli/commands/proxy.ts`) writes desired-state `stopped`
  and kills the pid. It never touches `.claude/settings.json`.
- The wiring stays. The port dies. Claude Code keeps dialling it.

## Why "just remove the env var" is not the fix

`ANTHROPIC_BASE_URL` is delivered through `.claude/settings.json` → `"env"`, and
per verification-notes §13 only `permissions` / `hooks` / `apiKeyHelper`
hot-reload — `env` does not. The wiki's own escape hatch says to remove the var
*"and reopen the editor"*. So unwiring on stop cannot rescue the **running**
session; it only fixes the next one. Any design that stops at "delete the key"
still leaves the user staring at a broken editor.

## The shape (Decision 56)

Two mechanisms, deliberately separate, because they answer different questions.

**1. `stop` keeps the port served — a bypass shim.** Tearing down the pipeline
no longer tears down the listener. The port stays bound by a forward-only path,
so Claude Code never sees a dead socket: no settings edit, no window reload,
toggling is instant. `stopped` therefore means *pipeline off*, not *port dead*,
and every surface must say so honestly rather than printing "proxy off".

**The shim still redacts — this is the load-bearing constraint.** The obvious
implementation is `x-golem-bypass` / slider level 0 semantics, and it is wrong:
level 0 is the single sanctioned redaction-off path and CLAUDE.md requires it
never be the default and always be surfaced loudly. A Stop button that silently
routed unredacted prompts upstream would make the redaction-off path reachable
by a click that says nothing about redaction. The shim serves at **level-1
semantics — redaction on, byte-faithful, no compression, no brevity, no
local-answer.** Full passthrough remains reachable only where it already is
(explicit level 0, or the per-request header).

**2. `golem proxy unwire` — the explicit "Golem out of the path" act.** Removes
`ANTHROPIC_BASE_URL` and `ENABLE_TOOL_SEARCH` from `.claude/settings.json` and
tells the user a reload is required. `golem proxy wire` is its inverse.
`src/cli/init.ts` already has the ownership-aware guard this needs
(lines ~531 and ~950 delete the var **only** when it equals Golem's own base URL,
never a foreign gateway's) — reuse it, do not re-derive it. A foreign
`ANTHROPIC_BASE_URL` must be left strictly alone.

## Hard constraints

- **Redaction is not weakened.** The shim runs it. No new path reaches level-0
  semantics without the existing loud surfacing.
- **Never unwire a base URL Golem does not own.** Reuse `init.ts`'s equality
  guard; a foreign gateway's wiring is untouchable.
- `.claude/settings.json` is git-tracked. `unwire`/`wire` churn it by design;
  `stop`/`start` must **not** — that is half the reason the shim exists.
- Cross-platform: argument-array spawn, no shell strings.
- Absence degrades safely: if the shim cannot bind, say so loudly rather than
  leaving the user in the exact silent-dead-port state this task exists to kill.

## Surfaces to update

- `ProxyDesired` (`src/cli/proxy-state.ts`) — `"running" | "stopped"` gains the
  bypass state; the SessionStart auto-start reads it, so its semantics change too.
- `golem proxy status` / `golem status` / the statusline — "proxy off" is no
  longer accurate. §46 hid the `→upstream` segment when the proxy was down; that
  logic needs revisiting now that "down" has two meanings.
- VS Code: the panel button and the `golem.menu` QuickPick gain the unwire action
  alongside start/stop, and the status bar must distinguish bypass from unwired.
- The `Dogfooding Golem` wiki page's "Escape hatch" section documents the manual
  edit — it should point at `golem proxy unwire` instead.

## Out of scope

- Changing what the pipeline does when it *is* running.
- Making `env` hot-reload — not in our gift; Claude Code owns it.
- A general "run Golem at level N without restarting" control. The shim is a
  lifecycle state, not a new dial (Decision 52 owns the dials).

## Verification

Standing bar (`npx tsc --noEmit`, `npm run lint`, `npm run format:check`,
`npx vitest run`) plus:

- A test that `stop` leaves the port accepting connections and a request still
  completes end-to-end through the shim.
- A test that the shim redacts — the whole hard-rule argument above is worthless
  if it is not pinned by a test.
- A test that `unwire` leaves a **foreign** `ANTHROPIC_BASE_URL` untouched.
- Live dogfooding check: stop from the VS Code UI, then send a real Claude Code
  request without reloading the window.
