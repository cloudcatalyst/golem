Splits what `proxy.accounts` fused: an account answers *whose credential*, a target answers *which endpoint + model* and points at an account. **A target holds no secret**, which is why the entire ADR-0003 threat model carries over untouched — the property that kept it an `M`, pinned by a test that a registered target serializes with no key field. The design was decided by reading the config that already existed: this repo's own settings hold **six** accounts, five sharing one OpenRouter credential while naming five different models — the many-targets-one-account case in production, before the registry existed, and the thing a one-target-per-account design would have got wrong. It became the fixture, and it forced `golem target list` to **derive a row from every account**, so an existing config is a usable registry with no edit (an empty table beside six happily-served accounts would have been R8.32's failure mode again). Fail-closed is exact: an unknown id yields no target *and the ids that do exist* — `No substitute was used` — because a registry that quietly swaps a neighbour for a typo'd id sends your **context** somewhere you did not name, which is worse than ADR-0003's mis-billed key. `trust` (`vendor \| local \| lan \| third-party`) is stored and surfaced now, consumed as a redaction floor in R9.3; its default is deliberately pessimistic — loopback Ollama `local`, non-loopback `lan`, `anthropic` `vendor`, **everything else `third-party`** (the most-redacted level), because an omitted field must never buy a target more of your context than it asked for. `credentialEnvForProxy` now resolves **N credentials, not 1**, with no new secret mechanism (`perAccountEnvVar` was already per-account, Decision 47) — and the widened blast radius is recorded at the function that causes it rather than discovered later. Deliberately **inert**: nothing routes on it (R9.2/R9.3 consume it); the only behaviour change is that startup now warns per misconfigured target instead of only the served one. `active_account` → `default_target` shim reads the old key when the new one is unset, so an existing config keeps working untouched. +37 tests (2300→2337). Verified live against the real six-account config. Debrief: `debriefs/2026-08-09-r9.1-target-registry.md`. |
