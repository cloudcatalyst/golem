# R13.11 — `inherit` auth is a proxy concept, and a dispatch that carries one prompt cannot iterate

**Date:** 2026-08-27
**Task:** `docs/plan/tasks/R13.11.md`
**Tags:** #debrief #coder #routing #auth #redaction #honest-observability

## Outcome

Two user-reported symptoms, one report, both reproduced live before any code
changed. Both fixed; the suite is green (3074 passed, 2 skipped, 0 failed).

1. **`coder` returned a bare `401` whenever nothing routed it.** Not a
   misconfiguration — step 4 of the `docs/plan/tasks/R10.8.md` resolution chain had never once
   worked on the commonest configuration Golem has.
2. **A retried draft "looped", re-answering the same question.** Not a model
   defect — the transport was stateless, so every call was turn one.

## What was actually wrong

### `inherit` answers two incompatible questions

`upstream_auth_scheme = "inherit"` is read in two places that want different
things:

| Asker | Question | `inherit` means |
|---|---|---|
| the proxy | how do I forward this request? | forward the client's own credential headers unchanged — correct, and why `defaultAuthScheme("anthropic")` returns it |
| `dispatch()` | how do I authenticate a request **I** am making? | send nothing — there is no client request to forward from |

"Send nothing" is right for a keyless loopback server (`ollama`, `llamacpp`) and a
guaranteed `401` for `api.anthropic.com`. The pre-flight guard read:

```ts
if (mapper === undefined && target.authScheme !== "inherit") throw …
```

— exempting precisely the case that could not work. Every unrouted `coder` call
POSTed with `authHeaders = {}`.

### The gate was green over the wrong thing

R10.8's recorded gate was *"provable from the audit record and `golem status`,
without a local model installed at all."* Both surfaces were correct for the whole
time the feature was broken: `golem status` truthfully printed `coder: anthropic
(target anthropic) — via the harness default upstream; nothing routes coder`, and
the audit line named the right target and route.

**Routing and reporting were right. The request had never succeeded.** And a test
asserted the defect as intent — *"still dispatches with no credential when the
scheme is inherit"*, expecting an Anthropic request to carry no `x-api-key` at
all — so it passed throughout.

The lesson is the transferable part: **a gate phrased over observability surfaces
can be fully green while the behaviour those surfaces describe has never once
happened.** When a step's whole purpose is "reach a destination", the gate has to
reach it. This is the dishonest-signal class the project exists to close.

### The stored key could never have helped

`makeAuthMapper("inherit", apiKey)` returns `undefined` **whatever key is
passed** — the scheme is tested before the key. So `golem gateway login
anthropic` stored a credential, `golem target list` truthfully said "key set",
and `coder` still went out bare. Same family as R10.8's finding that the MCP
server inherits no `GOLEM_UPSTREAM_API_KEY__*` env at all: the key existed, the
request did not carry it.

### The "looping model" was a stateless transport

`DispatchRequest` carried a single `prompt` and dispatch sent
`messages: [{role: "user", content: prompt}]` — no history, no system line. Asked
to retry, `openrouter:qwen/qwen3.7-flash` said:

> "I'd be glad to fix it, but I don't have visibility into your previous attempt
> or the failing test."

Re-calling with near-identical task text necessarily re-derives a near-identical
answer. **When an LLM appears to repeat itself across tool calls, check the
transport before the model.**

## What shipped

- **`originationAuthScheme(provider)`** — a genuinely different question from
  `defaultAuthScheme`, deliberately *not* derived from it (that one returns
  `inherit` for four providers because it answers the proxy's question).
  `anthropic`/`custom` → `x-api-key`, `azure-foundry` → `api-key`,
  `openrouter`/`openai` → `bearer`; `undefined` only where no header would do it
  (keyless `ollama`/`llamacpp`, Gemini's `?key=`, `claude-cli` authenticating as
  itself).
- **`NoDrafterConfiguredError`** — raised on the harness step only, and surfaced
  by `coder` as an **ordinary, non-error** result that hands the work back inline.
  A decline is not a failure: nothing is misconfigured, there is simply no
  drafter. Steps 1–3 still fail closed with the target named, because those were
  configured deliberately.
- **`DispatchRequest.attempts` / `.system`** — rendered by
  `buildDispatchMessages` into `system → user → (assistant, user)*`, so the last
  turn is always the user's. Exposed as the `coder` tool's `previous_attempts`.
  With no attempts the conversation is byte-identical to the single user turn it
  always was.
- **`redactReversibleTexts`** — one `PlaceholderTable` shared across every turn,
  with `redactReversibleText` reimplemented in terms of it so the two cannot
  drift. See the redaction note below; this was not a tidiness change.
- **Transport fixes** — `REMOTE_MAX_TOKENS = 4096` shared (the OpenAI-shaped path
  pinned nothing, so the ceiling differed per gateway and a truncation read as a
  restatement); `reasoning_content`/`reasoning` read as a *fallback*, never a
  preference; Anthropic system turns hoisted to the top-level `system` field,
  which the Messages API requires.
- **`RefineOutcome.revisedBy`** — refinement always runs on the local tiered
  model, including for a remote draft, and the reply used to report the *remote*
  model's name. A local 7B rewrite was attributed to `qwen3.7-flash`.
- **Honesty surfaces** — the `coder` tool description stopped claiming "local
  tiered Ollama inference", "Nothing leaves the machine" and "omit for the local
  model", all false since R10.8 wired the dispatcher unconditionally; it now says
  where it runs is a routing decision, that it may decline, and that each call is
  a fresh conversation. `golem status` stops implying the harness step is an
  assured destination. `golem target list`'s keyless exemption gained a note that
  it describes the proxy path only.

## Key lessons

1. **A config value that two subsystems read may be answering two different
   questions.** `inherit` was sound for the proxy and unusable for the
   dispatcher, and the shared name hid that for two releases. When a second
   caller appears, ask what the value means *to that caller* rather than reusing
   the resolver.
2. **Gate on the behaviour, not on the reporting of it.** Every observability
   surface was truthful while the feature was 100% broken. See
   the dishonest-signal class.
3. **"The model is looping" is a hypothesis about the transport too.** Statelessness
   produces output indistinguishable from a model that cannot follow instructions.
4. **Multi-string redaction must share one placeholder table.** Per-message tables
   give the same secret different numbers in different turns, and one `restore`
   map can then only put one of them back — the failure mode is **silent
   corruption of the reply**, not a leak. `redactRequestBody` already shared a
   table across a whole request body for exactly this reason. See [[Redaction Stage]].
5. **Widening a request shape widens the egress boundary.** `attempts` carries
   ordinary source code; redacting only `prompt` would have punched a hole
   straight through the one boundary `dispatch()` exists to enforce. The fix
   belonged in the same change, not a follow-up.
6. **A test can encode a defect as intent.** *"still dispatches with no credential
   when the scheme is inherit"* was protecting the bug. A test whose name asserts
   an absent credential is worth re-reading as a question rather than a rule.

## Deliberately not done

- **`golem status` does not read the credential store** to predict the decline.
  Status feeds the per-turn statusline, so that would add a DPAPI-backed lookup to
  every render. It states the dependency and points at `golem target list`.
  Predicting either outcome without checking would be the dishonest-signal class
  this project exists to close.
- **No fallback to the local Ollama model.** Considered and rejected by the user:
  R10.8's "local is a destination, never a fallback" rule stands, and the reporting
  user's own expectation was that the session's model does the work.
- **The 4 pre-existing `npm run lint` errors** in the merged R13.4-me mTLS files
  (`devices-auth.ts`, `mount-mtls.ts`, `device-catalog.ts`,
  `device-credentials.ts`, `user-factor.ts`) were left alone — another
  workstream's code, and unrelated to this one. Proved pre-existing by stashing
  this branch and re-running on `main`: the diagnostic set is identical.
