# R11.4 — what the retirement left behind

Shipped 2026-08-21, a day after R11.1 retired the slider (see
[[Compression Levels]] for what replaced it). Three leftovers,
all found the same way: by deploying the release and reading what it printed.

## Outcome

- Four user-facing strings that still said *slider* now name `compression.level`
  — including `golem config get`'s example key, which pointed at a setting that
  no longer exists.
- `classifyLevelTool` and its `mcp__golem__level` branch are gone. The tool went
  with the slider, so the branch was unreachable and its tests passed vacuously.
- `pruneRetiredSkills` makes a comment true that had been false since R11.1:
  `golem init` now actually removes a `/golem/<cmd>` skill Golem no longer ships.

## Key lessons

**Deploy and read the output.** The whole task started with `golem init` printing
"set compression.headroom_sidecar=true and slider ≥3" — a hint naming the control
the previous release had removed. No test asserted that string, and no reviewer
would have looked for it. Running the thing you just shipped and reading every
line it prints is the cheapest review available.

**A comment that describes behaviour is a claim, and claims rot.**
`BASICS_SKILLS` said "`golem init` prunes a managed skill that is no longer in
this table". `installSkills` iterates the table — it cannot see what left it. The
comment was written in the same commit that retired the skill, describing
machinery nobody had built. When a comment asserts behaviour, either a test pins
it or it is a wish.

**Dead code passes its tests.** Five assertions covered `classifyLevelTool`, all
green, all meaningless once the tool was gone. Coverage says nothing about
whether the code is reachable. Worth checking, when a feature is retired, what
still *classifies* or *validates* it.

**Deleting is the risky half of a table-driven installer.** Writing files from a
table is safe; removing what fell out of it can delete the user's work. The rule
that made it safe was already there — R9.5's provenance record, which
distinguishes "stale, Golem wrote it" from "edited, the user owns it". Reusing
that record cost one small helper (`isUnmodifiedManaged`) and made the prune
conservative by construction: a skill Golem has no record of writing is never
touched. The install side and the prune side now share one ownership rule.

**Retirement is not one commit.** R11.1 removed the setting, the CLI command, the
MCP tool, the telemetry and the status blocks — thoroughly, by any review. The
residue was in a hint string, an autonomy classifier and a seeded skill file:
three places nothing about "compression" would grep. A retirement is done when
the *installed project* stops mentioning the thing, not when the source does.
