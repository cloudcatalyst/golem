# R13.1 — Spike: hosted multi-turn claude CLI viability

Client `2.1.235`. Dated verification-notes **§142**. ADR-0007 §3a updated.

## Outcome

The unverified assumption behind ADR-0007 was confirmed: the `claude` CLI can be driven as a hosted, multi-turn session via `-p --input-format stream-json --output-format stream-json`. Eight items measured, six OBSERVED, one partial/one UNESTABLISHED. Recommendation: keep the `claude` CLI as §3a's runner. Neither fallback is justified.

## Key lessons

- Item 5 and 6 answered in the affirmative: Golem's own hooks fire in a hosted session and permission `ask` resolves to a synchronous refusal because headless/hosted mode structurally cannot open a dialog. This means ADR-0007 invariant 2 is enforceable without Golem writing its own agent loop.
- Windows SIGINT gap on item 3: `child.kill("SIGINT")` does not interrupt a running turn — only process-kill works. UNESTABLISHED on POSIX whether documented SIGINT behaviour holds.
- Usage-limit park is architecturally orthogonal to a spawned process (item 8). API error surface, not Golem snooze.
- Per-turn cost at Opus-5 pricing: $0.21-$0.51 per trivial turn when cold-cache (~44k cache_creation_input_tokens), drops with warm cache. Idle time costs nothing beyond OS process.
