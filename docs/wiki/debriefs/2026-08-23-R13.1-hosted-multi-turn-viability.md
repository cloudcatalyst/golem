# R13.1 -- Spike: hosted multi-turn claude CLI viability

Client `2.1.235`. Dated verification-notes **§142**. (A second, independently-written R13.1 close-out — [[Debrief: R13.1 Claude CLI hosted session spike]] — reports the opposite verdict on multi-turn stdin and is marked contradicted pending a human call.) ADR-0007 section 3a updated.

## Outcome

The unverified assumption behind ADR-0007 was confirmed: the `claude` CLI can be driven as a hosted, multi-turn session via `-p --input-format stream-json --output-format stream-json`. Eight items measured, six OBSERVED, one partial plus one UNESTABLISHED. Recommendation: keep the `claude` CLI as section 3a runner. Neither fallback is justified.

## Key lessons

- Items 5 and 6 answered affirmatively: Golem hooks fire in a hosted session; permission `ask` resolves to synchronous refusal because headless mode cannot open a dialog. ADR-0007 invariant 2 enforceable without writing own agent loop.
- Windows SIGINT gap: `child.kill("SIGINT")` does not interrupt a running turn. Process-kill only. POSIX behaviour UNESTABLISHED.
- Usage-limit park architecturally orthogonal to spawned process. API error surface, not Golem snooze.
- Per-turn cost at Opus-5: $0.21-$0.51 per trivial turn cold-cache (~44k cache_creation_input_tokens); warm cache drops significantly. Idle costs nothing beyond OS process.
