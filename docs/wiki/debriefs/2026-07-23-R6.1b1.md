First slice of case (b) — the generic, translating half of the provider work
the user actually wants (run Claude Code against OpenAI/ChatGPT and Ollama
local/LAN). Sliced b1→b4; this is **b1: non-streaming Anthropic↔OpenAI
translation**, chosen because it establishes the sensitive response-transform
seam on the simplest path and is live-testable against a local Ollama.

## What landed

- **`src/providers/openai-translate.ts`** — pure `anthropicToOpenAIChat`
  (system + messages, text content flattened, params, `stream` forced off, model
  overridable) and `openAIChatToAnthropic` (completion → Anthropic message;
  `finish_reason`→`stop_reason`; `usage` mapped; reports the **real serving
  model**, never a `claude-*` name). zod validates the boundary — legitimate
  here because this provider parses/reserializes (it is NOT the byte-faithful
  path the "no zod on payloads" rule protects).
- **`translateUpstream` proxy seam** (`ProxyServerOptions` → `server.ts`) — the
  ONLY code path that parses a response body: translate the request, POST to the
  provider's `/chat/completions`, **buffer** the response, translate it to
  Anthropic JSON, write it. Opt-in; when absent (Anthropic) the response stays a
  raw byte pipe (byte-faithful hard rule intact). Upstream errors pass through
  unchanged; a translation failure is a clean 400/502 proxy error, not a
  mismatched forward.
- **Providers `openai` + `ollama`** (`isTranslatingProvider`); auth defaults
  (`openai`→bearer, `ollama`→none); `upstreamAssumesCaching` now returns **false**
  for them (genuinely non-caching — the lossy semantic stage may pay there);
  `upstreamChatCompletionsPath` derives the POST path from the base URL.
- **`proxy.upstream_model`** config — Claude Code sends a `claude-*` model the
  backend lacks, so the model is overridden (e.g. `qwen2.5-coder:7b`). The proxy
  warns at startup if a translating provider has no model set.

## Live verification (the payoff)

Unlike case (a), b1 needs no cloud credential — ran a real `GolemProxy` against
`http://localhost:11434/v1` + `qwen2.5-coder:7b`: `POST /v1/messages` (Anthropic
body) → HTTP 200 with a well-formed Anthropic message
(`content:[{type:text,text:"PONG"}]`, `model:"qwen2.5-coder:7b"`, real
`usage`). verification-notes §74. So the seam works end-to-end on a real backend,
not just fakes.

## Scope / interfaces

No frozen `src/interfaces/` change. Proxy transport gains one additive optional
(`translateUpstream`). +12 tests (translation unit; proxy-seam integration with
a fake OpenAI upstream incl. error-passthrough + untranslatable-request 400);
1196 green; tsc/biome/format clean. The Anthropic passthrough is unchanged (no
translator) — its recorded-shape tests still pass.

## Deliberate b1 limits → next slices

- **Non-streaming only.** `stream` is forced off, so a real Claude Code client
  (always `stream:true`) is not yet served — that is **b2** (Anthropic SSE ↔
  OpenAI deltas), the next and larger slice.
- **Text only.** tool_use/tool_result are flattened to text best-effort;
  faithful tool-use mapping is **b3** (load-bearing for coding agents).
- **b4:** OpenAI + Gemini cloud (OpenAI reuses this translator + a `bearer` key
  from `GOLEM_UPSTREAM_API_KEY`; Gemini needs its own `generateContent` schema).

## Honest caveat

Running Claude Code against a local model is quality- and tool-use-sensitive
(local models are weaker and format tool calls differently) — an explicit,
labelled upstream swap, not a drop-in Claude. The dogfooded proxy was rebuilt
but not restarted (default `anthropic` provider unchanged).
