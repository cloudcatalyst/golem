# R2.4 — expand↔Headroom-CCR gap closed via hash backfill

Full technical detail is in verification-notes §61; this page records the
durable conclusion: **the gap §38 flagged during R2.5's dogfooding ("if
Headroom elides something into its own CCR, `expand` can't retrieve it") is
now closed for every hash convention the pinned Headroom package uses.**

## Root cause

Headroom's elision transforms (`read_lifecycle`, `log_compressor`,
`search_compressor`, `diff_compressor`, SmartCrusher's Rust path) each stamp
a `hash=<hex>` marker onto the content they replace. That hash is always a
**reproducible truncated digest of the pre-elision content** — SHA-256[:24]
by default, SHA-256[:12] for SmartCrusher's Rust path, MD5[:24] for
`log_compressor` — but it's a key into Headroom's own in-process Python
store, never shared with Golem's TS `CcrStore`. So `expand <hash>` threw
`UnknownRefError` for anything Headroom (rather than Golem's own lossless
stage) had elided.

Confirmed against the pinned `headroom-ai==0.30.0` source directly (not
docs), including the exact block-level replacement mechanics: Anthropic-format
elision replaces only the matched `tool_result` block's `content` string
in place (array length/order preserved); OpenAI-format `role:"tool"` messages
have their own top-level `content` string replaced.

## The fix

`backfillHeadroomCcrRefs` (`src/compression/headroom-ccr-bridge.ts`) diffs
the semantic stage's pre/post message arrays. For each block whose content
changed and whose new content carries a `hash=<hex>` marker, it verifies the
hash is a prefix of SHA-256 **or** MD5 of the OLD content — covering every
convention observed above — and backfills the OLD content into Golem's own
`CcrStore` under that exact hash. No marker-text rewriting: the marker
Headroom already emits resolves through the existing `expand` path
unchanged, because `expand`'s `ref_id` and `CcrStore`'s key are both
unconstrained strings (Golem's own `CCR_MARKER_RE` turned out to be unused
by any code path — only doc comments referenced it).

Wired as a new, non-frozen `GolemPipelineOptions.headroomCcrStore` option
(no frozen-interface change, no contract-tests-first requirement) and
constructed in `src/cli/proxy-runtime.ts` pointed at the same `.golem/ccr`
directory the proxy and the MCP server's `expand` already share — so a
backfilled ref is immediately visible to a later `expand` call. Fails open
throughout.

## Verified

`tsc --noEmit` clean, `biome check .` clean repo-wide, full `vitest run` —
79 files / 748 tests, all green (18 new/extended for this fix, covering all
four hash conventions, non-derived-hash rejection, idempotency, and
fail-open behavior at both the bridge-unit and pipeline-integration level).
