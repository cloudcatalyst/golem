# R10.12/R10.13 — a shipped decision fell out of a rewrite, and nothing noticed for three days

**Date:** 2026-08-14
**Tasks:** R10.12 (done), R10.13 (done)
**Outcome:** after `golem proxy stop` the port answers **401 from upstream** instead of connection-refused — the whole of R8.31's defect, closed again. `golem status` now catches a daemon older than the last `npm run build`.

Related: [[R8.31 — stopping the proxy meant a dead port, and unwiring alone could not fix it]].

## R10.12 — the regression, and where the brief was wrong

R8.31 built Decision 56's bypass shim on 2026-08-06 and its debrief stands. By
2026-08-13 the whole thing was gone: no `ProxyDesired`, no
`src/cli/proxy-state.ts`, no shim — and, worse than the brief recorded, **no
`golem proxy stop` command at all**. The VS Code Stop button shells out to
`golem proxy stop`, so the reporter's original gesture had gone from "leaves a
dead port" to "unknown command".

The brief guessed R10.1, the first-pancake rewrite, and asked for that to be
confirmed from history rather than assumed. It was wrong, and the check was
worth doing:

```
git log --diff-filter=D -- src/cli/proxy-state.ts
1992445  R9.23: rename ext to pkg, fix Caveman detection, add pkg install
```

**1992445 (2026-08-11)**, two days BEFORE R10.1 (13a8f19, 2026-08-13). The same
commit rewrote `src/cli/commands/proxy.ts` by 365 lines and left behind the
comment that explains the whole thing:

```ts
// R9.23: if the URL is in settings, the daemon should be alive.
// If it's not, restart it — no separate state file needed.
```

That is the moment the decision was overruled — not by argument, but by a
simplification that looked locally correct. "No separate state file needed" is
true if the only question is *is a daemon alive*. Decision 56 exists because
that is not the only question.

So R10.1's debrief should NOT gain the line the brief predicted. The lesson
belongs to R9.23: a rename-and-simplify batch is exactly where a shipped
behaviour disappears, because nothing about deleting a state file looks like a
policy change.

## What actually caught it

Not a test, and not a user. R10.11's `STATUS_FIELDS_READ` contract asked why
`vscode-extension/render.js` reads `st.proxy.bypass` when nothing emits it:

```js
{ path: ["proxy", "bypass"], unemitted: "R10.12" },
```

A field the UI reads and no producer writes was recorded as a tripwire rather
than deleted, and that record is what preserved the trail back to the missing
feature. Flipping it to `required: false` was the last step of the fix.

## Restoring it

Recovered from `1992445^` rather than redesigned — the code was correct, and
re-deriving it would have risked getting Decision 56(c) subtly wrong. The
load-bearing constraint:

> The natural way to build a passthrough is the existing `x-golem-bypass` /
> level-0 path, and it is **rejected**: that path forwards untouched, i.e. with
> redaction off.

Two tests hold that line, and the **control** is the important one: the shim
redacts even when the slider store says level 0, AND a level-0 non-shim build
demonstrably forwards the secret. Without the second, the first could pass
because the contrast vanished rather than because the shim held.

Also closed the reporting loop the shim needs: `collectStatus` emits
`proxy.bypass`, `collectSessionStateReport` **assigns** it (it had been declared
and zod-validated but never written), and the SessionStart hook honours the
recorded intent instead of unconditionally starting the full pipeline.

## Two things the live check found that the tests did not

**1. Every restored message named a flag that no longer exists.** The recovered
text said `golem proxy start --detach`; R9.23 had removed `--detach` from
`start`. Running it produced `error: unknown option '--detach'`. A recovery
instruction that errors is worse than none, and only executing it revealed that
— all four messages now say `golem proxy restart`.

**2. `restart` did not record intent.** Stop into bypass, then restart, and the
next SessionStart would helpfully bring the shim back. Found by reading the
state file after a live round trip.

## R10.13 — staleness that can see a rebuild

`stale: info.version !== currentVersion` is correct across a release and blind
within one. Every local `npm run build` leaves `VERSION` untouched, so a daemon
started before the build kept reporting as current — which is how R9.23's dedup
work was debugged for an hour while not running.

Added a cheap code stamp: `mtimeMs + size` of the daemon's entry script, hashed.
Deliberately not a hash of all of `dist/` — `proxyStatus` is on `golem status`,
the status line and the VS Code poll, and R10.10 measured that path. **What it
does not catch:** a surgical single-file copy into `dist/` that leaves the entry
script untouched. `tsc` rewrites every emitted file, so the normal loop is
covered.

Precedence is version first, fingerprint second, and an unknown fingerprint on
either side falls back rather than guessing — an unknown build is not evidence of
a stale one.

The live check caught a wording bug the unit tests could not: with versions
equal, the existing message rendered **"running build 0.22.0, not 0.22.0"**. The
renderer had assumed staleness always meant a version mismatch. It now
distinguishes the two causes.

## Lesson

R10.12's real subject is not the shim. It is that a decision with a spec entry, a
debrief, tests and a working implementation was removed by a batch that was not
about it at all, and the only thing that noticed was a contract test recording an
oddity in a UI file. **Write down the tripwire when you find a field nobody
emits** — deleting it as dead code would have erased the only evidence.
