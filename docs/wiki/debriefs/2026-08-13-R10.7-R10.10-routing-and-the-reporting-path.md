# R10.7–R10.10 — the default that was never a default, and a status bar lying about a healthy proxy

Related: [[R10.1 (part 1) — the first pancake was not burnt, it was just big]],
[[The deploy that broke the session, and the three bugs it exposed]]

**Date:** 2026-08-13
**Tasks:** R10.7, R10.8, R10.10 (done); R10.9, R10.11 (queued)

## R10.7 — the direction of a fix was the whole judgement

Tier P_MIN was the only one whose text and code embedders disagreed on vector
width (bge-m3/1024, nomic-embed-text/768), and both feed one collection. Ingest
embeds each kind with its own model; the driver resets the collection whenever
the incoming width changes. So a repo with prose and code thrashed, each kind
wiping the other.

Two models could have been paired. **Which one mattered more than the pairing.**
`textEmbed` decides the index signature AND every query (queries always embed
with the text model), so lowering it to 768 would have invalidated every existing
P_MIN index and cost query quality. Raising `codeEmbed` to 1024 only re-embeds
vectors that were already being reset away, and forces no rebuild.

The guard fixes the class, not the instance: every tier's embedders must share a
width, with the tier list derived from the enum so a future tier is covered
automatically, plus an anti-vacuity check — `embedDimFor` returns null for an
unknown model, and `null === null` would let a mismatched pair of unrecognised
models pass.

## R10.8 — the setting that existed to name a default was never read

`coder` resolved a target as explicit → `worker_targets` → **local model**.
`inference.default_target` was never consulted. So local was the implicit default
for every worker without an explicit mapping, and the knob that exists to say
otherwise did nothing.

**Two gates would have defeated the fix, and both only appeared once it was
built:**

1. The synthetic default target carries `proxy.upstream_model`, which is optional
   and unset on the commonest config there is — byte-faithful Anthropic forwards
   the client's own id. So the new final step hit a pre-existing "declares no
   model" refusal, and **the fresh-project case the task exists for would have
   errored.**
2. `mcp-serve` only wired the dispatcher when more than one target existed, which
   would have skipped it entirely for a project holding just the synthetic
   default — restoring implicit-local for exactly the configuration the gate
   named.

Neither was visible from reading the code. Both were found by building the thing
and asking what the *default* project does.

**And a third would have made it silently inert:** `mcp-serve` passed raw
`settings.proxy`, so `inference.default_target` was never merged in and the
resolver would have read the deprecated `proxy.default_target`. This is the same
R9.23 half-migration that produced six open-coded merges elsewhere; this call
site was missed **precisely because the dispatcher never read the key at all**,
so nothing surfaced it. The fix extracted the construction into a named function
— the bug was invisible *because* it lived in an inline literal that type-checks
structurally.

**Lesson: a setting nothing reads cannot drift loudly.** Grep for who READS a
renamed key, not just who writes it.

`llamacpp` landed as a first-class provider in the same change. The judgement
worth keeping: **trust is derived, not declared.** The same `llama-server` binary
is `local` on loopback and `lan` on `gpubox.lan`, so hardcoding "llamacpp =
local" would hand an unredacted prompt to a box across the room on the strength
of a config string. And `isKeylessProvider` deliberately excludes `gemini`
despite it also defaulting to `inherit` — gemini genuinely needs a key, so
keying off `inherit` would have silenced the warning that matters most.

## R10.10 — the bar was lying about the proxy, not reporting it

Reported symptom: the VS Code status bar flips online/offline at random while the
proxy is healthy.

The proxy was never involved. `extension.js` polls four CLI invocations in
parallel, each with an 8s timeout that **resolves to null**, and null renders as
offline.

The measurement is the part worth repeating, because it moved the fix:

| | ms |
|---|---|
| bare `node -e 1` | 177 |
| `node dist/cli/main.js --version` | 1429 |
| `golem --version` via the npm shim | 1894 – 3486 |
| loading `program.js` alone | **2146** |
| loading `status.js` alone | **526** |

So a JSON dump was paying ~1.6s for a command registry it never touches, and the
shim added another 0.5–2s of *variance* — which is what actually carries a call
over a fixed timeout. Fast-pathing `status --json` took it to ~1350ms.

**`stats --json` was deliberately left slower.** Its plain path branches on
telemetry aggregation and a `hasRequests` fallback, and duplicating that is
exactly the drift the fast path's "behaviourally identical" rule exists to
prevent. It is also not the call that matters: a null `stats` blanks a savings
figure, while a null `status` is what renders the bar offline. **Fixing the
slowest thing is not the same as fixing the thing that breaks.**

## The finding under all of it: the extension had no test that runs

Chasing the flapping turned up that `vscode-extension/` had never been updated
for R9.23. It called `golem account list` in five places — removed, so the
"Switch upstream" picker was empty and the switch a no-op. It read
`local_model.coder_model`, a field the CLI never emitted, so the status bar
showed a bare "local" instead of the model id.

`vscode-extension/render.test.js` would have caught all of it. It is run by
neither `npm test` (vitest includes only `tests/**/*.test.ts`) nor CI, and was
already 4 tests red on main. Its own assertions have rotted too — they check
`m.localCoderEnabled` where the model returns `coderEnabled`, so they would fail
against a *correct* implementation.

**A test suite nobody runs is worse than no suite: it looks like coverage.** And
the earlier 55-string `golem account` sweep missed these because it grepped `src`
and `tests` — `vscode-extension/` is plain JS outside both. When a rename sweep
is scoped by directory, the directories excluded are exactly where it will
survive. Queued as R10.11.
