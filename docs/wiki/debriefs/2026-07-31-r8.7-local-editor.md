# R8.7 — the local editor model

**Verdict: shipped, off by default, in one format only.** `coder` gains
`mode: "edit"`: the frontier model writes a ~20-token instruction, the **local**
model rewrites one small file, and **Golem validates the result** before anything
is written. The gate approved it — and rejected two of the three designs it was
asked to compare.

## The harness came first, and it changed the design

R8.7's gate said *harness before code, non-negotiable*, with the **edit format as a
measured variable** the way Aider treats it. `golem bench edit` was built first, its
bar fixed before the first run (ship at semantic ≥ 80% **and** apply ≥ 70%), and it
then contradicted the task document's own assumption that search/replace was the
format to build.

Measured on 12 hand-labelled cases with `qwen2.5-coder:7b` (§110 has the full table):

| format | in-format | apply | **semantic** |
|---|--:|--:|--:|
| `search-replace` | 50.0% | 50.0% | **33.3%** |
| `udiff` | 100% | 50.0% | **33.3%** |
| **`whole`** | 100% | **100%** | **91.7%** |

The two diff formats fail for *different* reasons, and separating them was worth more
than the verdict:

- **`search-replace`: half the replies were not in the format at all.** Asked for
  `<<<<<<< SEARCH` blocks, a 7B model returns the whole rewritten file anyway. A
  compliance failure, not an editing failure.
- **`udiff`: perfect compliance, half the hunks still do not apply.** The model will
  not reproduce existing lines byte for byte — which is precisely what *both* diff
  formats require. The trailing-whitespace leniency rescued **zero** of them, so this
  is paraphrasing, not whitespace.

Whole-file wins because there is nothing to copy. That is also its risk, and it is why
validation grew a fourth check.

## Validation is Golem's, and it now has four layers

1. **Unique match** — a search text that occurs zero times is `no-match`, twice is
   `ambiguous`. Never "use the first one": that is how an applier edits the wrong
   function.
2. **The result differs** — an edit that applies and changes nothing is `no-change`, a
   failure. Counting it as success is how a harness measures 100% and means nothing.
3. **Definition-loss guard** *(new here)* — the tree-sitter definition list before and
   after must not lose a name. This catches the whole-file failure a parse check
   cannot see: a rewrite that parses perfectly and has quietly dropped an unrelated
   function. On the measured cases it rejected nothing; its value is entirely on the
   large files the fixtures do not contain.
4. **It still parses** — via the tree-sitter probe, whose **three-way** return is
   load-bearing: `true` broken, `false` clean, `null` **unavailable**. "Could not
   check" is never reported as clean, and `apply` is refused when the syntax check did
   not run.

Nothing writes on a failed validation, ever. There is no fallback that writes the
model's raw text — the path R8.7's hard constraints forbid.

## The cost is opt-in, and provably zero when off

Three schema properties (`mode`, `file`, `apply`) plus their prose cost **+313
definition tokens on every request**: `coder` goes 614 → 927. That is the shape §100
rejected R8.S1 for, so the mode is behind `inference.local_editor_enabled`
(default **false**), and with it off `coder`'s definition is **byte-identical** to what
R8.6 shipped — measured, not asserted, via the new `golem bench tools --editor` flag
(the `--lsp` precedent from §109).

The arithmetic on the fixtures is honest and unflattering: ~21 instruction tokens
against ~51 for the hand-written edit is a ~30-token saving per edit, which does not
repay +313 per request. The saving scales with edit size and the schema cost does not,
so the claim is **conditional** — it pays on files big enough to matter. Where the
crossover sits is unmeasured, which is why `MAX_EDIT_LINES = 200` is described as a
guard rather than a bound.

## Propose by default

The default outcome of an edit call is **a diff and an unchanged file**. Writing needs
`apply: true`, a second explicit act — `mcp__golem__coder` is classified as a `write`
tool, so ADR-0002's gate sees it like any other write. Golem renders the diff itself
(a bounded LCS, no dependency) because the whole token argument is that reviewing an
edit is cheap *input* while writing one is expensive *output*; a review artefact that
was the whole file would erase the point.

## Two instrument findings

- **`--repeats` cannot sharpen this harness.** At `temperature: 0` every arm reproduced
  identical per-case outcomes over 2 and 3 passes. The report now says repeats buy
  reproducibility, not statistical power — only more cases move the ±8.3-point
  resolution.
- **An aggregate would have hidden the real result.** "Diff formats apply about half the
  time" is true and useless. The compliance/apply split is what identified one failure as
  a prompt problem and the other as a property of the model.

## How to turn it on

```
golem config set inference.local_editor_enabled true
# then reconnect the golem MCP server in Claude Code
golem bench edit                 # re-run the gate on your own machine/model
golem bench tools --editor       # what it costs you per request
```

A different local model may sit anywhere on that table — the gate is a command, not a
claim, so re-run it rather than trusting this page's numbers for a model that is not
`qwen2.5-coder:7b`.

## Still open

Whether an agent handed a validated local editor actually *stops* writing edits itself.
The same displacement question [[Repo Map]] and the LSP bridge left open, and the same
answer: it needs live traffic, not another bench.
