# R9.7 — the cache-serve red dot

The report: *"a webfetch which is serviced by golem works, but shows a red dot in
claude code."* Accurate. Golem's **best** path — content served from cache, network
fetch skipped, WebFetch's summarizer LLM call avoided — is the one that looks broken.

## Outcome

**The escape route was tested and declined.** The red dot stays, now with the reason
recorded in writing (which is what the task's gate asked for). What shipped is the
wording fix: both serve paths open `NOT AN ERROR —` and explain that Claude Code
renders hook-served content as a *denied* tool call.

## Why it renders red

Serving content without running the tool has exactly one expression at PreToolUse:
`permissionDecision: "deny"` with the content in `permissionDecisionReason`. Claude
Code draws a denied call as an error. Re-verified against live docs in verification-notes §115:
there is still no `updatedToolOutput` (PostToolUse only) and no synthetic-result
field. This is mechanism, not defect.

## Key lessons

**1. The untested escape half-works, and the working half is the useless one.**
`updatedInput` + `allow` really does rewrite the tool's input: a probe rewrote
`example.com/?r97-probe` → RFC 2606 and the call came back **green**. Confirmed, and
worth knowing for future work. But it is only useful if it can point somewhere Golem
serves from, and it cannot:

- `http://127.0.0.1:<port>` → **`WRONG_VERSION_NUMBER`**: WebFetch upgrades http→https
  and speaks TLS at a plain-HTTP server. Its own docs say so; nothing reached the HTTP layer.
- `https://127.0.0.1:<port>` self-signed → **`self signed certificate`**. It *connects*
  (no private-IP blocklist), the cert is the sole objection.
- `file://` and `data:` → **`Invalid URL`**.

**2. "Verify the premise first" earned its place in the brief.** The premise was two
claims wearing one coat — *can we rewrite the URL* (yes) and *can we serve the rewritten
URL* (no). Testing four URL schemes cost four tool calls and killed a design that would
otherwise have been half-built before the TLS handshake failed.

**3. The green dot needs a trusted cert — but NOT a CA (corrected).** This lesson as
first written said the price was a Golem CA in Claude Code's process-wide trust. That was
**wrong**, and verification-notes §121 withdraws it: a self-signed **`CA:FALSE` leaf** in
`NODE_EXTRA_CA_CERTS` validates fine (measured), appends to rather than replaces the
public store, and cannot sign for any other host — so there is no MITM blast radius. The
first test was misleading because `openssl req -x509` emits `CA:TRUE` by default. What
actually blocks a *default* install is scope: cloud sessions ignore the variable from a
settings `env` block, and Desktop app-managed sessions ignore a repository's settings
files — exactly where `golem init` writes. And a rewrite that lands in such a session
turns a cosmetic red dot into a genuinely failed fetch.

**4. Both remaining designs lose on their own merits anyway, which is what makes this a
decision and not a blocker.** Measured: the WebFetch summarizer call *does* transit the
proxy, single-turn and **uncached** — `https://example.org/` (~1.2 KB) billed **551 input
/ 9 output**, zero cache read or creation. Scaled to the 248,890-char hooks doc that
started this, that is **~62k input tokens per fetch at 0% cache hit**, against a session
whose real hit rate is 98.4% (verification-notes §93). And the proxy short-circuit that would fix those
tokens does it by putting the *raw page* in context whole — `MAX_SERVED_CHARS` (8,000)
exists precisely to prevent that. A 62k-token context blow-up is a worse bug than a red dot.

**5. A negative result still ships something.** The tick-inside-an-error-box was doing
real damage: it is why this got reported as broken rather than as ugly. Cost of the fix:
two string constants and a test.

## What shipped

- `src/hooks/web-fetch.ts` — `NOT_AN_ERROR` / `RED_DOT_NOTE` framing on both serve paths
  (cached hit and self-fetched raw page); module docstring records the decision so the
  next reader does not re-derive it.
- `tests/integration/hooks/web-fetch.test.ts` — pins the framing against regression.
- `docs/plan/verification-notes.md` §120 — the measurements and the declined design.

## Revisit if

Claude Code gains a PreToolUse output-substitution field. Then this is a one-line change.
The loopback route is filed as an **opt-in** candidate (R9.12) on the strength of §121.
