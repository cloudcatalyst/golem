# R1.1 — usage-telemetry A/B infrastructure + gzip sniffer fix

Batch gate task: measure real billed `usage` (not gross forwarded tokens) at
slider level 1 vs level 3 from live Claude Code traffic. See
[[R1.1 — net-of-cache billed-usage A/B]] for the finding; this page is the
what-changed record.

## What changed

- `src/proxy/usage-sniffer.ts` (new): `UsageSniffer`, a byte-faithful
  `Transform` that opportunistically extracts the Anthropic `usage` block from
  non-streaming JSON and SSE responses, fail-open throughout. Handles
  `content-encoding: gzip`/`br`/`deflate` via a side `zlib` decompression
  stream (decompresses a copy for sniffing only; forwarded bytes are always
  the original, untouched chunk) — added after discovering real upstream
  traffic is gzip-encoded and the first version silently sniffed nothing on
  any real request.
- `src/proxy/server.ts`: constructs `UsageSniffer` with `content-type` +
  `content-encoding` when `onResponseUsage` is configured; a generic `header()`
  helper replaces the old `contentType()`-only one.
- `src/telemetry/`: additive `kind: "usage"` JSONL event
  (`recordUsageEvent`), `aggregateUsageByLevel` (kept separate from the
  existing gross-token `aggregate()` headline), and a new
  `usage-report.ts` (`effectiveInputTokens`, `usageReportRows`) applying
  Anthropic's cache pricing multipliers (§14).
- `proxy-runtime.ts`: wires `onResponseUsage` to record each event with the
  resolved slider level.
- Tests: 5 new unit tests (`tests/unit/proxy/usage-sniffer.test.ts`,
  compressed-body cases: gzip JSON, gzip SSE, brotli, unsupported-codec
  fail-open, truncated-gzip fail-open) + 1 new integration test
  (`tests/integration/proxy-usage-telemetry.test.ts`, gzip end-to-end) + 5 new
  jsonl-store tests for `recordUsageEvent`/`aggregateUsageByLevel`.

## Design notes

- No frozen interface changed — `CompressionStats` etc. were deliberately left
  alone; usage accounting is a parallel, additive path.
- The gzip bug was invisible to the entire fixture-based test suite (fixtures
  are never encoded) and was only caught by driving the real flow per
  R1_BATCH.md's Definition of Done — confirmed via a manual `curl -D-` against
  the live proxy, then fixed, then re-verified against real traffic after
  rebuild+restart.
- The measurement itself concluded there is currently nothing to A/B: level 1
  and level 3 are pipeline-identical on Anthropic (semantic compression gated
  off by `isCachingUpstream()`, levels 1/3 share the same
  redaction/lossless-compression config). Full reasoning and numbers in
  verification-notes §54 and the synthesis page.

## Verification

- `tsc --noEmit`, `npm run lint`, `npm run format:check`, `npm test` all clean.
- Rebuilt (`npm run build`) and restarted the live proxy (`golem proxy restart`)
  twice — once to verify the gzip fix, once after switching the slider to
  level 3 and back to gather the level-3 sample — confirmed real `usage`
  events landing in `.golem/telemetry/events.jsonl` at both levels.
