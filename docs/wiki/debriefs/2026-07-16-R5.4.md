# R5.4 — Cruise-control autonomy modes & approval gates (WS-F4 / spec 20d)

The security-gated R5 task. Its build gate required **a written threat model
reviewed before enforcement code** — delivered as
[[ADR-0002 — Cruise-control autonomy modes & approval gates]]
(`docs/wiki/decisions/ADR-0002-autonomy-approval-gates.md`), written first.

## What shipped

- **`src/autonomy/`** — the policy + classifier + gate:
  - `policy.ts`: levels `manual` (default) / `assisted` / `outcome`
    (deliberately no "full auto"); project-scoped state at
    `.golem/state/autonomy.json`. **Fails closed** — an invalid/corrupt file
    reads as `manual`, never the least-restrictive.
  - `classify.ts`: `classifyAction` → `read | write | destructive | outward |
    unknown`. Conservative allow-list — anything not positively read/write is
    `unknown`; Bash is `unknown` unless it matches a positive safe allow-list,
    and destructive/outward patterns only ESCALATE.
  - `gate.ts`: the decision matrix. `allow` is emitted ONLY for read (assisted+)
    and write (outcome); destructive/outward are `ask` at every level; errors
    stay silent → native prompt. No path auto-approves the irreversible set.
  - `log.ts`: every decision appended to `.golem/state/autonomy-log.jsonl`
    (auditable action log, ADR requirement).
- **`src/hooks/pre-tool-use.ts`** — the `PreToolUse` enforcement hook. Verified
  I/O shape (verification-notes §65 + hooks ref): emits
  `hookSpecificOutput.permissionDecision`. **Exit 0 + no stdout on every failure
  path** → Claude Code's native prompt (the human) governs; never exit 2, never
  auto-allow on error.
- **CLI `golem autonomy show|set|wire|unwire|log`** + `golem hook pre-tool-use`.
  Activation is opt-in and two conscious acts: `set <level>` (loudly warned) +
  `wire` (installs the PreToolUse hook). **Not auto-wired by `golem init`** — an
  always-on gate on the permission path deserves the explicit step (ADR §7).
- **Tie-in:** autonomy level is surfaced in the R5.2 `SessionStateReport` +
  `golem watch`.

## Verification

- +27 tests (classify 10, gate 6 incl. the never-auto-destructive/outward
  invariant, policy 4, hook 6, skills +1). Full suite **1004 green**; tsc +
  biome clean.
- Driven end-to-end through the real CLI + hook: `Edit` at `outcome` → `allow`;
  `git push` / `deploy.sh` → `ask` even at `outcome`; `Edit` at `manual` →
  silent; the audit log recorded `allow/ask/ask/defer`. A malformed-JSON stdin
  (a Windows path with unescaped backslashes) proved the fail-safe live — the
  hook deferred silently rather than emitting anything.

## Notes / follow-ups

- No frozen interface touched; redaction/proxy path untouched (the gate only
  observes tool calls).
- **Bug caught in e2e (fixed):** a parent-level `--dir` option on the `autonomy`
  command shadowed each subcommand's own `--dir`, so `set --dir X` wrote to cwd.
  Fixed by making `autonomy` a pure command group with a default `show`
  subcommand (the working `task` pattern). Lesson for future command groups:
  don't put `--dir` on both a parent and its children.
- Classifier coverage is intentionally incomplete-but-safe: an unenumerated
  destructive capability falls to `unknown` → gated, never auto-run. Extending
  coverage = extending the positive allow-lists.
- The "drive the loop" outcome level ships only now that the gate enforcement is
  tested (memo's explicit ordering).
