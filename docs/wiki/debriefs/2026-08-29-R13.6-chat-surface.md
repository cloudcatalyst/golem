# R13.6 -- the chat surface, and an XSS my own test found

## Outcome

A phone-shaped conversation view, served over mutual TLS to a paired device:
assistant text as it streams, tool calls as collapsed blocks, refusals rendered
as refusals, scrollback rehydrated from R13.2's store, an honest Stop, and a
header that says out loud what this is. Self-rendered HTML, no framework, no
build step — R12.5's shell inherited rather than forked. See
[[Session Transport]] and [[Hosted Session]].

## The bug worth the whole task

The test that fed the session id `"><script>alert(1)</script>` failed, and it
should have.

The HTML interpolation was escaped. The **JavaScript** one was not: the session
id is also embedded into the page's inline script as
`var SESSION = ${JSON.stringify(sessionId)}`, and `JSON.stringify` is not an
HTML-context escape. The HTML parser hunts for the end-of-script tag *before any
JavaScript is parsed*, so a string containing one closes the `<script>` element
early and everything after it is markup. A real XSS, in a page served to an
authenticated device on a LAN.

Then it took **three attempts to fix**, and each failure was the same shape:

1. `.replaceAll("<", "<")` — the compiler reads `<` and produces a
   literal `<`. The call became `replaceAll("<", "<")`: a silent no-op.
2. Writing the escape through a shell into a Python script into a TypeScript
   string literal lost a backslash at one of the layers, with the same result.
3. Fixed by removing backslashes from the source entirely:
   `` `${String.fromCharCode(92)}u003c` ``.

The lesson is not "escaping is hard". It is that **a correct-looking escape that
silently does nothing is indistinguishable from a correct one until something
executes it** — and the only reason all three attempts were caught is that the
test asserted on *behaviour* (the raw sequence must not appear in the output)
rather than on the presence of an escaping call.

## Key lessons

- **Assert on the output, not on the mechanism.** `expect(page).not.toContain("<script>alert(1)</script>")`
  survived three wrong implementations. A test that had checked "we call an
  escaper" would have passed all three.
- **A control that cannot be honoured must not exist.** Gate-map item 3 is
  locked: destructive and outward are never answerable from a device. So there is
  no approve/deny button *at all* — not a disabled one — and a test asserts its
  absence. A greyed-out Approve implies an authority the design does not grant.
- **Absent beats disabled, for the send box too.** The device certificate gets
  you the page; the passcode window is what lets you send, and it lapses while
  the page is open. A greyed box invites a tap and a wonder; an absent one with
  "run `golem device unlock`" tells you what to do.
- **Echo the user's turn only after the server says delivered.** Optimistic echo
  is precisely the "a message the user believes they sent" failure R13.5's
  contract exists to prevent — and it is one line to get wrong.
- **Say what Stop actually does.** §142 measured that SIGINT does not interrupt a
  running turn on Windows; only a process kill does. So the confirm dialog says
  the session ends, because that is what happens. A control labelled "stop the
  turn" that stops the session is the same class of lie as an optimistic ack.
- **Name the kind of session in the header.** Hosted versus joined (R13.7) are
  two different things with two different capabilities, and the user must never
  have to guess which they are in. The parameter exists now so R13.7 adds a value
  rather than a redesign.

## What this could NOT prove

R13.6's gate names a real phone and screenshots. **The single most likely thing
to not work is whether a mobile browser will present an installed client
certificate to a LAN IP** — that is the load-bearing assumption of the whole
R13.4–R13.6 chain and it cannot be simulated here. Filed as **R13.15**
(`owner: user`), with an explicit instruction in the task: if it fails, do not
work around it by weakening the device claim.

`golem wiki check` all exit 0. `npx vitest run`: **0 failures**. +21 tests. Live:
`golem session host serve` prints the chat URL, and the chat, history and
interrupt routes all answer an unpaired caller `device:no-certificate`.
