# R5.1 — Durable task queue & auto-resume (WS-F1 / spec 20a)

Spec 20a's dogfooding origin: in-flight agent work was repeatedly lost to
session/credit limits. R5.1 makes a task a **checkpointed, persisted unit** that
re-queues instead of vanishing.

## Spike first (the memo's build gate)

The memo's hardest open question was the resume/relaunch mechanism ("headless/SDK
mode or a PTY wrapper — genuine unknown, verify against live Claude Code docs").
**Verified against the live CLI reference (verification-notes §65):** headless
print mode (`-p`) + `--resume <session-id>` (or `--continue`) is the mechanism.
It is a plain non-interactive process, so **no PTY / terminal scripting is
needed**. Golem assigns the session id up front (`--session-id <uuid>`) so
relaunch is deterministic. The memo's PTY fallback is not needed for the
headless path.

## What shipped

- **`src/tasks/` — a non-frozen `TaskStore` seam + file impl.** One
  zod-validated JSON per task under `<project>/.golem/tasks/<id>.json`
  (`taskSchema`, `FileTaskStore`, atomic temp+rename, corrupt/foreign files
  skipped on `list()`, id path-basename'd against dir escape). Mirrors the
  `JsonFileSliderStore` / session-state conventions.
- **Task shape:** `state` (queued/running/blocked/paused/done/failed/cancelled),
  `prompt`, `sessionId`, `continueLatest`, `worktree` (path+baseCommit+dirtyFiles
  — captured for R5.3), `idempotencyKey`, `checkpoints[]` (plan step + status +
  per-step idempotency key), `notBefore` (capacity gate), `lastError`,
  `attempts`. `isResumable()` = non-terminal AND capacity gate passed.
- **`buildResumeArgv` (pure, cross-platform argument array — never a shell
  string):** `--resume <id>` when deterministic, else `--continue`; optional
  `--output-format json` and `--permission-mode` (the latter pairs with R5.4).
- **CLI `golem task {add,list,show,resume,cancel}`** (`src/cli/task.ts` render +
  spawn helpers, wired in main.ts). `resume` **prints the command by default**
  and only launches on `--spawn` (detached, argument-array, no shell); if the
  binary can't be launched (e.g. Windows `.cmd` off the exec path) it degrades
  to printing the copy-pasteable command rather than risking a shell-string
  spawn. `cancel --delete` removes the record.

## Verification

- +25 tests (types 6, store 5, resume 6, cli 8). Full suite **977 green**;
  tsc + biome clean.
- Driven end-to-end on the real CLI: add (with session id + `--not-before`
  capacity gate) → list → show → resume. The capacity gate correctly refused a
  future-gated task; a non-gated `--continue` task produced
  `claude --continue --output-format json -p <prompt>`; cancel worked.

## Scope boundaries / follow-ups

- **Built:** the durable store, deterministic resume mechanism, capacity gate
  (memo option 1: user-declared `notBefore`), and the CLI. This is the
  foundation **R5.3 depends on**.
- **Deliberately not built here:** a background auto-resume daemon (poll-when-due
  + spawn) and full worktree capture/restore fidelity — the `worktree` field and
  `notBefore` gate exist so R5.3 / a later daemon can add the loop without a
  schema change. "Resume = replay the plan, not blind re-exec" is represented by
  `checkpoints[]` + `idempotencyKey` (state the resumed agent re-verifies); the
  replay logic itself lives in the agent's behavior on resume, which is the
  honest division (Golem persists state; the agent replays).
- Capacity option 2 (poll-with-backoff on a cheap request) remains a future
  fallback behind a flag, per the memo.
