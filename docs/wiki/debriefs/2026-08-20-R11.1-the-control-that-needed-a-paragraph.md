# 2026-08-20 — R11.1: the control that needed a paragraph

The user, reading their own `golem status`:

> I'm confused about what the slider means vs compression. I feel we don't need
> the slider any more.

They were right, and the output proved it:

```
Slider: level 3 (aggressive) → effectively 1 (lossless)
Dials:  brevity full (pinned) · compression 3→1 (auto — follows slider 3)
  ⚠ level 3 (aggressive) is inert here: the lossy semantic and context-substitution
    stages are off on a prompt-caching upstream (Decision 31)
```

Three rows and a warning to say *the number you set does nothing*. Every one of
those lines was accurate — [[Two status lines, one truth]] had just made them
accurate. **A number that needs a paragraph is not a control, it is a quiz.**

Related: [[Compression Levels]] (the replacement) · [[Redaction Stage]] ·
[ADR-0004] · [verification-notes §132].

## What it actually was

`slider.level` was a **preset over two dials** (Decision 52). So two controls
described one thing, every surface had to render both or mislead, and on the
default upstream Decision 31 gated the slider's top half off — making levels 2
and 3 inert exactly where most users live.

Retiring it is one of those changes where the diff is large and the idea is
small: `compression.level` (`off|1|2|3`) and `brevity.level` are now set
directly. 379 references across 63 files; `tsc --noEmit` was the worklist.

## The best thing this bought

The old table's level 0 had `redaction: false`, and a constant existed —
`MIN_ACTIVE_COMPRESSION_LEVEL` — for no purpose other than stopping a *pinned*
dial from selecting that row. One integer in a settings file could switch
redaction off; a clamp stood in front of it.

Deleting the row deleted the clamp **and the class of bug**. Every row now has
`redaction: true`, so "a dial turned redaction off" is not something the code can
express. The contract test that used to assert *the clamp works* now asserts
*there is nothing to clamp*:

```ts
it("NO compression level can disable redaction (ADR-0004)", () => { … })
```

**A safety property is better unrepresentable than defended.** Worth looking for
the next one: any place where a guard exists because a type is too permissive is
a place the type could be narrowed instead.

## Where level 0 went, and the wrong answer we nearly took

The tempting home for the full bypass was the existing `golem on`/`golem off`
toggle — same behaviour, already built, already loud. It is **in-process only**
(`#pipelineEnabled`, flipped by a POST to `/__golem/pipeline/<enabled>`), so it
resets to ON at every proxy restart, and the proxy restarts on project open and
on every `gateway use`. A durable bypass cannot live in a flag that forgets.

So `proxy.bypass_all` is a persisted setting, applied at proxy construction,
CLI-only (R8.33's rule survives its own special case), and loud everywhere. And
we found a second bug on the way past: **`golem off` silently reverts** and
reports success. Recorded, not fixed here.

It is deliberately *not* a value of `compression.level`. Compression and
redaction are different guarantees; folding them into one word is how someone
turns off redaction believing they turned off compression.

## Two things the refactor found that the design missed

**Live reload had to become opt-in.** The slider had a property the dials did
not: a `SliderStore` re-read settings per request, so the `level` tool could
change the level without a restart — while a *pinned* dial needed one. Losing
that would have made the replacement worse than the thing it replaced, so
`resolvePolicy` re-reads config (1s TTL, full precedence, fail-safe to the
build-time policy).

The first version re-read **unconditionally** — and silently discarded settings a
caller had *built* rather than loaded. The R2.2 context-substitution test caught
it: it passes `overrides: { compression: { level: "2" } }` and would have been
served the file's default. **A live re-read must not silently outrank the values
the caller handed you.**

**A retired enum VALUE is harder than a retired key.** R9.6's machinery handles
renames, which load with a warning. `compression.level: "auto"` is a live key
with a dead value: the whole file fails to load and *every* `golem` command dies.
Found on this repo's own `settings.local.json`, which said `auto` with no slider
level — so the slider-transform branch never ran and the sweep sailed past it.

That also made this the first migration that **transforms** rather than renames:
one key becomes two or three, with values computed from it, which a `from`/`to`
row cannot express. It reproduces the retired resolvers exactly, so a real pin
still wins, `auto` is replaced rather than mistaken for a pin, and
`slider.level: 0` becomes `proxy.bypass_all: true` with both dials off.

## Verification

- 2,763 vitest + 56 extension tests green; `tsc`, `biome`, `format:check`,
  `verify:deps`, `golem wiki check` all exit 0.
- The migration live-verified on seven fixtures **and on this repo's real
  settings file** (`slider.level: 3` + `compression: "auto"` → `compression: "3"`,
  brevity's existing pin untouched, backup at
  `.golem/state/config-backups/local-0.24.0.json`).
- The live surfaces afterwards:

```
Compression: 3 (aggressive) → effectively 1 (lossless) — set by local
Dials: brevity full (set by local)
⬢ Golem → ◆ anthropic (claude-opus-5) · ✎ qwen2.5-coder:7b · 🗜 lossless · ✂ full
```

The §103 "set vs ran" gap survives, and should: a caching upstream really does
degrade 2/3 to lossless. Retiring the slider removed the *needless* discrepancy,
not the real one.
