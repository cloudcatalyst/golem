# R2.6 — cache-safe structural tier + net-safe A/B

Full technical detail is in verification-notes §60; this page records the
durable conclusion: **the mechanism and measurement infrastructure are built
and tested, but the live real-traffic A/B this task's own deliverable calls
for was deliberately deferred, not run.**

## What shipped

- `compression.force_semantic_on_caching` — new opt-in settings leaf, off by
  default. Only has any effect when `headroom_sidecar` is also on and slider
  level ≥2.
- `GolemPipelineOptions.forceSemanticOnCaching` bypasses `isCachingUpstream()`
  for the semantic pipeline stage specifically. Decision 31's gate function
  itself is unchanged — this is an opt-in bypass, not a weakening.
- `semanticForced` tag on `kind:"usage"` telemetry events (static per-run,
  set at proxy-build time — no per-request correlation id exists to do
  better without a materially bigger change) + `aggregateUsageBySemanticForced`
  / `semanticForcedReportRows`, reusing R1.1's exact `effectiveInputTokens`
  formula so gate-on vs gate-off is judged on the same honest metric R1.1
  established (see [[R1.1 — net-of-cache billed-usage A/B (level 1 vs level 3)]]).
- Full gate green: `tsc --noEmit` clean, Biome lint/format clean, 738/738
  vitest tests passing (including 3 new/modified test files covering the
  bypass and the new aggregation).

## What did NOT happen — the live A/B

Actually proving net-cache-safety means flipping the flag on and restarting
the golem proxy this very session's own Claude Code traffic depends on —
live infrastructure this session is mid-use of. Doing that unilaterally,
mid-session, was judged a real operational risk (a broken pipeline mid-session
degrades this conversation's own proxying), not a hypothetical one, so it
was flagged rather than done — the same treatment R1.6 gave an Ollama
verification block.

**R2.6 is therefore partial by design:** mechanism + measurement tooling
shipped; the actual net-cache-safety proof is a manual follow-up (enable the
flag for a real session, let normal Anthropic traffic run a while at slider
≥2, compare `semanticForcedReportRows` gate-on vs gate-off). The gate stays
OFF by default until that follow-up produces a real number — consistent with
R2_BATCH.md's own contingency language ("if net-negative or inconclusive:
document why and leave Decision 31's gate as-is — a negative result here is
still the deliverable").

See also verification-notes §60, §58, §59.
