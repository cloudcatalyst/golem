# R2.2 — context-substitution sub-mode (Decision 24 sub-mode 1)

Full technical detail is in verification-notes §62; this page records the
durable conclusion: **when a request carries a span already sitting in the
project's web-cache, the proxy now elides it and replaces it with an
`expand`-able reference, and the tokens avoided are durably tracked as their
own telemetry metric.**

## Design decisions

**Gate slot reused, no frozen-interface change.** Decision 24 says this
sub-mode applies at "slider ≥3" under the OLD 0-5 scale. Translating through
Decision 30's collapse (old 1+2→new 1, old 3→new 2, old 4+5→new 3), "old ≥3"
lands on new **levels 2 and 3** — exactly `stages.semanticCompression !==
"off"` in the existing `LEVEL_TABLE` (`src/interfaces/policy.ts`). So this
stage reuses that field as its gate rather than adding a new `StageConfig`
field, avoiding `src/interfaces/`'s contract-tests-first hard rule entirely.

**Gated off on caching (Anthropic-style) upstreams**, the same
`isCachingUpstream()` rule Decision 31/R2.6 established for the semantic
stage — reused rather than reinvented. The reason is specific to this stage:
`native-lossless.ts`'s dedup is safe unconditionally because it's a pure
function of the current request's own prefix, but the web-cache lookup this
stage consults grows across requests — the same prefix could substitute
differently on a later call, breaking a previously-stable cached prefix
(§14). Non-caching upstreams have no stable prefix to break, so substitution
there is cache-safe by construction — no need to parse Anthropic's actual
`cache_control` breakpoints (machinery Golem doesn't have).

**Scope: webcache only, v1.** Only `src/knowledge/web-cache.ts`'s exact-URL
cache (pages fetched via WebFetch) is covered — not the full vector KB's
chunks. Deliberate narrowing; full KB-chunk substitution is a documented
follow-up, not built now.

## What was built

- `WebCache.list()` / `contentHashIndex()` — a `sha256(content) -> url` map,
  rebuilt fresh every call (the cache grows across requests; no incremental
  index to go stale).
- `src/compression/context-substitution.ts` — `substituteKnownContent`,
  scoped to user-role text and `tool_result` content exactly like
  `native-lossless.ts`, persisting each substituted original into the CCR
  store (fail-open) under its hash — the same reversibility precedent R2.4
  set for Headroom's markers.
- Pipeline Stage 4, wired through a new non-frozen
  `GolemPipelineOptions.contextSubstitution` option.
- A new `avoidedUpstream` telemetry event kind (`recordAvoidedUpstream` +
  `TelemetryStore.aggregateAvoidedUpstream()`), following the
  `recordRetrieval`/`recordUsageEvent` template — added only to the
  non-frozen `TelemetryStore` interface, not the frozen `CompressionStats`.
- `src/cli/proxy-runtime.ts` wiring: a project-rooted `WebCache`, re-hashed
  via a thunk on every request, sharing the Headroom backfill's `.golem/ccr`
  store.
