Full technical detail is in Decision 33 (`docs/golem-spec.md`); this
page records the durable conclusion: **the proxy can now answer a narrow
class of single-turn questions directly from the project knowledge base,
skipping the upstream LLM entirely — opt-in, off by default, and never
triggered by the slider.**

## Design decisions

**Re-introduces Decision 24 sub-mode 2 as its own contract, not a revival of
Decision 25.** Decision 25's automatic local-first trigger was removed
because it conflated "how aggressively do we compress" with "does the local
model sometimes answer for Claude" — the same conflation [[R2.6]] and
Decision 31 fixed for the semantic stage. This mode gets its own settings
leaf, `knowledge.local_answer_enabled` / `knowledge.local_answer_min_confidence`,
fully decoupled from `slider.level`.

**Narrower trigger than Decision 25's**, to cut its residual risk (a
confident-but-wrong answer to a question that only looks self-contained):
single-turn only (`messages.length === 1`, role `user`, plain text), and
extractive rather than generative — the answer is composed directly from
retrieved KB chunks (`composeFromHits`), never phrased freely by a chat
call, plus a confidence floor (default 0.6) below which the request falls
through untouched.

**Labeled, never silent** — served answers are prefixed *"**Golem** Answered
locally from the project knowledge base — verify independently."*, and the
synthesized response never uses a Claude model id.

**Checked before building: does [[r2.1-avoidedupstream-spike]]'s
`avoidedUpstream` bucket have real signal yet?** No — and structurally can't
on this repo's own dogfooded traffic, since the repo talks to Anthropic (a
caching upstream) and this stage, like R2.2's, only engages on non-caching
upstreams. Shipped anyway on the same honest-infra-first footing as
[[R2.6]]'s deferred live A/B: the mechanism and its tests are real, the
traffic evidence isn't yet.

## What was built

- `src/interfaces/local-answer.ts` — new frozen contract (`LocalAnswerService.tryAnswer`,
  `composeFromHits`), contract tests first per CLAUDE.md's hard rule.
- `src/knowledge/local-answer.ts` — `KnowledgeLocalAnswerService`, over the
  existing `FederatedSearch` read path; no new retrieval machinery.
- `src/pipeline/local-answer-response.ts` — eligibility check + non-streaming
  JSON / SSE response synthesis matching the recorded Anthropic Messages shape.
- `ProxyRequest.respondDirectly` (`src/proxy/types.ts`) — additive seam;
  `GolemProxy.handle()` writes it and skips the upstream call entirely when set.
- Pipeline "Stage 1.5" (`src/pipeline/pipeline.ts`), gated on
  `options.localAnswer`, running after redaction and independent of
  `slider.level` — a confident answer short-circuits even at level 0.
- `avoidedUpstream` telemetry extended with `avoidedUpstreamOutputTokens`
  (this mode avoids the whole round-trip, not just input tokens).
- `src/cli/proxy-runtime.ts` wiring over the same embedded knowledge base
  `golem index` / `mcp serve` already use; semantic embedder if an
  `InferenceService` is available, else the hashing-embedder fallback.

## Verified

`tsc --noEmit` clean, `biome check .` clean, full `vitest run` — 86 files /
809 tests, all green (new: contract tests for `KnowledgeLocalAnswerService`,
unit tests for eligibility/synthesis and the pipeline stage, integration
tests through the real `GolemProxy`, and composition-root wiring tests for
the new settings leaf).

Confidence floor (0.6) validated only empirically against one fixture
(matching query ≈0.66, unrelated ≈0.06) — not yet validated against real
queries. Decision 33 is marked PROPOSED, not ACCEPTED, until a human reviews
a served answer end-to-end.
