# R8.9 — change ledger, or how to discard an attempt instead of repairing it

Last row of R8d. `golem checkpoint` snapshots the worktree into
`refs/golem/ledger/<id>` and can put it back, so a failed attempt is **thrown away**
rather than unpicked — see [[Change Ledger]] for the surface itself.

## What shipped

- `src/checkpoint/git.ts` — `runGit` (argument arrays, resolves for every outcome,
  always closes stdin) and `inspectRepo` (git on PATH? repo? HEAD? detached? index
  dirty?).
- `src/checkpoint/ledger.ts` — create / list / resolve / plan / restore / drop /
  prune over shadow refs, all through a throwaway `GIT_INDEX_FILE`.
- `src/cli/checkpoint.ts` + `golem checkpoint create|list|show|restore|drop|prune`
  (`cp`, `take`, `ls`, `undo` aliases) — the loud preview and the `--yes` consent
  convention.
- `golem checkpoint restore|undo|drop|prune` classified **destructive** in
  `src/autonomy/classify.ts`, so ADR-0002's never-auto set gates it for an agent at
  every autonomy level; `create`/`list` stay cheap.
- A `/golem/checkpoint` skill, and one paragraph added to `/golem/develop`:
  checkpoint *before* a wide or speculative change.
- 12 integration tests against a real git repo + 10 unit tests for the preview and
  the consent gate.

## The design decisions worth keeping

**Shadow refs, from the repo rule.** This repo commits only when asked, so a snapshot
had to be a commit object that no branch points at. `commit-tree` parented on `HEAD`
+ `update-ref refs/golem/ledger/<id>` gives that: no branch, no index write, `HEAD`
unmoved, and git's default refspecs do not carry `refs/golem/*` so it cannot leave
the machine. Bonus that fell out of it — a snapshot is an ordinary commit, so
`git diff refs/golem/ledger/<id>` needs no Golem command at all.

**A throwaway index is the whole safety mechanism.** Every staging step runs with
`GIT_INDEX_FILE` pointed at `<gitDir>/golem-index-<pid>-<n>`, and the restore uses
`read-tree` + `checkout-index -f -z --stdin` against that same temp index. So the
user's index is never read-modify-written, and `-z --stdin` also means a thousand
changed paths do not hit Windows' ~8k command-line limit. The real index is *copied
in* first, purely so git's stat cache is reused and only changed files are rehashed.

**No MCP tool, deliberately.** §88/§100 measured what a definition costs on every
request. The model can call the CLI through `Bash` for nothing, so the guidance is a
skill (lazy) rather than a tool (billed). This is the first R8 feature to make that
trade explicitly.

**Gate the destructive half only.** `restore` is in the never-auto set, which is what
the task asked for. Making `create` cheap was equally deliberate: gate the snapshot
and the model stops taking snapshots, and then the feature saves nothing.

**A restore is itself undoable.** It takes a `pre-restore` checkpoint first and
prints the command that reverses it. Cheap, and it converts "destructive" into
"reversible", which is the only reason a preview + prompt is enough consent.

## Two findings from running it, not from writing it

**The smoke test caught a real bug the tests did not.** In a scratch repo with no
`.gitignore`, the first live restore reported "2 deleted" where the plan said 1: the
extra path was Golem's **own `.golem/` state**, created after the checkpoint by the
very command being tested. A restore that deletes telemetry, tasks and CCR blobs is
rewinding *Golem*, not the user's attempt. Fixed by excluding it in the pathspec
(`:(exclude).golem`) so both the snapshot and the plan agree it is out of scope —
`.gitignore` was doing that job invisibly in every real project, which is exactly why
no test had noticed. The regression test now asserts it with `.golem/` untracked and
un-ignored.

**Line endings are git's, not the disk's.** `checkout-index` runs the smudge filter,
so on this machine (`core.autocrlf=true`) restored files came back CRLF and three
tests failed on `\r\n`. Not a bug — it is precisely what `git checkout` does, and
matching git is the contract — so it is documented in the module and the concept page
and pinned (`core.autocrlf=false`) in the test repos, which keeps the tests about the
ledger rather than about the developer's git config.

## Unmeasured, and named as such

The saving is **structural, not measured**: nobody has yet counted a repair cycle
against a discard on real traffic. The mechanism costs ~0 tokens when unused (no tool
definition, no hook), so the downside is bounded — but "discarding is cheaper than
repairing" remains an argument from §93's re-reading number, not an A/B. The
displacement question is the same one [[Repo Map]] and [[LSP Bridge]] left open: does
the model actually *reach* for it? That needs dogfooding, and the honest answer today
is that the skill exists and the habit does not yet.

## Also of note

Writing the module surfaced one dogfooding oddity worth remembering: Golem's
redaction stage rewrites e-mail literals in the transcript on the way *back* to the
model, so a committer address written into source reads as `[REDACTED:email:N]` when
the model greps for it afterwards. The bytes on disk are correct — it is a display
effect of [[Redaction Stage]] — but an agent editing such a line cannot match it, and
has to anchor its edit elsewhere.
