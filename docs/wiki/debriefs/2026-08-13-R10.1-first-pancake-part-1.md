# R10.1 (part 1) — the first pancake was not burnt, it was just big

Related: [[Configuration Surfaces]], [[Web Cache]]

**Date:** 2026-08-12/13
**Task:** R10.1 (partial — see the task doc for what remains)
**Branch:** `r10.1-first-pancake-rewrite`

## Outcome

Eight commits. ~1,200 LOC of genuinely dead code deleted, four monoliths split,
three previously-unenforced invariants turned into tests, and two user-facing
staleness bugs fixed. The suite went from 2546 to 2553 tests with none lost.

But the headline is that **the task's own premise did not survive measurement.**

## The premise was wrong, and finding that out was the most valuable hour

R10.1 was written on the "first pancake" assumption: release 1 is throwaway
scaffolding, so keep the recipe and scrap the execution. Five parallel surveys
plus a full import-graph sweep (dynamic `import()` included) over 261 src and
212 test files found:

- **Zero** `TODO`/`FIXME`/`XXX`/`HACK` markers anywhere in `src/`
- **Zero** commented-out code blocks
- **Zero** orphaned tests, **zero** `.only` leaks
- **Exactly two** near-duplicate files, both from the single R9.23 rename
- Total provably-dead code: **942 LOC — 1.6% of a 59,600-line tree**

There is no vibe-coded sprawl here. There are large *files* of dense,
decision-cited, tested code. So the work is not scrapping — it is splitting
monoliths and converting conventions into structure. The lesson generalises:
**measure before you believe your own framing of a codebase**, especially when
the framing is flattering to the act of rewriting.

The same check saved the benches. ~2,000 lines of `*-bench.ts` in `src/` looked
exactly like proof-of-concept residue. They are not: all four back shipped
`golem bench …` commands, `bench cost` IS spec Decision 21f, and `edit-bench` is
the live gate for a feature shipped off by default. Moving them to `tests/`
would have broken the CLI.

## The R9.23 rename left more behind than duplicate files

R9.23 renamed accounts→gateways by **forking** each file rather than renaming
it. The residue was not merely 871 duplicate lines:

- `cli/gateways.ts` (the live module, imported by four command files) had **zero
  direct tests**. All 37 tests had stayed on the dead `cli/accounts.ts`. The
  deletion was therefore mostly a *coverage rescue*.
- `default_target` moved from the `proxy` section to `inference`, but no caller
  got one place to read it back — so the same merge was open-coded five times,
  twice inside one function where the two copies feed the `upstream` and
  `targets` fields of `golem status --json` and must agree or the output
  contradicts itself.
- `inference.coder_enabled` was deleted as a settings leaf but survived in eight
  places in `src/`, two of them user-facing: `golem local status` printed
  `coder tool: enabled (inference.coder_enabled, from <layer>)` — naming a
  setting that no longer exists, and attributing it to the *endpoint's*
  provenance — and the `coder-first` guidance rule, which ships into
  `.claude/rules/` and is read by Claude every session, gated its enforcement
  claim on the same dead key.

**Lesson: a rename is not done when the code compiles.** Grep the retired name
across prose, guidance text and status output, not just identifiers.

## A documented rule that nothing checked

CLAUDE.md says "Headroom pinned exactly; imports only in
`src/compression/headroom-adapter.ts`". Only the *pin* half was ever tested. The
isolation half was code review alone — a PR adding a Headroom import anywhere
would have gone green. The rule held; nothing was holding it.

`tests/contract/headroom-isolation.contract.test.ts` now checks it against the
source tree. Two things made it correct rather than merely present:

1. **It strips comments first.** Naming Headroom is fine and widespread
   (`compression.headroom_sidecar` is a config key). Only *reaching* it is
   forbidden. The first version failed on a doc comment in `schema.ts`.
2. **It only flags bare specifiers.** Importing the adapter's public class by
   relative path is the rule working as intended. The first version flagged
   `proxy-runtime.ts` for doing the right thing.

It also asserts the adapter *does* import and spawn Headroom, so the guard can
never pass vacuously by the sidecar being deleted. **And it was verified to fail
on a real violation** — a guard nobody has tried to break is worth little.

## Splitting without changing behaviour

Four monoliths split, every public export preserved so no call site changed:

| file | before | after |
|---|---|---|
| `cli/status.ts` | 940 | 290 + collect (413) + render (284) |
| `cli/proxy-runtime.ts` | 470 | 204 + three `proxy-build/` modules |
| `hooks/web-fetch.ts` | 686 | 364 + serve + revalidate |
| `hooks/post-tool-use.ts` | 603 | 279 + digest + served-fetch-label |

`buildProxyFromSettings` went from 357 lines in one function to a 108-line
assembler. **The seams were never invented** — they were already visible as the
`// 1.` … `// 8.` comments, the per-probe `try/catch` blocks, and the test
files' own `describe()` structure. When a file tells you where it wants to be
cut, the split is low-risk; when you have to invent the boundary, it is not.

Two new tests were the point of the exercise, both verified to fail when
violated:

- Byte-fidelity at slider ≤1 asserts `mapUpstreamHeaders`/`translateUpstream`
  are **absent keys**, not merely `undefined` — `resolveProxyConfig` copies
  optional keys only when defined, so an absent key proves it was never passed.
  An extraction returning a harmless `(h) => h` identity would have silently
  broken byte-fidelity and passed a weaker assertion.
- The WebFetch green-path stdout JSON is pinned with `toStrictEqual` against a
  real loopback CA and HTTPS endpoint — **written and run against unmodified
  source first**, so it pins pre-existing behaviour rather than the refactor's
  output. That ordering is what makes a characterisation test trustworthy.

## Duplication that should NOT be removed

`isRecord` had 18 definitions. Nine remain, and five of those survive
deliberately: `cli/statusline.ts`, both Ollama clients and both LSP modules omit
the `!Array.isArray` check, so **they accept an array as a record**. That is a
behavioural difference, not a formatting one — in statusline it guards parsing
Claude Code's stdin JSON, where an array would read `length` as data. Unifying
blind would have changed how malformed payloads parse.

**Lesson: "identical-looking" is not "identical".** Diff the bodies before
merging helpers, and when they differ, report rather than reconcile.

## The suite is intermittently red, and CI structurally cannot see it

Five full runs of the same commit gave 5, 0, 3, 0, 3 failures. Every failure was
contention: the ~26 integration files spawn real subprocesses, and when the
worker pool saturates, `spawn()` latency balloons. One test measured at **409ms
alone** had timed out at 20,000ms.

Two traps worth carrying forward:

- **Never run the full suite while subagents work.** Parallel agents turned 0
  failures into 5.
- **"Timeouts are flake, assertions are real" is WRONG here.** One flake
  presents as `AssertionError: expected true to be false` — headroom-adapter's
  R8.30 backoff test waits 400ms for a worker that dies at 300ms, and under load
  the exit event misses that 100ms margin. Re-running the file in isolation is
  the only reliable check.

Tracked as **R10.2**, along with why the obvious fixes (pool tuning, raising
`testTimeout`) are both wrong.

## Working with parallel agents

Three split agents succeeded on disjoint files. A second wave of three was
killed mid-edit by a session limit and left the tree with 31 type errors — one
agent had deleted local helper definitions before adding the imports that
replace them.

Two agents had also created new modules but died before updating `init.ts` and
`selection.ts`, so the originals still held the code and the new modules were
unreferenced duplicates. **Those were deleted, not kept**: a half-done split
left in the tree is worse than not starting, because it is dead code that looks
like progress — the exact thing this task exists to remove.

**Lesson: give each agent a disjoint file set and targeted test files only, and
assume any agent may die mid-edit.** Verify the tree compiles before trusting
any of it, and prefer finishing an interrupted refactor by hand over leaving
both halves in place.
