# R8.5 — repo map, and the oversized-`Read` skeleton

**Verdict: SHIPPED, and the gate said yes — +21.4 accuracy points for 57 tokens.**
The first item in the R8 context-economy line whose own instrument approved it,
after §93 (bust prevention is a guard rail, not a lever), §94, §95, §97 and §100
(R8.S1 rejected) each redirected or closed a line of work.

## Why this was next

`golem stats --context` put `Read` second among tool consumers (27,056 tokens
across 18 results in the §95 capture; 40,708 across 20 later) **and** it is the
surface an external Bash-output compactor structurally cannot reach (§90). §93
established that ~83% of input cost is re-reading an already-cached context, so a
read avoided pays on every later turn rather than once.

## What shipped

1. **The map** — [[Repo Map]]: `src/knowledge/repo-map.ts`. tree-sitter symbol
   extraction → an import/reference graph → personalized power-iteration rank →
   a signature skeleton rendered to a token budget (default 1.4k). Pure over
   `(file contents, options)`: no clock, no randomness, no printed scores, and a
   total tie-break on every ordering, because the map lands in a cached prefix's
   neighbourhood and an unstable rendering re-prefills (§14). Parsed facts are
   cached per file on mtime/size, so a second map in one process costs the walk.
2. **The `code` MCP tool** — **one** tool with a `mode` parameter, never one tool
   per capability. §88/§100 measured definitions as a permanent per-request bill,
   so R8.6's LSP surfaces will be modes of this same tool. `mode: "map"` is the
   only mode today; `query` re-ranks toward the question, `paths` weights files
   already in play, `budget_tokens` caps the spend.
3. **The oversized-`Read` skeleton** — the swap target the task asked for. When
   the PostToolUse digest replaces a huge `Read`, it now carries every definition
   in the file with its **real** line number (offset-aware, so a `Read` starting
   at line 500 reports file lines). That turns recovery from `expand` — which
   re-enters the whole original, §95 measured one at 6,356 tokens — into a `Read`
   of forty lines. Extracted from the **redacted** text, like the excerpts.
4. **The gate** — `golem bench map` (`src/knowledge/repo-map-bench.ts`), in the
   shape of `golem bench tools`: 22 hand-labelled retrieval cases, an A/B against
   the plain path list, cost and accuracy in one view.

## The numbers (§101)

| arm | context | mean tokens/call | accuracy |
|---|---|--:|--:|
| baseline | plain path list (386 paths) | ~1,329 | 28.6% (18/63) |
| candidate | repo map, re-ranked per question | ~1,386 | **50.0% (33/66)** |

+21.4 points for +57 tokens; 22 cases × 3 repeats; resolution 4.5% (one case), so
the delta is 4.7× resolvable and it reproduced exactly at 1 and 3 repeats. The map
costs ~0.6× one whole-file read (~2,238 tokens mean), so it pays if it avoids one.
The `code` definition adds ~262 forwarded tokens (~101 description + ~161 schema).

## What the measurement changed

Three ranking bugs were found by looking at real output, not by reasoning:

- **Only exported symbols may be graph targets.** File-local names (`body`,
  `url`, `draft`) were attracting inbound reference weight from the whole repo,
  floating a test file above `src/interfaces/`.
- **A queried map needs more than a personalized teleport vector.** At damping
  0.85 the hubs still won; a queried map now drops damping to 0.5 *and* scales the
  final rank by query affinity.
- **Word parts and IDF, not substrings.** `the` is inside `pathExists` and `and`
  inside `expand`; with substring matching those beat `digest` (2 files).

The verdict rule was also tightened mid-run: "any excluded chooser error ⇒
inconclusive" let one reproducible unusable reply erase a delta 4.7× the
resolution. It now scores excluded errors the worst possible way and asks whether
the sign survives (+18.2% here, so it cannot flip).

## Honest limits

- The chooser is a **local 7B model** (`qwen2.5-coder:7b`, `--role drafter` — the
  tier's `classifier` is *still* not pulled, third occurrence; see the
  `local-models` task). This is evidence the map carries the signal, not a claim
  about how a frontier model uses it.
- **Memo open question 3 is still open.** This measures whether the map *names*
  the right file, not whether the model then skips reading it. Displacement needs
  live traffic.
- tree-sitter is tier-2 (Decision 53). Absent, `code` reports "no repo map
  available" and a swapped `Read` keeps its plain head/tail digest — a no-op,
  never an error path.
- Both features are opt-out: `knowledge.repo_map_enabled` and
  `knowledge.read_skeleton_enabled`, on by default.
