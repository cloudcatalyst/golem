Second slice of case (b). b1 established the response-transform seam on the
non-streaming path; b2 adds the streaming path — the one that matters, because
Claude Code almost always sends `stream:true`. So after b2, an OpenAI-schema
upstream (OpenAI / Ollama local or LAN) is genuinely usable in the editor.

## What landed

- **`src/providers/openai-stream.ts` — `OpenAIChatSSETranslator` (a `Transform`).**
  Consumes OpenAI Chat Completions SSE bytes (chunked on any boundary — it
  buffers an incomplete tail line and re-parses) and emits a well-formed
  Anthropic event stream: `message_start` → `content_block_start` →
  `content_block_delta`(`text_delta`)×N → `content_block_stop` → `message_delta`
  → `message_stop`. `message_start`/`content_block_start` are emitted lazily
  exactly once; `finish_reason`→`stop_reason` via the shared `mapStopReason`;
  the trailing OpenAI `usage` chunk feeds `message_delta.usage`. An empty stream
  still produces a valid empty message.
- **Request now honors `stream`** (`anthropicToOpenAIChat`): b1 forced it off; b2
  passes the client's flag through and adds `stream_options:{include_usage:true}`
  so the upstream emits a final usage chunk.
- **Proxy seam extended** (`UpstreamTranslator`): `translateRequest` now returns
  `{body, stream}` so the proxy picks the response path — non-streaming buffers +
  `translateResponse` (b1); streaming pipes `upstream.body` through
  `createStreamTranslator()` to the client with SSE headers, **never buffered**.
  Still the only path that parses a response; the Anthropic passthrough is a raw
  byte pipe.

## Live verification

Real proxy → local Ollama (`qwen2.5-coder:7b`), `stream:true`: HTTP 200
`text/event-stream`, full correct Anthropic event sequence, streamed text
`PONG`, `message_delta` with `end_turn` + real usage (verification-notes §75).
So streaming works end-to-end on a real backend, incrementally.

## Scope / interfaces

No frozen `src/interfaces/` change. `UpstreamTranslator` (non-frozen proxy type)
gained `createStreamTranslator()` and `translateRequest` now returns `{body,
stream}`. +5 tests (streaming unit incl. mid-frame chunk splits + empty stream;
a streaming proxy integration test); suite green on clean runs (1201; one
unrelated `cli-init` idempotency flake, §68-class, retries green). tsc/biome/
format clean; wiki check clean. Anthropic passthrough unchanged.

## Known caveat (documented, not a bug)

Anthropic carries `input_tokens` in `message_start`, but OpenAI streaming reports
usage only at the end — so `message_start.usage.input_tokens` is 0 and the real
counts arrive in `message_delta.usage`. Clients that read input tokens only from
`message_start` under-count; a fix would buffer the head and defeat streaming.
Acceptable for a local run.
