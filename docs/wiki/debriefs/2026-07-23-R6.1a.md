Second task off the R6 build order (after R6.4). The verification pass
(verification-notes §73) split "provider adapters" into two very different
builds; this is the small, byte-faithful-safe half.

## The finding that shaped it (§73)

- **Azure AI Foundry Claude speaks the native Anthropic Messages API**
  (`/anthropic/v1/messages`), not OpenAI — OpenAI-style calls 404. Auth is
  `api-key`/`x-api-key` or an Entra `Authorization: Bearer`. **OpenRouter** is
  OpenAI-schema primary but *also* exposes an Anthropic Messages endpoint.
- So **case (a)** — Anthropic-**protocol** gateways — is "different host + auth,
  same wire protocol." SSE and tool-use blocks pass through exactly as against
  `api.anthropic.com`, so the byte-faithful hard rule holds by construction. The
  real OpenAI/Gemini/Ollama translation is **case (b)** (next), which needs a
  response-transform seam this task deliberately does not add.

## What landed

- **`src/providers/index.ts`** — `UpstreamProvider`
  (`anthropic`|`azure-foundry`|`openrouter`|`custom`) + `UpstreamAuthScheme`
  (`inherit`|`x-api-key`|`api-key`|`bearer`); `resolveAuthScheme` (an explicit
  scheme wins; `inherit` on a non-Anthropic provider → that provider's default);
  `makeAuthMapper` (strips the client's Anthropic `x-api-key`/`authorization`,
  injects the configured credential under the scheme's header, keeps
  `anthropic-version`); `upstreamAssumesCaching`.
- **Config** — `proxy.upstream_provider` + `proxy.upstream_auth_scheme` leaves
  (base URL already existed). The **credential is never a setting** — it is read
  from `GOLEM_UPSTREAM_API_KEY` (secret; the R6.2-lite single-key path, distinct
  from R6.2's multi-account store).
- **`mapUpstreamHeaders` proxy seam** (`ProxyServerOptions`/`ProxyConfig`,
  additive) — applied in `server.ts` immediately before the upstream request,
  **outside** the pipeline (so it maps auth on `x-golem-bypass` too — the
  upstream always needs valid creds) and **never touches the body**. Default
  (Anthropic) has no mapper → literally a no-op, byte-identical path.
- **`assumeCachingUpstream` fix** (`pipeline.ts`) — the URL heuristic classified
  a non-`anthropic.com` host (Azure) as *non-caching*, which would let the lossy
  semantic stage rewrite history and break Claude-via-Azure's prompt cache. The
  selected provider now overrides it: non-Anthropic Claude gateways are treated
  as caching (fail-safe; a forced A/B still uses R2.6's `force_semantic_on_caching`).

## Scope / interfaces

No frozen `src/interfaces/` change. Proxy transport gains one additive optional
(`mapUpstreamHeaders`); pipeline gains one additive optional
(`assumeCachingUpstream`). +14 tests (providers unit, proxy auth-mapping
integration incl. the bypass case, pipeline caching-override both directions);
1184 green; tsc/biome/format clean.

## Honest limitation

**Live-unverified.** No real Azure Foundry / OpenRouter credentials or endpoints
in-session, so this is tested with fakes/recorded shapes only — a real
end-to-end run against a gateway is a user-side step (same posture as R7.3's
binaries). The Anthropic default path is unchanged, so the dogfooded proxy was
rebuilt but **not** restarted unilaterally.

## Next (case b)

Per the user's goal: one Anthropic↔OpenAI-Chat-Completions adapter reaches
OpenAI/ChatGPT **and** Ollama (local & LAN, `http://gpubox.lan:11434`), then
Gemini. That build adds the response-transform seam (translate the upstream's
response + SSE + tool-use back to Anthropic shapes) — the high-scrutiny piece;
the Anthropic path must stay untouched.

third party), [[Compression]] (why the caching classification gates the lossy
