# R13.2 — the conversation store: redacted transcripts, local-only, bounded, forgettable

**Task this closes:** `docs/plan/tasks/R13.2.md`, under ADR-0007 §6
(Retention) and §5 invariant 5 (redaction before storage). Full evidence is
in `docs/plan/verification-notes.md` §143; this page is the durable pointer
into it, and `docs/wiki/concepts/Conversation Store.md` is the user-facing
"what is retained, for how long, how to delete it" page the task's gate
requires.

## What this is, and why now

`src/session/session-tree.ts` (R8.S3) records a conversation's branch/fork
shape from **content hashes only** — no prompt content, on purpose, stated in
its own header. Two upcoming features need real turn text on disk that a hash
cannot provide: scrollback (seeing the previous messages again) and
continuing a conversation later (R13.8). ADR-0007 §6 accepts a **deliberate,
narrowly-argued exception**: a second, separate store, redacted before write,
local-only, bounded, and removable by one command. Revision 1 narrowed the
justification further by dropping branching — this store is sized for
scrollback and continuation, not an indefinite archive.

## What was built

1. **A frozen contract**, `src/interfaces/conversation-store.ts`:
   `ConversationStore` — `appendTurn`, `readConversation`, `listConversations`,
   `forget`, `forgetAll` — plus `ConversationTurn`/`ConversationRecord`/`ConversationSummary`
   types, re-exported from `src/interfaces/index.ts`. `src/interfaces/` is
   frozen-contract territory; R13.3 (session host), R13.5 (transport), and
   R13.8 (continue/start flows) all consume this and must be flagged as
   dependent workstreams wherever this interface changes again.
2. **`LocalConversationStore`** (`src/session/conversation-store.ts`), the
   implementation: one JSON file per conversation under
   `<project-root>/.golem/conversations/<conversationId>.json`, atomic writes
   (temp file + rename, matching `session-tree.ts`'s `writeSessionTree`),
   mode `0o600`, zod-tolerant reads (a missing or corrupt file reads as
   absent rather than throwing).
3. **Structural redaction.** `appendTurn` runs `redactRequestBody`
   (`src/pipeline/redaction.ts`) over `turn.content` unconditionally — there
   is no parameter, flag, or branch that persists the raw value. Proven, not
   just asserted: a test builds a github-token-shaped secret **at runtime**
   (`` `ghp_${"a".repeat(36)}` ``, per the standing fixture rule) and asserts
   the stored bytes contain the redaction placeholder and never the secret.
4. **Bounds**: `maxConversations` (default 32) and `maxAgeMs` (default 30
   days), both configurable, oldest (`lastTurnAt`) evicted first, age checked
   before count. Shape precedent: `web-cache.ts`'s bounded local store under
   `.golem/`.
5. **Deletion**: `golem session forget <id>` and `golem session forget --all`,
   wired to the real store and covered by CLI-level tests
   (`tests/unit/cli/session-forget.test.ts`), not a mock.
6. **Identity agreement**: `conversationIdFor` delegates entirely to
   `cachePrefixFingerprint` (`src/proxy/cache-prefix.ts`, fixed by R8.13) —
   the same function `session-tree.ts` already uses — so one conversation has
   one id in both stores. `conversationStoreDir` resolves through
   `resolveWorktreeRoot` (task `ccr-ref-scope`) first, so a linked-worktree
   checkout and its main checkout agree on where the store lives.
7. **`.gitignore` coverage verified, not assumed.** This repo lists every
   `.golem/` subdirectory individually rather than relying on one blanket
   pattern, so `.golem/conversations/` was added explicitly and a test shells
   out to `git check-ignore -q` and `git ls-files` against the real repo to
   prove it, rather than trusting the existing `.golem/compact/`-style
   entries to also cover a brand-new subdirectory.

## The bug found and fixed along the way: Commander.js and a shared `--dir`

`golem session` (the tree-view command) and `golem session forget` (the new
subcommand) both need their own `--dir <path>` option. Both declared it.
Result: `forget`'s action always received the module's default directory,
never the value actually typed on the command line — in **both**
`forget --dir <path> <id>` and `forget <id> --dir <path>` order.

Root-caused with three single-file, no-project-code Commander repros (see
verification-notes §143 for the exact scripts and outputs), not by guessing
inside the real codebase:

- Parent-only declares `--dir` → child's action reads the correct value via
  `command.parent.opts().dir`. Works, both orders.
- Both declare `--dir`, distinct defaults → the CLI-typed value is lost
  entirely; the child's action reports **its own default**, not the parent's,
  regardless of order.
- `program.enablePositionalOptions()` on the root fixes it too, but scoping
  that call to the child subcommand alone does not.

Fix applied: kept `--dir` declared on both (so `--help` on either subcommand
still documents it), but `forget`'s action reads
`command.parent?.opts<{ dir: string }>().dir ?? opts.dir` instead of trusting
its own parsed `opts.dir`. Verified in the minimal repro and in the real CLI
test suite, all three cases (flag before the id, flag after the id, no flag
at all).

**Flagged for R13.3/R13.5/R13.8**: any further subcommand nested under
`session` that redeclares a flag `session` itself already owns will hit this
exact bug. Either read it via `command.parent.opts()` as done here, or
declare it nowhere but the parent.

## What is NOT in scope here

The session host (R13.3), the transport (R13.5), continue/start flows
(R13.8). Branching (dropped by ADR-0007 Revision 1). Indexing transcripts
into the vector knowledge base — a searchable archive of every conversation
is a larger privacy decision than this ADR made. Syncing anything anywhere.
Anything about what `session-tree.ts` itself records — it keeps recording
hashes only, unchanged, sitting beside this store rather than being replaced
by it.
