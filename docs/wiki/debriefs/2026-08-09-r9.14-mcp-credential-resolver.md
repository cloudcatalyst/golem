# R9.14 — the MCP server could not authenticate to anything (2026-08-09)

Related: [[Configuration Surfaces]], [[R9.13 — a project that upgrades Golem fixes its own settings files]]

## Outcome

Asked to point `coder` at Anthropic's Sonnet 5. It already *was* pointed there —
`inference.worker_targets = {"coder":"sonnet-5"}`, and the `sonnet-5` target was
already `anthropic` + `claude-sonnet-5`. What it was not, was working: 401.

The 401 was not about Anthropic. `openrouter-qwen3` — a target `golem target
list` correctly reported as `key set — DPAPI-encrypted` — returned 401 too.
Decision 47 hands a credential to a process the CLI **spawns**, which is why
`credentialEnvForProxy` is called from the proxy start paths, `golem account`
and `golem init`. Claude Code spawns the MCP server itself from `.mcp.json`,
which has no `env` block, so the MCP process inherited no
`GOLEM_UPSTREAM_API_KEY__*`, `makeAuthMapper` returned `undefined`, and every
remote dispatch went out with **no auth header at all**. `coder --target
<anything credentialed>` had never worked.

`createTargetDispatcher` now takes an optional `resolveKey`, and `golem mcp
serve` installs one backed by `credentialEnvForProxy`.

## Key lessons

**A mechanism documented as "at spawn" silently excludes every process you
don't spawn.** Decision 47's env handoff is correct and its docstring is
accurate — it just describes a world with one child process. The MCP server
arrived later, spawned by somebody else, and inherited the *assumption* without
inheriting the *environment*. Worth asking of any handoff-at-spawn design: who
else runs this code, and who spawns them?

**The credentialed-target surface was honest and the dispatcher was not.**
`golem target list` said the key was stored, and it was. `golem target test`
probed it successfully. Both were true, and neither described what `coder`
actually did, because the checking path and the using path read the credential
from different places. A status surface can only vouch for what it itself does.

**A resolver, not more environment.** The obvious fix mirrors the proxy: call
`credentialEnvForProxy` at startup and set `process.env`. Five lines, and it
would work. It would also put N secrets in the environment of a process that
spawns capability probes and Ollama calls, all of which inherit it — the
"widened blast radius" `credentialEnvForProxy`'s own docstring accepts for the
daemon, taken on again somewhere it was not needed. Passing a closure keeps the
secrets in one function and out of every child. Resolution logic is still
`credentialEnvForProxy`'s, deliberately: a second implementation of the
store-id mapping would drift silently.

**No credential should fail by name, not by 401.** The dispatcher previously
sent an unauthenticated request and surfaced whatever came back — for this bug,
a bare `401 Unauthorized` naming neither the target nor the account nor the
missing key. It now refuses before the network when the resolved scheme needs a
credential and none resolves. `auth_scheme: inherit` still dispatches with no
header, because that is a configured choice rather than a missing secret.

**Five existing tests had encoded the bug as acceptable.** They passed `env: {}`
while dispatching to a credentialed target — incidental to what they were
testing (redaction, restoration, transport), but it meant the suite had been
asserting that an unauthenticated dispatch is fine. Making the dispatcher refuse
turned them red, which is the test suite doing its job.

## Verification

`tsc --noEmit`, `biome check`, full suite **2491 passed** (+4 new, 5 fixtures
corrected). Live-verified against the built `dist/`, using the exact resolver
`golem mcp serve` installs:

```
resolveKey("openrouter-qwen3") -> <73 chars>
resolveKey("anthropic")        -> undefined (no stored credential)
process.env leak check: no GOLEM_UPSTREAM_API_KEY* in env

--- live dispatch to openrouter-qwen3 (was 401) ---
model: qwen/qwen3-14b | text: "ok"

--- live dispatch to sonnet-5 (no key stored yet) ---
refused: target "sonnet-5" needs a credential and none resolved for account
"anthropic". Store one with `golem account login anthropic`.
```
