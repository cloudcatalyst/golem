# T3 — distillation engine + lazy webcache distill

`docs/plan/next_batch.md`'s W3a: a raw webcache page should become a
wiki-shaped, model-authored source-note draft — in the model's own words,
citing the source, with candidate wikilinks limited to pages that already
exist — rather than a raw mirror sitting in the vector index forever. Zone 1
(`Distillation Pipeline`'s "Stage 2") was the missing piece between capture
(T4) and promote (plan-gated, unchanged).

## What changed

- `src/knowledge/distill.ts` (new): `distillPage(inference, {url, rawText,
  existingTitles})` calls `InferenceService.chat("summarizer", ..., {
  jsonSchema })` — the first real caller of the frozen `jsonSchema` option —
  and validates the response with zod (`distillResultSchema`). Slug is
  kebab-cased from the model's slug, falling back to the title if that's
  empty after normalizing. Wikilinks are filtered to case-insensitive matches
  against `existingTitles` and rewritten to their canonical casing; anything
  the model invents is silently dropped rather than trusted. Invalid JSON or
  a schema mismatch raises `DistillParseError` carrying the raw model output,
  never a partial/garbage write.
- `src/knowledge/distill-store.ts` (new): `writeDraftFile(projectDir, url,
  draft, nowIso)` writes `.golem/distill/<slug>.md` — zone 1, gitignored,
  already wiki-shaped (`type: "source"`, `sources: [url]`, reusing
  `parseFrontmatter`/`serializeFrontmatter` from `src/wiki/frontmatter.ts` so
  promoting a draft later is a copy, not a reformat). `stripKnownSecrets` runs
  on the summary before writing — belt-and-suspenders, since the webcache
  input is already fully redacted by `runWebFetchPost`'s pipeline, but the
  model's own phrasing is never trusted blindly onto disk. `findDraftByUrl`
  scans drafts for one whose `frontmatter.sources` contains the URL, making
  distill idempotent by URL rather than needing a separate index.
- `src/cli/distill.ts` (new): `distillOne({projectDir, url, force?,
  inference?, nowIso?})` — thin, testable business logic following the
  `notes.ts`/`ollama.ts` convention (CLI action in `main.ts` stays a thin
  wrapper). Prefers an existing draft over re-distilling unless `--force`;
  constructs `OllamaInferenceService` via the same
  `OllamaClient`/`detectCapability`/`createProbeRunner` pattern as `mcp
  serve`/`proxy start`, degrading to a clear `InitError` (not a crash) if no
  local model is reachable or the URL isn't cached yet.
- `src/cli/main.ts`: registered `golem wiki distill <url>` with `--pending`
  (list drafts), `--force`, `--json`, `--dir`.
- `src/hooks/web-fetch.ts`: `runWebFetchPre` now checks `findDraftByUrl` on a
  cache hit and appends a one-line pointer ("a distilled source-note draft
  for this URL already exists at ...") to the served reason — lazy backfill
  per Decision 29, never triggers a distill itself, wrapped in its own inner
  `try`/`catch` so a bug there can't regress the hook's cache-serve path.
- `src/cli/skills.ts`: `/golem/wiki-ingest` now runs `golem wiki distill
  $ARGUMENTS` as step 2 (before the manual-distill/approval/write steps), so
  Claude reviews an existing local-model draft instead of re-distilling from
  scratch.
- Wiki: refined `Distillation Pipeline`'s Stage 2 (built, not planned) and
  `Wiki-First Knowledge`'s new "Zone 1 -> zone 2 data flow" section
  (append-and-refine, per Decision 29 — no wholesale rewrites).

## Design notes

- Idempotent-by-URL via `findDraftByUrl` rather than a separate distill
  index or MCP tool — one less moving part, and the wiki-shaped frontmatter
  already carries the URL in `sources`.
- Distillation covers webcache/URL input only, not `notes.jsonl` — captured
  notes still go through manual distillation. Extending to notes is a
  natural T3 follow-up but wasn't in this task's scope.
- Redaction floor is belt-and-suspenders on the summary, not the primary
  control: the primary control is that webcache input is already
  pipeline-redacted before it's ever cached (unchanged, never reordered).
