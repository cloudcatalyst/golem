# R12.5 -- the companion app is the dashboard that already existed, bound one interface wider

## Outcome

A phone on the same network can read a Golem project's state: what is blocked
and the exact tool call being waited on, the savings figures, the compression
dial. It is installable to a home screen, it goes visibly dead when the network
does, and **it can answer nothing** — no form, no button, no input, no write
route, every method but GET/HEAD refused on every path.

No new dependency. The runtime is still five.

## What it actually took

Almost none of this was new UI. R12.11 reduced the task to capability 1
(observe) because Anthropic's channel relay already carries remote *authorize*
first-party, so the genuinely novel thing this task might have built — an
approve/deny surface — was subsumed rather than needed. What was left was four
things the existing dashboard was not:

1. **Reachable.** `startDashboard` bound `127.0.0.1` and nothing else, which is
   the one address on the machine a phone definitely cannot reach. Now `host`
   defaults to loopback and `LAN_HOST` is an explicit opt-in
   (`golem dashboard --lan`, or `telemetry.dashboard_lan`).
2. **Phone-shaped.** 2rem of padding and a 60rem column is a fine dashboard and
   an unusable phone screen. Mobile-first now, widening at a 40rem breakpoint.
3. **Installable.** A real web manifest and real PNG icons.
4. **Honest about being disconnected.**

## Key lessons

- **The security argument for a LAN bind has to be structural, or it is not an
  argument.** "Read-only" is not a policy this server checks — it is the absence
  of a route plus a method guard, and the test asserts 405 for four methods
  across five paths rather than once, because a softened guard is what would
  quietly turn a read surface into something else.
- **`0.0.0.0` is a bind target, not a destination.** A LAN mode whose only output
  is `http://0.0.0.0:4654/` and `http://127.0.0.1:4654/` is a feature the user
  cannot use. `lanUrls()` enumerates what a phone can actually type, IPv4 first,
  skipping internal and link-local IPv6 (`fe80::` needs a zone index that means
  nothing on the phone — printing it would be printing something that cannot
  work).
- **A PNG is a handful of CRC'd chunks around a zlib stream, and `node:zlib` is
  built in.** An installable app needs raster icons; Golem ships no binary assets
  and no build step, and adding an image library for three icons would be a
  dependency for a decoration. ~130 lines generates them instead, supersampled
  3x3 so the hexagon's diagonals do not stair-step. The test decodes the result
  — signature, `IHDR` dimensions, `IEND` — rather than asserting that some bytes
  were served.
- **iOS ignores the web manifest.** It reads `apple-touch-icon` and the
  `apple-mobile-web-app-*` meta tags, so both mechanisms ship. Knowing which
  platform reads which is the whole of "installable on at least one platform".
- **No service worker, deliberately.** It needs a secure context, and over plain
  HTTP on a LAN it cannot register — but the better reason is that a caching
  service worker is a machine for showing stale data, and this task's gate is
  *"pulling the network shows a disconnected state rather than stale data"*. The
  two were in direct conflict; the gate wins.
- **A silent retry loop IS stale data.** The old poller caught fetch failures and
  tried again next tick, leaving the last good numbers under a live-looking
  header. Now three missed polls greys the readout and shows a "not connected"
  banner, and `visibilitychange` re-ticks on resume — an installed app coming
  back from the background has been asleep, not connected.
- **Put the sentence where the control is not.** The brief asked for a line
  saying the screen cannot start a turn. Since the reduction also removed
  approve/deny, the version that shipped says the honest thing for what actually
  exists: *"This screen is read-only. There is no prompt box and no approve
  button — nothing here can answer the agent or start a turn."*

## What this could NOT prove

R12.5's gate says "installable to a home screen on at least one platform,
**verified on a real device**". No test in this repo holds a phone. Everything
mechanically checkable was checked, including a live run over a real LAN address,
but `display: standalone` actually suppressing browser chrome, iOS using the
`apple-touch-icon` instead of screenshotting the page, and whether a 6s stale
threshold reads well when you walk out of Wi-Fi range are all facts about a
device. Filed as **R12.14** (`owner: user`).

## Gate

`tsc --noEmit`, `npm run lint`, `npm run format:check`, `npm run verify:deps`,
`golem wiki check` all exit 0. `npx vitest run`: **3137 passed / 2 skipped /
0 failed**. +16 tests. Live run: bound `0.0.0.0`, served over
`http://192.168.0.20:<port>/`, manifest `application/manifest+json`,
`/icon-180.png` 936 bytes and decodable, `POST /api/stats` → 405.
