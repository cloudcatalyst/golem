# 2026-08-20 — R10.24: two status lines, one truth

A user read Golem's two status lines side by side in one VS Code window and
listed, in a single sentence, five things wrong with them. Every one was real.

Related: [[Architecture]], [[The error frame Golem threw away]] (the previous
batch, same honesty rail), [verification-notes §130 / §131].

## What they saw

```
CLI:        ⬢ Golem · → ✎ qwen2.5-coder:7b · ◆ anthropic (claude-opus-5) · 🗜 lossless · ✂ full
status bar: ⬢ Golem · Lossless → ✎ qwen2.5-coder:7b · ◆ anthropic (claude-opus-5)
```

The dial is after the destination in one and between brand and arrow in the
other. The arrow — which means "where this conversation goes" — lands on the
model that DRAFTS, because both renderers printed diverging workers before the
chat model. And in the status bar an OpenRouter target read
`deepseek (deepseek-v4-flash)`: the vendor parsed out of the model id, naming a
company Golem never talks to, while the one fact the reader needs — which of
their gateways is carrying this traffic — was nowhere on the line.

## The interesting part: what a narrow pin bought us

The two surfaces share no module on purpose (the extension must not import the
CLI's graph). Since R9.4 a test has pinned the ROLE GLYPHS they use, with a
comment saying "change both together; a test pins that they agree".

That test worked. The glyphs never drifted. Everything around them did — segment
order, label semantics, model precedence, how many proxy states exist, and which
glyph the bypass shim gets. **A narrow pin does not just miss the rest; it makes
the rest feel covered.** The presence of `role-marks-parity.test.ts` is exactly
why nobody thought to check the shape.

So the fix is a test that renders equivalent state through BOTH implementations
and demands one identical string. It found something no human had reported: the
CLI drew the redaction-only bypass shim as a **filled green hexagon**, identical
to a fully-running pipeline — the one thing Decision 56 exists to distinguish.

**When two implementations of one surface cannot share code, the test is the only
place the contract can live — so pin the OUTPUT, not the constants.**

## The second lesson: a dial that cannot act must not be displayed

Both surfaces printed the configured compression and brevity while the proxy was
stopped, unwired (running, with Claude Code talking straight past it — R8.32), or
serving the bypass shim. R8.32 had established this for the glyph and Decision 56
for the label; neither reached the dials. So the most confident-looking part of
the line kept advertising transforms that no stage was running.

The states are now NAMED — `off`, `unwired`, `bypass`, and nothing when simply
running — in one vocabulary on both surfaces, and the dials appear only while
they are in force. Naming matters because colour and glyph-fill are unreadable
under `NO_COLOR`, in a screenshot, or to anyone who has not memorised ⬢ against
⬡.

While updating the tests we found this, from R8.32:

```ts
it("does not claim a compression level when Golem is not in the path", () => {
  expect(line).toContain("aggressive");   // ← the claim the name forbids
```

A test that was green, precise, and pointed at the wrong behaviour. **Read the
test name against its assertion**; agreement is not automatic.

## The picker could not pick a model, and the reason was one missing verb

`inference.default_target` is a TARGET selector. R9.1 resolves targets
(`<gateway>:<model>`), R9.2 routes per target, R10.8 made the leaf the chat
fall-through — and the only writer, `useGateway`, rejected target ids. So a
gateway fronting two models could be selected only as a whole, and selecting it
served `models[0]`. With `openrouter` fronting a qwen and a deepseek entry, the
deepseek model was unreachable from every UI *and* the CLI.

Nothing failed loudly. The picker simply offered one of the two models the user
had configured, and `gateway list` reported that model as the gateway's model
however they had switched.

**A setting named after a concept must accept that concept.** The registry and
the router spoke targets; the writer spoke gateways; the gap presented as a UI
that "doesn't show the picker correctly".

## Left open, deliberately: the slider

The fifth point — *"I'm confused about what the slider means vs compression. I
feel we don't need the slider any more"* — is a design question, not a defect,
and the confusion is earned. `slider.level` is a **preset over two dials**
(Decision 52), so two controls describe one thing and the status line must show
both. And on a caching upstream — the default — Decision 31 gates the semantic
stage off, so **levels 2 and 3 are inert**: this user's machine reads
`slider 3 (aggressive)` while effective compression is `1 (lossless)`. The
surface is being honest; the control is the problem.

379 references across 63 files, a config leaf needing migration, the `level` MCP
tool, and level 0's redaction bypass (a CLAUDE.md hard rule that would have to
move somewhere explicit) all hang off it. That is its own task and its own
decision, so it stays a question rather than a drive-by.
