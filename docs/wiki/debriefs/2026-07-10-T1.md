# T1 — wire ccrRefsRetrieved telemetry

`golem stats` / the dashboard always reported `ccr_refs_retrieved: 0` from
durable telemetry — `JsonlTelemetryStore.aggregate()` hardcoded it
(verification-notes §25). Retrievals happen in the `expand` MCP tool's
`retrieve()` path, which runs in the MCP server process — a different process
from the proxy that calls `compress()` — so the in-memory counter on
`NativeLosslessCompression` (`src/compression/native-lossless.ts`) that
already tracked retrievals per-account never reached durable storage and was
lost whenever that process exited.

## What changed

- `TelemetryEvent` (`src/telemetry/types.ts`) gained two optional fields:
  `kind?: "request" | "retrieval"` (absent === `"request"`, so every event
  ever written before this change still parses and counts the same way) and
  `ccrRefsRetrieved?: number`.
- `recordRetrieval` (`src/telemetry/index.ts`) persists a `kind: "retrieval"`
  event — deliberately not a pipeline event: no policy ran, no tokens were
  saved, and it must not count toward `requests`.
- `JsonlTelemetryStore.aggregate()` now branches on `kind`: a retrieval event
  adds to `ccrRefsRetrieved` and is otherwise skipped (no `requests`/token
  accounting); everything else works as before.
- `mcpCompressionService` (`src/cli/mcp-compression.ts`) wraps `retrieve()`
  to call `recordRetrieval` after a successful live retrieve, fire-and-forget
  (same pattern `recordPipelineEvent` already uses on the proxy side) — a
  telemetry write must never fail the retrieve the model is waiting on.

The `kind` discriminator was the key design decision: without it, a
retrieval-only JSONL line would have inflated `aggregate().requests` (which
counts one per line) even though no pipeline request happened.

## Verification

New tests: `tests/unit/telemetry/jsonl-store.test.ts` (retrieval events
count toward `ccrRefsRetrieved` without inflating `requests`, are scoped by
`projectId`, and old lines with no `kind` field still parse as requests) and
`tests/unit/cli/mcp-compression.test.ts` (an actual `compress()` → `retrieve()`
round trip durably records the count, checked via a fresh `JsonlTelemetryStore`
reading the same file — not through `stats()`, since a retrieval alone
deliberately doesn't clear `statsSourceForCli`'s requests-based
telemetry-vs-live threshold). Full gate: `tsc --noEmit`, `npm run lint`,
`npm run format:check`, `npm test` (70 files / 670 tests) all clean.
