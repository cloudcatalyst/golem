# R8.S3 — Session tree recorder + CLI (spike)

**Verdict: shipped as spike only.** Recording + `golem session tree` view. No actuation — Decision 37's limit stands.

Related: [[Context Ledger]], [[Dogfooding Golem]].

## Goal

Golem sees every request, so it can reconstruct a conversation's shape — including branches after a rewind. Pi's `/tree` feature, minus the half Golem cannot do.

## What shipped

**`src/session/session-tree.ts`** — `SessionTreeRecorder`:
- Observes request bodies via the pipeline's `sessionRecorder` option
- Builds a tree from content hashes (SHA-256 of first user message)
- Detects forks and branches by tracking parent hashes
- Persists to `.golem/state/session-tree.json`
- Storage is bounded: latest-N, not forever

**`src/cli/commands/session.ts`** — `golem session tree`:
- Renders the recorded tree with branch/fork annotations
- Shows timestamps, depth, hash prefix

**Wired into pipeline** via optional `sessionRecorder` in pipeline options, invoked from `onEvent` handler.

## Hard constraints observed

| Constraint | How met |
|---|---|
| No prompt content stored | Hashes only — same standard as `cache-prefix.ts` and context ledger |
| Better identity than cache prefix | Content-hash per node, not `messages[0]` hash (which collided in R8.13 at 98%) |
| Bounded storage | Latest-N capped, oldest evicted |
| No actuation | `golem session tree` only. Relaunch is `claude -p --resume <id>` (R5.1's command builder) |

## Tests

10 unit tests in `tests/unit/session-tree.test.ts`. Recording, branch detection, fork detection, persistence round-trip, bounded-storage eviction. No integration tests — the spike deliberately avoids wiring into the proxy's e2e flow.

## What remains unbuilt

- Session sharing or gists
- Replacing Claude Code's own resume
- Re-launch from within Golem (blocked by Decision 37)
