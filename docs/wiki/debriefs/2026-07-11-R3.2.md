# R3.2 — real HTML/PDF text extraction for ingest

**Before:** `.html`/`.rst`/`.txt` all routed through the plain-text window
chunker with raw markup intact (tags, `<script>`/`<style>` content, comments
all indexed verbatim). `.pdf` wasn't even in `isChunkableExtension` — PDFs
were silently skipped by ingest entirely, never read or chunked.

## What was built

- `src/knowledge/extractors.ts` (new file, sibling to the chunkers, not
  inside them): `extractHtmlText` (dependency-free regex-based tag
  stripper — drops `<script>`/`<style>` content and comments, breaks lines
  at block-element boundaries, decodes named + numeric entities, collapses
  blank-line runs) and `extractPdfText` (uses the optional `unpdf` package
  to pull the merged text layer of a PDF).
- `chunker.ts`'s `isChunkableExtension` extended to include `.pdf`.
- `ingest.ts`'s two content-reading call sites (`planIngest`,
  `chunkFilesRelativeTo`) now go through a new `readChunkableContent`
  helper that dispatches by extension before handing text to the chunker.

## Design decisions

**Extraction lives outside `chunker.ts`, not inside it.** The chunker
module's own doc comment commits to "pure TS, zero dependencies" — adding
`unpdf` there would break that invariant. Extraction runs as a distinct
step before chunking; the chunkers still only ever see plain text.

**`unpdf` over `pdf-parse`/`pdfjs-dist` directly.** Confirmed via `npm view`
(dependencies/peerDependencies/peerDependenciesMeta) that its only
dependency, `@napi-rs/canvas`, is an **optional** peer used solely by a
`renderPageAsImage` helper this repo never calls — so the default install
stays free of native/GPU deps (CLAUDE.md's hard rule). ESM-native exports
were the other deciding factor (repo is ESM-only, Node ≥ 22).

**Defensive `Uint8Array` normalization inside `extractPdfText`.** unpdf
rejects a Node `Buffer` outright with an explicit error, even though
`Buffer` is technically a `Uint8Array` subclass — discovered via a
throwaway debug script reproducing the exact ingest failure. Fixed once,
inside the function itself (`new Uint8Array(data.buffer, data.byteOffset,
data.byteLength)`), so every current and future caller is protected rather
than requiring callers to remember to convert.

**Test fixtures use hand-crafted minimal PDFs, not real binary files.** A
bare single-page PDF text object with a deliberately omitted/invalid
`xref` table still parses via pdf.js's fallback object-scanner (logs
`Warning: Indexing all PDF objects` to stderr, recovers anyway) — verified
empirically before committing to the technique, avoiding the need to check
in or generate a real PDF binary for tests.

## Verified

`tsc --noEmit` clean, `biome check .` clean, full `vitest run` — 87 files /
818 tests, all green (7 new extractor unit tests + 2 new ingest-traversal
tests covering `.html` and `.pdf`).
