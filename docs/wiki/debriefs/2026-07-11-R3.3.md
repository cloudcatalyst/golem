# R3.3 — opt-in tree-sitter WASM syntax-aware chunker

**Before:** all code files (`.ts`/`.js`/etc.) were split by `chunker.ts`'s
pure-TS `chunkCode` — a line/column window heuristic with no awareness of
function or class boundaries, so a chunk could cut a function in half.

## What was built

- `src/knowledge/tree-sitter-chunker.ts` (new file): `chunkCodeSyntaxAware(ext,
  content): Promise<RawChunk[] | null>` — parses `.ts`/`.mts`/`.cts`/`.tsx`/
  `.js`/`.jsx`/`.mjs`/`.cjs` via `web-tree-sitter` WASM grammars, one chunk per
  top-level declaration (oversized nodes still fall through to `chunker.ts`'s
  `windowChunks`). Returns `null` — never throws — on any failure: package
  absent, WASM init failure, unsupported extension, parse error.
- `knowledge.syntax_aware_chunking` config leaf (default `false`), threaded as
  an optional parameter through `ingest.ts` → `knowledge-base.ts` → `index.ts`
  → `build-knowledge.ts`. Off by default; the heuristic chunker is unaffected
  unless a caller opts in.
- `chunker.ts`'s internal `windowChunks` exported for reuse (oversized-node
  fallback) instead of duplicating the windowing logic.

## Design decisions

**`web-tree-sitter` + grammar packages are `devDependencies`, not
`dependencies` or `optionalDependencies`.** This was already the blessed shape
per `verification-notes.md` §27 (pure-TS `chunkCode` as the P1 default,
WASM tree-sitter as the documented opt-in, native bindings rejected outright)
— R3.3 needed no new design decision, just matching it. `optionalDependencies`
were briefly considered and rejected: npm installs them by default on a plain
`npm install` (unless `--omit=optional`), so that wouldn't have honored
CLAUDE.md's "never in the default install" rule. `devDependencies` gives real,
testable, offline packages for this repo's own CI while shipping zero
footprint to `golem-run` consumers — the exact pattern the Headroom sidecar
already established (never in `package.json`'s shipped surface at all).

**Grammar `.wasm` files are resolved via `createRequire(...).resolve(pkg/package.json)`,
not `import.meta.resolve`.** Plain Node ESM supports `import.meta.resolve`
natively, but vite-node (which backs vitest) doesn't implement it —
`__vite_ssr_import_meta__.resolve is not a function` surfaced only under the
test runner, not in a standalone Node probe script. `createRequire`'s
resolver works identically in both environments, so it was the correct fix
rather than a test-only workaround.

**Type-only import of `web-tree-sitter`'s types.** `import type { Language,
Node as TsNode } from "web-tree-sitter"` is erased at compile time — no
runtime cost, and since these types never appear in `chunkCodeSyntaxAware`'s
exported signature, they don't leak into consumers' `.d.ts` resolution either.

new ingest-traversal tests covering the opt-in flag on and off).
