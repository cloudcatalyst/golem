# R9.3 — `coder` runs on any target (2026-08-09)

Related: [[R9.1 — the target registry, and the config that was already one]],
[[R9.2 — the proxy serves many targets, and the one Pool that stopped it]],
[[R8.33 — a tool call could turn redaction off, and only warn afterwards]].

## The finding that shaped the task

`src/mcp/` contains **no redaction calls at all**, and that was correct. While the only
model `coder` could reach was local, nothing left the machine, so there was nothing to
redact against.

The moment `coder` can name a remote target, that stops being true: it becomes an **egress
path that bypasses the proxy's redaction stage entirely** — carrying exactly the material
most worth redacting, since `coder` grounds its drafts in KB and wiki hits and, in edit
mode, project source.

So redaction could not be a follow-up slice. It ships in the same change as the `target`
parameter, and it is enforced structurally rather than by discipline: `dispatch()` has
exactly one non-local code path, and that path cannot reach the network without passing
through `redactReversibleText` first.

## The frozen contract was not amended

`src/interfaces/inference.ts` is frozen, and its doctrine is that *callers never name
concrete models* — dispatch is role-based through the tier catalog. A `coder` that names a
target contradicts that head-on.

The resolution was to leave the contract alone and put `TargetDispatcher` **above** it:

- no target, or a `local`-trust target → delegate to `InferenceService` exactly as today
- any non-local target → redact, dispatch, restore

`InferenceService` keeps its precise present meaning. Nothing about the local path changed,
which is why the whole existing test suite was untouched by this task.

## Redaction had to become reversible, without becoming weaker

A draft full of `[REDACTED:anthropic-key:1]` is worthless, so the round trip is part of the
requirement. `redactReversibleText` is a new entry point beside `redactStandaloneText`,
using the **same rule table and the same per-value placeholder allocation**; what crosses
the wire is byte-identical to what the existing function would have produced. The
restoration map lives in memory for one dispatch and is never serialized, stored, or
logged.

Per-VALUE numbering (not per-occurrence) is what makes restoration total: one secret
appearing three times is one placeholder used three times, so putting it back is
unambiguous. Placeholders carry their closing bracket, so none is a prefix of another
(`[REDACTED:x:1]` cannot match inside `[REDACTED:x:11]`) and restoration needs no ordering
care.

## Trust may raise the floor. It may not assert its way past physics.

`trust: "local"` is the only value that permits the unredacted path — and it is honoured
**only when the endpoint is genuinely loopback**. A target declaring `trust = "local"` on
`https://api.openai.com/v1` is refused that path and redacted like anything else.

This is the guard that matters most, because `trust` is user-authored config. A typo, or a
copy-pasted target block, would otherwise silently convert a redaction bypass into an
egress. Config gets to be more cautious than Golem's default; it does not get to be less.

A test pins it: a remote target claiming `trust: "local"` still sends redacted bytes, and
never touches the local service.

## The gate, as a recorded proof

The task's gate is that no secret leaves for a non-local target while the draft comes back
usable. The tests assert on the **bytes actually captured** from the outbound request, not
on the code path:

- the dispatched payload contains neither the key nor the address, and does contain
  `[REDACTED:`
- the stub echoes the redacted prompt back, and restoration reproduces the original
  **byte for byte**
- the audit record carries the target, provider and trust, and neither the account key nor
  the prompt's secrets

A fixture detail worth keeping: every secret is assembled at runtime. Writing a literal key
into the test file gets it redacted by tooling before the test ever runs, and writing a
literal `[REDACTED:…]` placeholder is worse — redaction is idempotent over it, so the test
passes while proving nothing. The first draft of this file did exactly that, and the gate
test passed for the wrong reason until the fixture was fixed.

## What the tests caught

`upstreamChatCompletionsPath` returns a **path**, because it was written for undici, which
takes origin and path separately. The dispatcher uses `fetch`, which needs an absolute URL.
The transport test failed on `/api/v1/chat/completions` vs the full URL — a bug that would
have broken every remote dispatch against a real endpoint and could not have been caught by
any amount of reading.

## Selection is bounded by the schema itself

The `target` parameter is a **zod enum** built from the targets config declares and marks
`agent_selectable` (default true — declaring a target is already a deliberate act, so
per-target opt-in would be ceremony without safety). An ad-hoc URL or an account name is
not expressible, so "can never reach anything undeclared" is visible in the tool definition
rather than enforced somewhere downstream.

The parameter is only added when there is more than one target to choose from. `coder`'s
definition bills on every request (§110), so a choice-free parameter would be pure cost.

Refinement deliberately stays on the local service: it is a cheap critique loop, and sending
the draft out a second time would double the egress for no benefit the target was chosen
for.

## Verification

`tsc --noEmit`, `biome check` (457 files), full suite **2374 tests** (+14), 14 of them this
task's.

**Not verified live.** The gate's "completes a draft on a remote target" half was not run:
it would dispatch a real request to a third-party provider on the user's credential, which
is an outward act. Every layer beneath it is covered by tests against a captured transport,
and the local-coder setting was left disabled exactly as found.

## Lesson

The security-relevant work in this task was not the feature — it was noticing that a
module's *absence* of redaction had been correct for a reason that this change quietly
invalidated. `src/mcp/` had no redaction because it had no egress. Adding one line of
capability turned a sound omission into a hole.

The narrower version: **when you give an existing component a new reachable destination,
re-derive the assumptions that justified what it does not do.** The dangerous edits are the
ones that make previously-true comments false without touching them.
