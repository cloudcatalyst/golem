# R13.5 -- the wire, and two limits that disagreed

## Outcome

A paired device can attach to a hosted session over SSE and receive assistant
text, tool calls and tool results as they happen; POST a message and be told it
was delivered only once it actually was; drop the connection and resume with no
loss and no duplication; and be *told* — never left to infer — when the session
ends or parks. See [[Session Transport]].

Verified live end to end: `golem session host serve` prints its stream and
message URLs, and both routes answer an unpaired caller with
`device:no-certificate` rather than serving anything.

## Key lessons

- **Two limits that disagree are worse than either.** R13.4's server capped
  request bodies at 8 KiB — right for an enrolment claim, which is what it was
  sized for — while R13.5 promised a 32,000-character message. The smaller cap
  won silently, and worse, it won by **destroying the socket**: at the client an
  oversized message was indistinguishable from the server crashing or the network
  dropping. Fixed on both counts: the server's cap moved well above anything a
  mounted handler may accept, so the handler's own limit is the one that speaks,
  and overflow now answers `413` with the limit named instead of hanging up.
  Found by a test, which is the only reason it was found at all.
- **A gap must be reported, not smoothed over.** The replay ring is bounded, so a
  client that was away long enough cannot be given everything. Telling it
  `gap: true` costs one boolean; not telling it means the user reads a continuous
  conversation that is missing a turn. *A gap the user can see is recoverable; a
  gap they cannot is a conversation they will misread.*
- **Silence has to mean something definite.** Without heartbeats a client cannot
  distinguish a live-but-quiet session from a dead socket, and would have to
  guess — the exact inference the event contract forbids. With them, silence
  means "still here" and every ending is an explicit event.
- **Acknowledge delivery, not receipt.** ADR-0007 §3b makes injection
  acknowledged; a POST that returned 200 on accepting the bytes would have undone
  that in one line. It resolves only after the turn reaches the session, and a
  refusal is a 502 rather than a cheerful success.
- **A duplicated instruction to an agent is not a duplicated packet.** Retrying a
  dropped POST is normal; making the agent act twice is not. The `messageId`
  ledger is a retry window, not a history — bounded, because a client retrying an
  id from an hour ago is not retrying.
- **Backpressure drops the client, never the session.** One phone's slow radio
  must not stall the agent. The ring still holds what a dropped subscriber
  missed, so the cost is a reconnect rather than data — trading the other way
  would buy convenience with a correctness property.
- **Name the wire in `src/interfaces/`.** R13.6 and everything after code against
  these shapes; leaving them implicit in a server file would make every future
  client an archaeology exercise.

## A test-suite finding, unrelated to the feature

`tests/unit/runtime-assets-drift.test.ts` began failing about half the time — as
a **timeout**, never as a wrong answer. It walks the whole of `src/` and reads
every `.ts` file, twice; measured at ~500ms alone and **6.1s** inside a full
parallel run, which put it close enough to the 5s default to flip a coin. This
task's new files pushed a pre-existing fragility over the line rather than
causing it. Raised the ceiling for that file only, with the measurement in the
comment, following `cli-init.test.ts`'s precedent. Four consecutive clean full
runs afterwards.

Worth remembering as a shape: **a test whose cost grows with the codebase will
eventually fail on time rather than on content**, and it will look like a
regression in whatever happened to be merged that day.

## What is NOT here

The UI (R13.6). Starting or resuming sessions from a device (R13.8). Injection
into a live *harness* session (R13.7 — a different mechanism with its own
delivery semantics). Anything beyond the local network (invariant 9; R13.10).

Also still open from R13.3: a hosted session does not outlive the process that
started it, so `golem session host serve` is the process serving it.

## Gate

`tsc --noEmit`, `npm run lint`, `npm run format:check`, `npm run verify:deps`,
`golem wiki check` all exit 0. `npx vitest run`: **3245 passed / 2 skipped /
0 failed**, four consecutive clean runs. +14 unit tests, +14 integration tests
over the real mTLS server with real client certificates — because "the handler
refuses" and "the request never got there" are different guarantees.
