R6.2 spec 21d, built after ADR-0003 was accepted with the user's ToS scope
decision: **legitimate account/provider switching only** — the automated
quota-evasion half (21e-style limit-circumvention) is explicitly out.

## What landed

- **Config:** `proxy.accounts` — a NON-SECRET registry (`id`, `provider`,
  `base_url`, optional `model`/`auth_scheme`) — and `proxy.active_account`. The
  credential is **never a setting**: account `<id>`'s secret comes from env
  `GOLEM_UPSTREAM_API_KEY__<ID>`; the legacy single account keeps
  `GOLEM_UPSTREAM_API_KEY`.
- **`src/providers/accounts.ts`** — `resolveActiveUpstream` (pure): active unset
  → legacy top-level config; active found → that account (+ its env key,
  resolved auth); active set-but-unknown → **legacy + a warning, never a silent
  switch to a different registry account** (ADR-0003 fail-closed). A missing
  per-account key is surfaced downstream (401/warn), never swapped for another
  key. `perAccountEnvVar` uppercases/sanitizes the id.
- **`src/cli/accounts.ts` + `golem account list|use`** — `list` shows the
  registry, the active marker, and whether each key env var is **set** (a
  boolean — never the value); `use <id>|none` is fail-closed (rejects an unknown
  id) and appends a switch entry to `.golem/state/account-log.jsonl` (the ADR
  audit log). No MCP/tool surface reads or sets accounts (config/CLI only).
- **Proxy wiring** (`buildProxyFromSettings`): resolves the active account up
  front and feeds provider/base/model/auth/key into the existing R6.1
  auth-mapping + translation seams. One active account per proxy run.

## Verification

- **+15 tests**: resolver (legacy passthrough, account selection + per-account
  key, no cross-account/legacy key leak, unknown→fail-closed+warning,
  `perAccountEnvVar`) and CLI (list key-set flags with a no-secret-in-output
  assertion, fail-closed `use`, clear, audit-log line, render). Suite **1231**
  green (one unrelated `cli-init` concurrency flake, §68-class — green standalone
  3×). tsc/biome/format/wiki clean.
- **Live-verified** (§78): built a proxy from settings with
  `active_account:"local"` (Ollama) and hit it — HTTP 200, served by
  `qwen2.5-coder:7b`. The full path (registry → resolver → provider selection →
  translation → upstream) works end-to-end.

## Security posture (ADR-0003 invariants met)

Secrets never in settings/logs/telemetry/wiki (env-only; a `.golem/credentials.json`
was rejected — no plaintext-on-disk). Fail-closed selection (no silent re-route).
Audit log of switches. No tool surface. Redaction + Anthropic byte-fidelity
untouched (account selection is a transport concern, like R6.1 auth-mapping).

## Explicitly NOT built (ToS + scope)

- **Automated quota-evasion / route-on-exhaustion** — a 429 from the active
  account surfaces to the client as today; no hidden retry on another account.
- **Per-request capability/availability routing (21e)** — future; depends on
  21a escalation. v1 is one explicitly-chosen active account per run.
- **OS-keychain credential backend** — env-var-first shipped; keychain is a
  verified-future option (needs a light cross-platform mechanism first, ADR-0003).

## R6 state

R6.1 (case a + b) + R6.2 (account switching) + R6.4 shipped. Remaining R6: the
21e routing extension (own decision), R6.3 companion app (deferred), and live
cloud end-to-end checks (user-side, need real keys).
