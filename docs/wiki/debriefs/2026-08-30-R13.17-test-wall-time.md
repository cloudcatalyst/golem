# R13.17 -- the test suite's floor was one file, not the worker count

## Outcome

`checkpoint-ledger.test.ts` — 12 tests, one `describe`, each doing a real
`git init` + commit — was **51.4s of strictly serial work in a single file**,
out of a 53.0s wall for the four heaviest integration files. Split along its
seams into four `checkpoint-ledger-*.test.ts` slices sharing a
`helpers/checkpoint-repo.ts` fixture: **51.4s → 20.4s**, same 12 tests, same
assertions, nothing deleted.

Plus `test:changed` / `test:unit` / `test:full` scripts, so the full suite stops
running once per task and runs once at close-out, where the gate actually is.

Full suite after: **250 files passed / 1 skipped, 3266 tests, 85.18s, exit 0.**

## The lesson worth keeping

**Vitest parallelises across files, never within one.** No file in this suite
uses `.concurrent`. So the suite can never finish faster than its slowest single
file, and at the tail one worker grinds alone while fifteen sit idle.

That single fact explains a result this repo had already recorded but not
diagnosed: R10.1 measured every pool/worker configuration as *worse* than
baseline (threads+cap 141s, two-project split 195s + 6 failures, simple threads
209s). Those experiments could not have worked. **A worker count cannot
subdivide a file.** The floor was a partitioning problem the whole time, and
"config tuning is a dead end" was the right conclusion drawn from the wrong
model of the cause — which is why it never led anywhere.

Generalisable: when a parallel test runner stops responding to concurrency
tuning, stop tuning concurrency and go measure the *unit* it parallelises over.
See [[Dogfooding Golem]].

## What was deliberately not done

- **No `vitest.config.ts` pool/worker change.** R10.1's dead end stands.
- **No integration test deleted or thinned.** They carry R8.32/R9.4/R9.22, and
  they are the coverage that makes [[Change Ledger]] trustworthy. This was a
  re-partition: `git mv`-shaped, not a rewrite. Test count went up, not down.
- **No global `testTimeout` raise.** R10.2 forbids it. The per-file 90s ceiling
  the ledger tests already carried was preserved verbatim in each slice, with
  its justification — the slices are shorter, but an individual test's spawn
  cost under contention is unchanged.

## Two things found on the way

**`--changed` reruns everything when `package.json` is in the diff.** That is
vitest's `forceRerunTriggers` default (`package.json`, `vitest.config.*`,
`vite.config.*`), not a bug — but it means the first run of `test:changed` in
the very commit that *adds* `test:changed` looks like it does nothing. Written
into CLAUDE.md so the next person doesn't file it as broken.

**A file split collides violently with an in-flight branch.** The unmerged
`R13.16-skills-plugin-user-scope` rewrites `cli-init.test.ts` (+319 lines) and
`cli-status.test.ts` (+82). Splitting a file into six on one branch while
another rewrites it in place is not a resolvable merge. Those two splits — the
second-biggest win available — are **deferred inside R13.17's own doc** rather
than attempted, and wait on R13.16 landing. Cheap to notice, expensive to
discover late.
