# R9.15 — spending the subscription without borrowing its token (2026-08-09)

Related: [[R9.14 — the MCP server could not authenticate to anything]], [[Configuration Surfaces]]

## Outcome

R9.14 made `coder` able to authenticate to a credentialed target. The user then
asked the obvious follow-up: *what if I have no pay-as-you-go credit — can't we
use the quota I already have?*

Two routes existed and only one was honest. Golem now ships a `claude-cli`
target provider: a draft is produced by **spawning the user's own Claude Code
CLI**, which authenticates as itself. Golem never reads, copies or forwards that
credential.

## The line, and why it is where it is

The tempting route was near-free to build: Golem's proxy already sees Claude
Code's `authorization` header on every request it forwards, and the OAuth
credential sits in Claude Code's own store. Either could have been replayed
against `api.anthropic.com`.

Forwarding the user's own requests is Golem's entire job. Minting requests Claude
Code never made, on the credential issued to it, is a different act — and the
spec had already written the rule down (§267): *account switching is
user-initiated and transparent, not covert evasion of limits.* The distinction
that matters is not "whose quota" but **who originated the request**.

Spawning the official client keeps both sides true: the quota is the user's, and
every request is made by the client the credential belongs to. This is Decision
53's ladder applied to a credential rather than a binary — external tools are
spawned or detected, never shipped, and now never impersonated either.

## Key lessons

**The user's constraint was a guard that did not exist.** They described the
feature as firing "only when the coder model is different from the current model
and it isn't using a 3rd-party upstream". That was not how dispatch worked —
routing was purely "`worker_targets.coder` names this target", with no comparison
of any kind. Rather than correct the sentence and move on, both halves became
real guards, because both describe genuine failure modes: drafting on the model
the session already uses spends the same quota in a worse context, and drafting
through a spawned client while the session is fronted by a third party bills the
draft to a different account than the work. A user's mistaken description of
current behaviour is often an accurate description of desired behaviour.

**Both guards refuse; neither reroutes.** Falling back to the local model on a
guard failure would have been friendlier and wrong — it is the silent-substitution
class this dispatcher already refuses for unknown target ids. One exception,
documented: an unknown session model (no `served-model.json` yet) *allows* the
dispatch, because refusing on no evidence costs more than the waste it prevents.

**The prompt goes on stdin, and that is the whole safety property.** A drafting
prompt contains project source, KB grounding, and whatever a model wrote — the
worst possible thing to interpolate into a command line, especially on Windows
where a `.cmd` shim must be run through `cmd.exe /c`. Putting the prompt on stdin
means argv holds only fixed flags plus a model id (validated against a
conservative pattern), so there is no command line for it to escape from. The
Windows shim path then costs nothing in safety.

**Scrubbing the environment is not hygiene, it is routing.** `ANTHROPIC_BASE_URL`
is set in this project — it points Claude Code at Golem's own proxy. A spawned
client inheriting it would have looped back into Golem, been forwarded to
whatever upstream is configured (possibly a third party, the exact case guard 2
exists to prevent), and invited re-entrancy on hooks. Stripping `ANTHROPIC_*`
makes "this draft runs on your subscription" true by construction rather than by
hope. Stripping `ANTHROPIC_API_KEY` with it is deliberate: leaving it in scope
would make *which quota gets billed* depend on the user's shell.

**A spawn is an egress.** The redaction gate had exactly one non-local path and
now has two; both pass through `redactReversibleText` before anything leaves.
The test asserts on what the child actually received, not on the code path.

**Adding a provider is not free.** `defaultAuthScheme`'s exhaustive switch caught
it immediately — a new enum member is a new case everywhere the compiler can see,
which is the argument for exhaustive switches over defaults. One place the
compiler could *not* see: `proxy.upstream_provider` would have happily accepted
`claude-cli` and produced a setting that parses and cannot work. Split into
`PROXY_PROVIDERS`, enforced at config-load time.

## What it costs, measured

~6.5s per draft, cold, against a local model's sub-second — a whole Claude Code
session start each time. And it spends the **same pool** as the interactive
session, competing for the rate limit `snooze` parks on. It does not conjure
quota; it moves drafting into a fresh small context instead of the session's
large one. Whether that nets out is a measurement nobody has taken yet, so the
route is opt-in and the numbers are stated rather than implied.

## Verification

`tsc --noEmit`, `biome check`, full suite green — **2510 passed**, +10 from
`tests/unit/inference/claude-cli.test.ts`. The unit tests pin the negative
properties (no secret in argv, no `ANTHROPIC_*`/`GOLEM_*` in the child's
environment, redaction before spawn) using an injected spawn.

Live, through the adapter itself against the real binary:

```
LIVE: "ok" in 6482ms
```

An earlier hand-probe established the flags before any code was written:
`printf '<prompt>' | claude -p --model sonnet --output-format text
--no-session-persistence --strict-mcp-config` → `ok` in ~7.0s with
`ANTHROPIC_BASE_URL` unset.

## Using it

```
golem target add subscription --provider claude-cli \
  --base-url https://api.anthropic.com --model claude-sonnet-5 --trust vendor
golem config set inference.worker_targets '{"coder":"subscription"}' --scope local
# then restart Claude Code — the MCP server reads settings at startup
```

`base_url` is required by the target schema and ignored by this provider; it
records where the spawned client goes, which keeps `golem target list` honest.
