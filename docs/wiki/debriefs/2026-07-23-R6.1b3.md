Third slice of case (b), and the one that matters for coding agents: tools.
Without it, a Claude Code turn that calls tools against an OpenAI-schema upstream
loses its tool exchange. b3 maps tools faithfully in both directions.

## What landed

- **Request** (`anthropicToOpenAIChat`, rewritten): Anthropic
  `tools:[{name,description,input_schema}]` → OpenAI
  `tools:[{type:"function",function:{name,description,parameters}}]`;
  `tool_choice` (`auto`→auto, `any`→required, `none`→none, `{type:"tool",name}`→
  `{type:"function",function:{name}}`). Message translation now expands one
  Anthropic message into several OpenAI messages: an assistant turn's `tool_use`
  blocks → an assistant message with `tool_calls`; a user turn's `tool_result`
  blocks → one `role:"tool"` message each (emitted before any user text, since
  they answer the prior calls) keyed by `tool_call_id = tool_use_id`.
- **Response non-streaming** (`openAIChatToAnthropic`): `message.tool_calls` →
  `tool_use` content blocks (`input = JSON.parse(arguments)`, `{}` on bad JSON),
  after any leading text; `finish_reason:"tool_calls"` → `stop_reason:"tool_use"`.
- **Response streaming** (`OpenAIChatSSETranslator`, extended): Anthropic blocks
  are strictly sequential, so the translator now keeps exactly one block open and
  closes it before the next. Text → a `text` block; each OpenAI
  `delta.tool_calls[i]` → a `tool_use` block whose `arguments` fragments stream as
  `input_json_delta.partial_json`. `id`/`name` captured from the first fragment;
  parallel tool calls become sequential tool_use blocks.

## Verification

- **Unit:** +8 tests across request tools/tool_choice, message expansion,
  non-streaming `tool_calls`→`tool_use` (incl. bad-JSON args → `{}`), and
  streaming tool-call (`input_json_delta` fragments concatenate to the full JSON)
  + text-then-tool sequencing (indices 0 then 1, with the intervening
  `content_block_stop`). Suite ~1207 (one unrelated `cli-init` concurrency flake,
  §68-class — green standalone 3×). tsc/biome/format/wiki clean.
- **Live (best-effort) vs Ollama `qwen2.5-coder:7b`:** a request WITH tools was
  accepted and translated (HTTP 200), but the model returned the call as **text**,
  not a native `tool_calls` — so the `tool_calls`→`tool_use` path is
  **unit-verified, not live-verified** here. Native tool-calls depend on the
  backend model/server (Ollama tool support is model/version-dependent), not on
  Golem's mapping (verification-notes §76).

## Scope / interfaces

No frozen `src/interfaces/` change; no proxy change (b3 is entirely in the
`src/providers/` translation layer the b1/b2 seam already invokes). Images still
dropped. Anthropic passthrough untouched.
