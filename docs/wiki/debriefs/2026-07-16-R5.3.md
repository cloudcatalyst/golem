# R5.3 — Task/question queue + local conversation multiplexing (WS-F2+F8 / spec 20b, 21a)

Builds on R5.1's `TaskStore`. Lets the user enqueue prompts without blocking,
services overlapping conversations LOCALLY on the Ollama tier, and escalates to
Claude only where cloud quality is needed — explicitly, never silently.

## What shipped (`src/tasks/multiplex.ts`)

- **`serviceTaskLocally(task, deps)`** — run a queued task's prompt through a
  local role (default `drafter`), attach the output as `task.result`, mark it
  `done`, and add a checkpoint. Optional grounding (R4.2-style `ground` dep)
  folded into the prompt. The local model may append a `NEEDS_CLAUDE` marker,
  surfaced as a checkpoint note. **Fails open:** an unavailable model leaves the
  task `queued` with a recorded `lastError` — nothing lost, nothing crashes.
- **`runQueueLocally(store, deps, {concurrency, limit})`** — service the queue
  with bounded concurrency (default 2 — mirrors the drafter's single-flight
  discipline; keep small to respect the machine). Probes with the first task and
  **stops early if the local model is down** rather than hammering a dead
  endpoint. Persists every outcome. `mapWithConcurrency` is the small,
  order-preserving bounded pool underneath.
- **`escalateTask(task, grounding)` (21a)** — an EXPLICIT hand-off: fold the
  local first-pass result + any grounding into the prompt as context, mark
  `escalated`, and re-queue so `golem task resume` relaunches it to the Claude
  tier. Never called automatically (Decision 31 — escalation is an explicit act,
  like `coder`).
- **Task schema (+additive):** `result?` (local output) and `escalated` flag.
- **CLI:** `golem task run [--concurrency N] [--limit N]` and
  `golem task escalate <id>` (+ a `buildInferenceForDir` helper that returns
  null when Ollama is unreachable, so `run` degrades to a clear message).

## Verification

- +8 unit tests (service success/grounding/fail-open, `mapWithConcurrency`
  cap+order, queue run all/unavailable/empty, escalate folding). Full suite
  **1012 green**; tsc + biome clean.
- Driven end-to-end against the REAL local model: enqueued a task, `golem task
  run` serviced it locally (`qwen2.5-coder:7b`) and attached the result, then
  `golem task escalate` folded that pass into the prompt and marked it escalated
  (checkpoints: "serviced locally …; escalated to Claude tier").

## Notes / follow-ups

- No frozen interface touched (consumes the frozen `InferenceService`).
- **Grounding-injection during servicing** is supported by the multiplexer
  (`ground` dep) but not yet wired from the `task run` CLI (would reuse the MCP
  layer's `gatherGrounding`/`assembleHits`). Escalation already folds the local
  result, which is the primary handoff context; wiring KB grounding into `run`
  is a clean follow-up.
- A background auto-service daemon (watch the queue, service as tasks arrive)
  builds naturally on `runQueueLocally` — deferred with R5.1's auto-resume loop.
