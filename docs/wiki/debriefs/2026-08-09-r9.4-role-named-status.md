# R9.4 — status by role, and targets per worker (2026-08-09)

Related: [[R9.1 — the target registry, and the config that was already one]],
[[R9.2 — the proxy serves many targets, and the one Pool that stopped it]],
[[R9.3 — coder on any target, and the egress path that had no redaction]],
[[R8.32 — a running proxy nothing was pointed at]].

## The report

Immediately after R9.3 shipped: *"based on these changes, the status line and status bar
makes less sense."*

Correct. Both surfaces rendered `local (qwen2.5-coder:7b) + anthropic (claude-opus-5[1m])`,
a shape whose whole grammar encodes the assumption R9.1–R9.3 had just removed: **that
drafting is local and only the upstream is a real choice**. Once a draft can run on any
declared target, "local" is not a fact about the model — it is a leftover from when there
was nothing else to say.

This is the same failure family as [[R8.32]], one step milder: not a surface asserting
something false, but a surface whose *vocabulary* could no longer express the truth.

## Naming, and why two obvious words were wrong

The user asked whether the conversational model should be called the "thinker" or the
"reasoner". Neither, and the reason is local to this codebase rather than a matter of
taste: Golem already uses reasoning/thinking in a **narrow technical sense** —
`upstream_reasoning_effort`, `map_reasoning_to_thinking`, and mapping a provider's
`reasoning_content` into Anthropic `thinking` blocks. Either word would read as a claim
about reasoning traces, not about which model drives the conversation.

**chat** names the job, which is the convention the existing roles already follow
(`summarizer`, `extractor`, `classifier`, `drafter`, `judge`). A term of art that already
means something narrower in the same repo is worse than a plain word.

## The shape changed twice, and the second time was the important one

The first pass added `inference.coder_target` — a scalar, exactly as scoped.

Then the user mentioned they were considering more tool workers, *"like the coder, for
things like document writing, which would have its own default target for the writer."*
That single sentence invalidated the shape: a `writer` makes it `writer_target`, then
`reviewer_target`, each growing a schema leaf, a UI-model entry, a status field and two
status-surface branches.

It was reshaped into `inference.worker_targets`, a map keyed by worker name, before
release — the cheapest possible moment. **Adding a worker is now one line of config plus a
glyph**, and every surface renders N workers generically.

What a map gives up is per-key schema documentation, per-key env overrides, and — the one
that actually bites — a typo'd key being silently ignored. That last is bought back by
`KNOWN_WORKERS` + `unknownWorkerWarnings`, which reports `worker_targets."writer"` before a
writer exists rather than swallowing it. Deliberately a *warning*, not a failure: a config
typo must not stop the worker that IS configured correctly. An unknown **target** stays a
hard failure at dispatch, because that would send work somewhere the user did not choose.

## The line policy is "show what diverges"

Chat, plus only the workers whose model differs from it:

```
⬡ Golem · Passthrough → ✎ qwen/qwen3-14b · ◆ claude-opus-5[1m]
⬡ Golem · Passthrough → ◆ claude-opus-5[1m]          ← every worker agrees
```

Printing a worker that agrees with chat costs width and tells the reader nothing; the
interesting fact is always a divergence. It is also what keeps the line **bounded** as
workers accumulate — with a glyph each, it only grows when the user has actually pointed a
worker somewhere else.

The glyphs are placeholders the user will choose, isolated in one `ROLE_MARKS` constant per
surface. There are necessarily **two copies** (the extension is plain CommonJS sharing no
module with the TypeScript CLI), and two copies of a user-facing constant drift invisibly —
nothing fails, the surfaces just quietly disagree about what a symbol means. So parity is
asserted: same marks, each a single code point (a double-width glyph misaligns everything
after it on a per-turn status line), no two roles sharing one.

## Running it caught what reading it did not

With `coder_target` set to an id that resolves to nothing, `golem status` rendered:

```
Inference: coder qwen2.5-coder:7b (target ghost) · chat anthropic
  ⚠ inference.coder_target "ghost" is in neither proxy.targets nor proxy.accounts …
```

A model that can never run, attributed to a target that does not exist, **directly
contradicting the warning printed underneath it**. `coder` fails closed on an unresolvable
target, so the honest answer is that there is no coder backend at all. Both surfaces now
omit the worker entirely and say `FAILS CLOSED`.

The code read fine. The fallback chain (`target model ?? local model`) looked obviously
correct in isolation and was wrong precisely at the point where the target was broken — the
state nobody thinks to picture while writing the happy path.

## Verification

`tsc --noEmit`, `biome check` (460 files), `verify:deps` ok, **2394 tests** plus 50
extension tests. Verified live in a scratch project (never the user's own config) across
all four states: two models, flattened, unknown worker key, unresolvable target.

Deployed locally: rebuilt, proxy restarted onto the new build (pid 14520), and the VS Code
extension installed at 0.7.0 — it had been stuck at a registered **0.5.0**, so
`deploy:local` had been a no-op against a path that did not exist.

## Lesson

A vocabulary can go stale the same way a value can. The old status line was not printing a
wrong *number*; it was printing a wrong *grammar* — `local + upstream` cannot express "the
coder is on OpenRouter and chat is on Anthropic", so no amount of correct data would have
made it honest.

And the narrower one, twice over in this task: **the user's throwaway sentence about future
plans was the most valuable design input received.** "I'm considering a writer" arrived
after the scalar shipped and before it released, which is the only window in which
reshaping config is free.
