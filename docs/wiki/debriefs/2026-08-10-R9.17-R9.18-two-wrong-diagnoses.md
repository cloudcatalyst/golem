# R9.17 + R9.18 — two defects, three wrong diagnoses, and what fixed them

Related: [[R9.12 — the served-WebFetch red dot goes green, behind a CA that cannot lie]]
(the batch these surfaced in), [[Web Cache]]

**Date:** 2026-08-10
**Tasks:** R9.17 (coder-first gate), R9.18 (proxy restart false negative)
**Follow-up filed:** R9.20 (credential resolution latency)

## Outcome

Both defects fixed and verified by observation rather than reasoning:

- **R9.17** — the `local-coder` gate nudges **once per session** again. Proven live: the
  first non-trivial code write in this session was redirected, the next two went straight
  through. Guidance re-enabled.
- **R9.18** — **10 consecutive `golem proxy restart` runs, 10 successes**, each with a
  distinct new pid, where roughly one in three used to report `did not come up`.

## The thing worth remembering

**Every initial diagnosis in this batch was wrong, and each was wrong because it was
inferred from a symptom instead of measured.** All three were stated confidently, and two
of them were written into task docs as if settled.

| defect | first diagnosis | what measurement showed |
|---|---|---|
| R9.17 | "Claude Code rotates `session_id` per tool call" | one stable id across Bash and Write; the state was a **single global slot** two sessions kept overwriting |
| R9.18 | "`proxy.close()` waits on keep-alive sockets" | `close()` already calls `closeAllConnections()` |
| R9.18 | "the port is slow to release" | process dead in **4ms**, port free in **4ms**; the cost was 6.7s of credential resolution *before* `listen()` |

The tell in each case was the same: a plausible mechanism that explained the symptom,
adopted without a measurement that could have falsified it. The cheap probes that settled
them — dumping hook payloads, timing each startup step, timing `resolve()` per account —
each took a couple of minutes and each overturned the story.

## Lessons

**1. "Two different values appeared" is not evidence of rotation.** Two denials wrote two
different session ids, and the obvious reading was that the id changes per call. The other
reading — two *sessions* — needed one payload dump to confirm and would have saved a
wrong task doc. When a shared file holds an unexpected value, ask who else writes it.

**2. Concurrency is the default in this repo, and single-slot state cannot survive it.**
The project routinely has several sessions live at once: another window, a parallel agent,
a headless `claude -p`. Any per-project state keyed to "the" session is a starvation bug
waiting to happen. The state now holds a bounded set.

**3. Unit tests that pass the happy value twice prove nothing about interleaving.**
`decideCoderFirstNudge` was pure, correct, and fully tested — with the same id twice. The
failing case, two sessions taking turns, had no test. It does now.

**4. A timeout tuned to a fast path becomes a liar on a slow one.** `waitForPort`'s 8s
budget sat just above a 6.9s startup. Nothing was broken; the deadline was simply too tight
to be honest. Prefer being slow to declare failure: a false failure sends someone
debugging a healthy system, which costs far more than waiting.

**5. A discarded return value is a bug in waiting.** `restartProxyDetached` called
`waitForPortFree` and ignored the answer, then started a daemon that could only exit with
"already running". Worse, the restart sometimes *looked* successful because `waitForPort`
was seeing the old listener — a false success, which is the more dangerous failure.

**6. Fix the cause, or file it — do not quietly rename it.** Making credential lookups
concurrent barely helped on Windows, because concurrent PowerShell startups contend rather
than overlap. Rather than leave a comment claiming a win that the measurement contradicts,
the comment says what was actually measured and the real fix (one batched decrypt) is filed
as R9.20 with the numbers.
