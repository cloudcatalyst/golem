# R10.21/R10.22 — The wiring belongs in the file that is not committed

**Date:** 2026-08-14
**Tasks:** [R10.21](../../plan/tasks/R10.21.md), [R10.22](../../plan/tasks/R10.22.md)

## Outcome

`golem init` now writes Claude Code's whole wiring — `env`, the
`mcp__golem__*` permission, six hooks, the status line, the default permission
mode — into the gitignored `.claude/settings.local.json`. The committed
`.claude/settings.json` is left alone unless `claude.settings_scope=project`
says otherwise. `golem config set` / `unset` default to `--scope local` for the
same reason one level down.

Readers were not moved: every surface that asks "is this project wired?" walks
both files in Claude Code's own precedence order (local shadows committed,
verification-notes §13). Only the write target is a choice.

## Key lessons

**A default that silently keeps working is the hardest kind to notice is
wrong.** Committed wiring never failed loudly — it just travelled to clones that
could not honour it (a port assigned on another machine, hooks needing `golem`
on PATH) and churned in everyone's diff. R9.22 had already carved out
`NODE_EXTRA_CA_CERTS` on precisely this reasoning and stopped there; the rest of
the wiring is machine-local by the same argument.

**Two files add a second way to take a setting over, and it is invisible.** The
codebase enforced "never clobber a FOREIGN setting" thoroughly. Writing our
`statusLine` into the local file leaves a user's committed one intact
byte-for-byte — and completely inert, because the local file outranks it. Not
clobbering is not the same as not overriding; only one of the two shows up in a
diff. `writeStatusLine`/`writeDefaultMode` now check the other file too.

**Hooks made the migration sweep mandatory rather than tidy.** Claude Code
MERGES hooks across settings files. A leftover copy in the shadowed file does
not lose to the new one — it runs alongside it. So init sweeps the non-target
file and uninit sweeps both, instead of the simpler "write the new place and
leave the old".

**One resolver, or the fleet drifts.** Six modules each had their own
`path.join(projectDir, ".claude", "settings.json")`. They now share
`claudeSettingsFiles()`, which hands back the target AND the other file from a
single scope decision, so no writer can end up sweeping a file it is also
writing.

## R10.22 — what the init conflicts were hiding

The same init run reported eight `conflict` lines (files Golem would update but
refuses to overwrite once edited). They looked like one problem and were two.

**"Conflict" does not tell you which side is ahead.** Four *skills* were stale on
DISK — the shipped text was newer, and the on-disk copies still named
`golem stats` / `golem devices` where the source had moved to MCP tools. Four
*rules* were the reverse: hand-condensed rewrites of what Golem ships. Same
banner, opposite remedy — refresh one set, fold the other back.

**Condensation silently drops the facts nobody re-derives.** The four rewritten
rules held exactly one new fact ("ADRs go in `docs/decisions/`, not the wiki")
and had quietly lost four: the **blind auto-park** warning when a rate-limit feed
goes cold, `knowledge.wiki_dir` being configurable, redaction-before-storage +
contradictions-surfaced, and local-answer's single-turn constraint. Every one is
the kind of fact that only matters on the day it matters.

**Golem was spending the budget it exists to defend.** Seeded rules load into
every session; the five defaults totalled 8,322 bytes of permanent context.
Adopting the terse voice with the four facts restored lands at 5,684 (−32%).

**Where brevity was refused:** three test assertions pin exact phrases (the wiki
ladder's order, "keep the wiki current", `ENFORCES`). Those encode contract, not
wording — the phrasing was restored rather than the tests loosened.
