# R8.31 — `proxy stop` left Claude Code wired to a dead port (2026-08-06)

Found by dogfooding, reported as one sentence: *"when I stopped the proxy using the VS
Code UI, it didn't seem to remove the Anthropic URL. That needs to be much more robust."*

Spec [Decision 56]; findings in `verification-notes.md` §112.

Related: [[Dogfooding Golem]], [[Configuration Surfaces]].

## What was actually broken

Nothing in the stop path was buggy — the behaviour had never been designed. Three hops,
each correct in isolation:

- `setProxy(false)` in the extension runs `golem proxy stop --dir <cwd>` and nothing else.
- `proxy stop` wrote desired-state `stopped` and killed the pid.
- No surface in that path reads or writes `.claude/settings.json`.

So `ANTHROPIC_BASE_URL` kept naming a port with nothing behind it, and every request
failed with connection-refused until the proxy was restarted or the file hand-edited. §46
introduced the VS Code toggle and specified only the *process* lifecycle; the wiring was
never in scope, and no test asserted anything about the pair.

**The evidence was sitting in the working tree.** `git diff .claude/settings.json` showed
an uncommitted hand-edit deleting the whole `env` block — the maintainer had already
worked around this manually, which is what the wiki's own "Escape hatch" section tells you
to do. A documented manual workaround is a design gap with a bandage on it.

## The finding that changed the design

The obvious fix — have `stop` delete the key — **does not solve the reported symptom.**
`ANTHROPIC_BASE_URL` arrives through `settings.json` → `"env"`, and §13 (live docs) lists
what hot-reloads: `permissions`, `hooks`, `apiKeyHelper`. `env` is not among them, and
`model`/`outputStyle` are explicitly called out as needing a restart. Golem's own escape
hatch independently says to remove the var *"and reopen the editor"*.

Deleting the key therefore fixes the **next** session and leaves the current one broken.
Any design that stops there ships a fix the reporter would still experience as broken.

So the answer had to keep the socket alive: **`stopped` now means *pipeline off*, not
*port dead*.** A redaction-only shim stays bound to the project port, and Claude Code
never notices — no settings edit, no reload, no churn on a git-tracked file.

## The trap: the cheap shim would have breached a hard rule

The natural way to build a passthrough is the one that already exists —
`x-golem-bypass` / slider level 0. It is wrong, and this is the part worth remembering.

That path forwards **untouched**, which means redaction off. CLAUDE.md admits level 0 as
the single redaction-off exception *only* on the condition it is never the default and is
always surfaced loudly; `src/cli/skills.ts` already tells agents to prefer level 1 "unless
a true full bypass is intended". A Stop button built on level 0 would have made the
redaction-off path reachable from a click that says nothing about redaction — a hard-rule
breach arriving disguised as a convenience feature.

The shim pins **level 1**: redaction on, byte-faithful, no compression, no brevity, no
local-answer. `sliderPolicyForLevel(SliderLevel.Lossless)` already yields exactly that
from its own defaults, so this needed **no new dial and no frozen-contract change** — one
pinned policy constant, frozen at module scope specifically so the live slider cannot
reach it. Two tests hold the line: the shim redacts even when the slider store says 0,
and a **control** asserts that a level-0 non-shim build really does leak the secret. The
control is the load-bearing one — without it, the first test could keep passing for the
wrong reason if the contrast ever disappeared.

## What else fell out

- **Going direct is now explicit.** `golem proxy unwire` / `wire`, plus a VS Code
  "Go direct (unwire Golem)" action that confirms first and then *offers the reload* —
  because reporting success without it is the same defect in a new place.
- **The ownership guard was reused, not re-derived.** `init.ts` already deleted the var
  only when it equalled Golem's own base URL. That logic moved to `src/cli/proxy-wiring.ts`
  and `uninit` now calls it, so there is one definition of "is this wiring ours?". A
  **foreign** `ANTHROPIC_BASE_URL` survives an unwire untouched, and a test says so.
- **`stop --hard`** keeps the old behaviour for "get off my port", and warns when it is
  about to leave live wiring pointing at nothing.
- **`bypass` is restored on SessionStart.** A project left with the pipeline off is still
  wired, so reopening it without the shim would recreate the very defect.
- **A smaller dishonesty, exposed by fixing the bigger one.** With the shim serving, the
  statusline still printed `✂ full` — the *configured* brevity dial — while the shim runs
  no brevity stage. Same species as calling a served port "off", so it is suppressed in
  bypass, in the CLI line and in the extension.

## Verification

Standing bar green (`tsc`, `biome check`, `format:check`, `verify:deps`, 2281 tests, +20).
Live, on a scratch project first so the session's own proxy was never at risk:

- after `stop`, the port still accepts connections (the whole defect, gone);
- `status` / `statusline` / `golem status` all name the bypass state rather than "off";
- a POST through the shim with a bogus key returned **401 from `api.anthropic.com`** —
  proof it forwarded upstream rather than refusing the connection;
- then repeated against this repo's real config and port, and the original state restored.

## What is not measured

Whether the shim's presence changes anything measurable about latency or throughput — it
runs the level-1 path the proxy already ran, so there is no reason to expect a difference,
but nobody timed it. And the reporter's exact gesture (Stop from the VS Code UI, then a
real request with no window reload) was verified through the CLI equivalent plus a synced
extension; the click itself is a human check.

## Lesson

Two lifecycles were being treated as one. "Is the process running?" and "where is the
client pointed?" are independent facts, and every surface here knew only the first. The
report arrived as a complaint about the *second* ("it didn't remove the URL") — but the
fix was not to make stop do more to the wiring; it was to notice that the wiring **cannot
be changed cheaply at all**, and to make the process lifecycle stop depending on it.

When a documented manual workaround exists for a UI action, that is the design gap
announcing itself. This one had been written down in the wiki for weeks.
