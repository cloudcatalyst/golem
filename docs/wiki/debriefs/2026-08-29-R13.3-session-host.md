# R13.3 -- the host can refuse, and the event it refuses at is not the one R12.12 chose

## Outcome

`golem session host start "…"` spawns a `claude` session through Golem's proxy,
streams it back with tool calls visible, and **refuses** a destructive or outward
call outright. Demonstrated live against the real runner (§147 item 6): the
session tried `rm -rf ./victim`, was refused with Golem's reason, reported the
refusal accurately, explicitly declined to route around it, and the file
survived. See [[Hosted Session]].

## The finding that changed the design

R13.3's brief assumed the host would be *"the first place in Golem where a `deny`
exists at all"*. It was written before R12.12 shipped, which put a real `deny` on
the guest path at `PermissionRequest`. So the obvious move was to reuse that
event.

**Measured (§147 item 3): `PermissionRequest` is the wrong enforcement point for
a hosted session, and fails silently.** It fires only when Claude Code is about
to *ask* for permission, and in a headless session under `--permission-mode
default` most calls never ask. A `PermissionRequest` deny hook was installed and
a plain `echo` inside the session's own cwd ran to completion — the hook never
fired at all, proven by having it append to a file before deciding. The file was
never created.

`PreToolUse` fires before every tool call and its deny stops it, with the reason
delivered to the model as the tool result. That is the host's point.

R12.12 is not wrong: its problem was a *dialog* opening and a connected channel
answering it, and `PermissionRequest` is what precedes a dialog. Two tasks, two
events, because two problems.

## Key lessons

- **The strongest available mechanism is not always the right one — check that it
  fires.** `PermissionRequest` is strictly more authoritative than `PreToolUse`
  (only its decision object can grant or deny a *request*), and it was still
  useless here, because in this mode there is usually no request. "Can it refuse?"
  and "will it be asked?" are different questions and only the second one was
  load-bearing.
- **A negative result needs a probe that can distinguish "didn't fire" from
  "fired and lost".** The first spike saw a denial and nearly concluded the hook
  worked — but the message was Claude Code's *own* working-directory guard. The
  hook only became falsifiable once it wrote to a file before deciding.
- **`--settings <inline JSON>` makes the enforcement the host's own.** Without it
  the gate would depend on the guest project's wiring, one `golem autonomy unwire`
  away from a session Golem spawned running ungated. Measured: it wires hooks for
  a project that has none.
- **Derive the matrix, don't restate it.** The first cut wrote its own
  (level × class) table and mapped `manual` to `ask` — which, with nobody
  attached, denied every **read** and made a hosted session useless at the default
  autonomy level. The fix was to derive from `decideGate` and translate: `null`
  (defer) means "Golem adds no restriction", not "ask a human". A human to defer
  to is exactly what a hosted session does not have.
- **Two relationships, two types.** `GateEmission` stays `allow | ask | null`
  because that is an honest account of what a *guest* can do; `HostDecision` adds
  `deny`. Widening the shared enum would have told every hook call site that
  refusal was on the table for the guest path. Same argument for the second log.
- **Fail-closed here, fail-silent there.** The guest hook fails to silence, so a
  crash leaves the human's permission flow in charge. The host gate fails to deny,
  because there is no human flow to fall back to.
- **A commander `--dir` collision silently hosted a session in the wrong project**
  (§147 item 7) — the same quirk R13.2 hit at `session forget`, one level deeper.
  Any subcommand added under a command that already declares `--dir` inherits it,
  and the symptom is acting on the wrong repository without a word.

## What is NOT here

- **Detaching.** The registry, liveness checks and reaping ship; a session still
  runs under the process that started it. `list` reports honestly rather than
  claiming otherwise.
- **An answerer for `ask`.** No transport (R13.5) and no chat surface (R13.6), so
  every `ask` currently refuses. The `HostAttachment` seam is tested on both
  branches; only the unattached one has ever run.
- **A non-Claude runner.** One adapter, and the seam left obvious
  (`runnerArgs` + `runnerArgsOverride`).

## Gate

`tsc --noEmit`, `npm run lint`, `npm run format:check`, `npm run verify:deps`,
`golem wiki check` all exit 0. `npx vitest run`: **3217 passed / 2 skipped /
0 failed**. +18 unit tests, +18 integration tests spawning a real process that
speaks the real stream-json protocol. The real-runner demonstration is live and
dated in §147 rather than claimed here — spawning `claude` in the suite would
cost money per run and need credentials, so the protocol is tested in CI and the
binary is measured in the note.
