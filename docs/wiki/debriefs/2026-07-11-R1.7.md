# R1.7 — cross-OS e2e smoke + Linux fs.watch reliability already shipped

`R1_BATCH.md`'s R1.7 asked for a GitHub Actions cross-OS matrix running an
e2e `golem init` smoke test plus a Linux recursive-`fs.watch` reliability
check, with a fallback to wire if native recursive watch proved flaky on
Linux. Checking each piece against the repo before building anything showed
all of it already exists.

## What was found

- `.github/workflows/ci.yml` already runs `ubuntu-latest` / `macos-latest` /
  `windows-latest` × Node `22`/`24`, executing `npm run lint`, `npm run
  typecheck`, `npm test`, `npm run build` on every push to `main` and every
  PR — the matrix R1.7 asked for.
- `tests/e2e/golem-init-smoke.test.ts` (T-C2) already is the e2e smoke test:
  fake `InitProbe` (no real `claude` CLI/home dir), idempotence check, then a
  real `buildProxyFromSettings` proxy doing a level-1 byte-faithful round
  trip against a fake upstream, asserting response equality and durable
  telemetry (`tokensBefore > tokensAfter`, `ccrRefsStored >= 1`). Picked up by
  plain `npm test` via `vitest.config.ts`'s `include: ["tests/**/*.test.ts"]`.
- Linux fs.watch reliability was resolved **by design**, not by a
  prove-then-fallback contingency: [[ADR-0001 File Watcher Backend]] shipped
  Option 2, which never attempts native recursive watch on Linux at all
  (`NATIVE_RECURSIVE_PLATFORMS = new Set(["win32", "darwin"])` in
  `src/knowledge/file-watcher.ts`) — Linux unconditionally uses the
  hand-rolled `TreeWatcher`. `tests/integration/knowledge-watch.test.ts`
  exercises this with no OS-skip guards, in the same CI matrix.
- The runner-strategy decision R1.7 asked to record (stub vs. real Ollama/uv
  in CI) was already the de facto, consistently-applied practice —
  `tests/integration/cli-ollama.test.ts` states outright it fakes everything
  OS-touching — just never written down as a dated decision. Now recorded in
  [[Redaction Stage]]'s neighbor doc, `docs/plan/verification-notes.md` §57: stub
  Ollama/the `claude` CLI everywhere in the automated suite; the real
  install/pull path stays a manual-only per-OS checklist (§48), never a CI
  job.

## Design notes

- `R1_BATCH.md`'s R1.7 wording ("if Linux recursive watch proves flaky, wire
  the ADR-0001 fallback") doesn't match what ADR-0001 actually decided — the
  fallback *is* the shipped, unconditional Linux implementation from T6, not
  a contingency waiting on a failure signal. There is nothing left to wire.
- No status change to ADR-0001: its `accepted` decision (Option 2, `chokidar`
  deferred) is unchanged by this finding — this debrief only confirms and
  documents what was already true.
