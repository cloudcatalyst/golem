# R2.1 — Decision 24 avoidedUpstream spike

Measured (not built) whether real usage data justifies building Decision
24's proxy-side KB/web-cache answer substitution. Full write-up in
[[R2.1 — avoidedUpstream measurement spike]]; short version: the telemetry
needed to answer the question directly doesn't exist yet (`search`/`fetch`/
`ingest`/`wiki_read` aren't instrumented at all), and the one real proxy
signal available (CCR retrieval rate — 0 `expand` calls against 1051 stored
refs) is encouraging but measures a different mechanism than KB-answer
substitution.

Recommendation carried into R2.2: ship its `avoidedUpstream` telemetry
bucket from the start rather than adding it later, so the next spike has
real data. R2.3 stays gated behind R2.1 and R2.2 — confirmed by evidence,
not just sequencing convention: there is currently no signal at all for how
often a KB/web-cache hit could replace a whole turn.

No code changed this task — verification-notes §59 + this debrief + the
synthesis page are the full deliverable, per R2_BATCH.md's own scoping
("measurement, not a feature").
