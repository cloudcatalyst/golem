The diagnostic that aims the rest of R8, built because [[Cache Observability]]'s
first measurement (§93) changed the question from "did the cache hit?" (98.4% —
yes) to "*what* am I paying to re-read?".

## What shipped

- `src/proxy/context-ledger.ts` — `buildContextLedger` attributes every token in
  the outgoing request to a bucket (tools / system / user text / assistant text /
  thinking / tool results / images / other), names the biggest individual blocks,
  and resolves each `tool_result` back to **the tool that produced it** by mapping
  `tool_use_id` through the assistant turns.
- Latest-only persistence to `.golem/state/context-ledger.json`, following
  `writeLimitState`'s atomic temp+rename, fail-open contract.
- `golem stats --context [--json]` via `src/cli/context.ts`.
- 24 tests.

## Two design calls

**The pipeline stays clock-free.** `buildContextLedger` returns a
`ContextLedgerCore` with no timestamp, and the CLI layer stamps `capturedAt` on
write — matching the existing "`nowIso` is injected" convention in
`recordPipelineEvent`, and respecting the standing determinism obligation that
pipeline decisions never read the wall clock. The first draft read the clock inline
and was rewritten.

**Not a telemetry event.** One ledger per request would be a large durable write
for a value only the newest copy of which is useful, and the per-request history is
already covered by the savings/usage events. Latest-only, like the limit
prediction.

**Tool names are kept; content never is.** A test asserts no prompt text reaches
the ledger while `Read` and `Grep` do. Without the name resolution the biggest
consumer of an agentic context is an anonymous blob and the report is unactionable
— that resolution is the feature.

## The first capture (§95) — 550 messages, ~312k tokens

| bucket | tokens | share |
|---|--:|--:|
| assistant text + tool calls | 102,868 | 33.5% |
| tool results | 95,463 | 31.1% |
| thinking blocks | 54,074 | 17.6% |
| user text | 32,199 | 10.5% |
| **tool definitions** | **18,827** | 6.1% |
| system prompt | 3,365 | 1.1% |

Three things it settled, all of which move work:

1. **The `tools` block is ~5× bigger than §88 believed — 18,827 tokens, and the
   largest single block in the request.** §88 measured Golem's own 11 tools
   (~3,847 with schemas); a real session adds Claude Code's built-ins and every
   other MCP server. **R8.S1 (schema shrinking) is promoted** — its ceiling is
   18.8k, not 3.8k. The rejected *prose* shrinker stays rejected (§89).
2. **Bash is the biggest tool consumer: 36,968 tokens across 132 results.** The
   first quantified case for the RTK recommendation (§90), and confirmation that
   descoping R8.3 away from Bash filters was correct — install the tool that has
   100+ of them rather than rebuilding them.
3. **One `expand` call cost 6,356 tokens**, fourth-largest of any tool. The
   `golem-ccr-refs` guidance rule's warning is now measured rather than asserted.

Not actionable but worth knowing: **thinking blocks are 17.6%** — a bucket Golem
cannot touch at levels ≤1 without changing the proxy-fidelity hard rule. Anyone
proposing to drop stale thinking should know that is a rule change, not a knob.
