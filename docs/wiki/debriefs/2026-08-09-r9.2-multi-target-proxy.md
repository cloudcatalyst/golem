# R9.2 — the proxy serves many targets (2026-08-09)

Related: [[R9.1 — the target registry, and the config that was already one]],
[[R8.32 — a running proxy nothing was pointed at]].

## The blocker was one line of the constructor

`server.ts` built a single `undici` `Pool` from `upstreamBaseUrl` at construction. That —
not the routing, not the translators — was the entire structural reason one proxy run
served one upstream. Replacing it with a lazy `Map<origin, Pool>` made concurrency across
targets fall out for free, because per-origin pooling is exactly what undici is for.

The cap (`MAX_POOLED_ORIGINS = 32`) deliberately does **not** fail a request when reached:
past it the origin is dialled with an unretained pool. A bound that exists to stop a
pathological config growing a map must never become a reason a real request fails.

## Additive, and the tests are the proof

`resolveRoute` is optional. Absent, the proxy is the code it has always been — same
single upstream, same byte pipe, no rewriting. The gate for this task was that *every
existing byte-fidelity and recorded-shape test passes unmodified*, and they do: 104 proxy
tests, then 513 proxy+CLI, then the full 2360, none edited.

That is worth stating as a design rule and not just an outcome. The alternative shape —
make routing the only path and express "one upstream" as a one-entry registry — would
have been cleaner in the abstract and would have put every existing fidelity guarantee
through new code on day one.

## Three explicit levels, and the rule that isn't expressible

| # | level | authored by |
|---|---|---|
| 1 | `model: "golem/coder"` in the body | user / sub-agent definition |
| 2 | `x-golem-target: <id>` | hook / config |
| 3 | `proxy.default_target` | user config |

Plus a conversation binding between 2 and 3, which is an optimisation rather than a level:
level 1 is already stable turn to turn because the client re-sends the same id.

`providers/routing.ts` is **pure and total** — no I/O, no clock, no registry lookup. It
returns an id it cannot validate, on purpose, because only the caller can fail closed with
an error naming the configured targets. Eleven unit tests cover the chain exhaustively,
which is affordable precisely because nothing is mocked.

The design's most important property is what it *cannot* express. There is no rules engine
and no suggestion channel, so no rule can key on a per-turn signal (thinking-enabled, token
count). Such a rule ping-pongs one conversation between targets and busts the prompt-cache
prefix on every switch — which costs far more than any routing decision saves. The inputs
here are per-conversation or per-request-authored, never per-turn-observed.

## Fail-closed had to be literal

An unknown target dials **nothing**:

```
golem proxy: virtual model id "golem/ghost" does not match any configured target.
Configured targets: alpha, beta. No substitute was used — add it with `golem target add`.
```

Tests assert both stub upstreams saw **zero** requests, for an unknown virtual id and an
unknown header target alike. Serving the default there would send the caller's context to a
model they did not name, and they would have no way to notice. Claude Code does not catch an
unknown `golem/*` id (§114 caveat 4), so this error existing is the only thing between a
typo and a silent misroute.

Two more refusals, both about the same failure: a virtual id whose target declares **no
model** (there is nothing to send), and a body that is not JSON with a model field.

## The one place the proxy rewrites a request

A virtual id must never reach an upstream — no provider has a model called `golem/coder`.
So when level 1 selected the target, the body's `model` is replaced with the target's own.

This is the single model rewrite in the proxy, and it only ever replaces a string that was
never a real model id, so ordinary traffic keeps its byte-faithful guarantee untouched. The
restatement that matters: **byte-fidelity is a property of the provider, not of the proxy.**
An Anthropic-protocol route is a raw byte pipe; a translating route never was (R6.1 case b).
Per-route selection states that per request instead of per run.

## The extraction that prevents a silent bug

`buildUpstreamTransport` was pulled out of `proxy-runtime.ts` so the single-upstream path
and every routed target construct their translator through the *same* code. Two copies
would drift, and this is a domain where drift does not throw — a subtly wrong translator
produces a mangled response, not an error. The refactor immediately earned itself: writing
the second copy exposed that `createOpenAIToAnthropicSSE` takes **one** argument with
`mapReasoning` merged in, not two, which a fresh implementation had got wrong.

## Observability, because N targets breaks every "current" surface

- `served-model.json` gains a per-target map. The top-level fields are kept and now mean
  "most recently served by any target", so every pre-R9.2 display surface stays correct
  without being taught about targets.
- `golem status` grows per-target rows — only when more than one target exists, since
  otherwise the `Upstream:` line already answers it and a one-row table is noise.
- `limit-prediction` snapshots record **which target** produced them, and status names the
  targets the reading says nothing about as `unmonitored_targets`. Only some providers emit
  `anthropic-ratelimit-unified-*`; without naming the rest, one target's utilization reads
  as coverage for all of them and the snooze auto-park is blind without saying so. This was
  already observably wrong with *one* target — the auto-park went dark during the R9 design
  session for exactly this reason.

Live against this repo's real registry:

```
Targets: 7 configured
  * anthropic (anthropic, trust=vendor) (client's own id) — nothing served yet
    openrouter-laguna (openrouter, trust=third-party) poolside/laguna-s-2.1:free — nothing served yet
```

## Verification

`tsc --noEmit`, `biome check` (455 files), `verify:deps` ok, full suite **2360 tests**
(+23). Twelve integration tests run **two real stub upstreams against one proxy**, so
"serves many targets concurrently" is demonstrated rather than asserted.

**Still open — §114 caveat 5.** The proxy half of the slash question is now proven: a
slash-bearing `golem/<id>` routes correctly end-to-end through a real proxy. What remains
unverified is the *Claude Code* half — that a sub-agent defined with `model: golem/<id>`
forwards the string intact. That needs a live session, and confirming it would dispatch a
real request to a third-party upstream on the user's credential, so it was not run here.
If it ever fails, the fallback is a flat id (`golem-coder`) and the design is unaffected.

## Lesson

The task doc predicted the whole shape — one `Pool`, resolve before the pipeline, transport
from the route — and it was right, which is the useful observation: the expensive part of
this work had already happened in the proposal and the R9.1 split. What the code added was
the refusals.

Every genuinely new decision here was about what to do when something is *wrong*: unknown
id, modelless target, non-JSON body, a limit reading that covers one target out of seven.
A routing layer is mostly its error paths, because the happy path is a lookup.
