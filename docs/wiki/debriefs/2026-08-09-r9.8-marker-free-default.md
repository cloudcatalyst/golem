# R9.8 — marker-free by default, and the warning nobody could read (2026-08-09)

Related: [[R9.9 — the config surface could not write half its own schema]], [[Configuration Surfaces]]

## Outcome

An editing-heavy session at slider 3 produced a loop: tool output came back rewritten
with `<<ccr:…>>` refs and crushed tables, so an exact-match `Edit` built from what the
model *saw* failed against the file's real bytes. Decision 57 makes **marker-free the
default** wherever the semantic stage runs, and fixes the reporting path that was
supposed to have made the underlying misconfiguration visible.

Measured on a 400-row tool result against the real `headroom-ai==0.30.0` pin:

| route | tokens saved | `<<ccr:…>>` markers |
|---|---|---|
| stock pipeline (before) | 19,181 | 37 |
| marker-free (now default) | 15,740 | **0** |

82% of the saving kept, for tool output that always matches the bytes an `Edit` will be
applied to.

## Key lessons

**The task's premise was wrong, and it was wrong in the most instructive possible way.**
R9.8 was written expecting the opaque `headroom_config` bag simply could not express
*nested* Headroom config. `HeadroomConfig.smart_crusher.lossless_only` turns out to
exist, be settable, and **do nothing** — because Headroom's default pipeline constructs
`ContentRouter()` with no config argument at all, so the nested object is held by the
pipeline and never handed to the transform that reads it. Had the passthrough been
"fixed" to forward the correct-looking nested key, it would have reported success and
changed nothing: precisely the failure Decision 53(h) exists to prevent, one level
deeper. **Verifying against the installed package rather than the docs is what caught
it** — three of the task's five premises did not survive measurement.

**When config cannot reach a behaviour, the reach point may not be a config object at
all.** Here it is the *transform instance*. The worker therefore builds a real default
pipeline and replaces **only** the `ContentRouter` inside it, rather than rebuilding the
transform list — so an upstream release that adds a transform keeps it, and the coupling
narrows to "there is a transform named ContentRouter", which fails loudly into
`config_ignored` rather than silently.

**A process-global singleton needs an explicit restore, not just an install.** The
pipeline `headroom.compress()` uses is module-level state. Installing a configured router
and stopping there means one lossless request quietly configures every later request in
that worker. The restore-on-every-request path is guarded by its own test, because this
is the class of bug that only shows up under real traffic.

**`HEADROOM_LOSSLESS_ONLY` exists and is a trap.** It is read only in Headroom's
`proxy/server.py` — their own proxy, which Golem does not run. An env var that is real,
documented, and inert in your process is worse than one that does not exist.

**Two premises died on contact with a measurement.** Headroom's `DEFAULT_EXCLUDE_TOOLS`
already covers Read/Glob/Grep/Write/Edit, and Golem forwards the assistant `tool_use`
blocks that make the tool name resolvable — so Read output was never the exposure;
Bash, WebFetch and MCP output were. And level-3's `compress_user_messages: true`,
flagged as opting a coding agent into what Headroom tells coding agents to skip, is
**inert on the shipped install**: identical savings, byte-identical prose and
tool_result both ways, because the prose-compressing Kompress stage needs the `[ml]`
extra the default install deliberately omits (§35). It was documented rather than
flipped on a theory.

**The honesty machinery existed and was pointed at `/dev/null`.** The adapter had built
a careful "this Headroom ignored …" warning, deduplicated per distinct key set. The
daemon spawned with `stdio: "ignore"`. In the mode people actually run the proxy in,
that warning — and the target-misconfig and missing-credential warnings beside it —
reached nobody. This repo's own `settings.local.json` carries a `headroom_config.plugins`
key that has been silently dropped this whole time, *with* a warning that was invisible.
**A diagnostic nobody can find is the same as no diagnostic**, and it is a more expensive
failure than having no diagnostic, because it buys false confidence. The daemon now
appends to `.golem/proxy.log` (front-truncated at 1 MB, falling back to `"ignore"` if it
cannot be opened — a proxy that will not start because of a log file would be worse than
the bug) and `golem status` reports the path.

**Default changes are Decisions.** The task said to argue `lossless_only` in the
ADR/spec rather than flipping it quietly, and that is what the measurement was for: the
82%/zero-markers number is what makes the trade arguable rather than a preference.

## Verification

Full suite green (2434 passed), `tsc --noEmit`, `biome check`, `verify:deps` all 0. The
behaviour is pinned two ways: against a stub `headroom` in
`tests/fixtures/headroom-worker-selftest.py` (CI stays Python-light) and, during
development, against the real pinned package through `uv run --with headroom-ai==0.30.0`
— which is where every number in this debrief came from.
