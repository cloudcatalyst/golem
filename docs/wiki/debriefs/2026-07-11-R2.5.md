# R2.5 — Headroom `read_lifecycle` disable verification

Resolves §53's open question gating R2.6: can Headroom's `read_lifecycle` be
disabled to build a cache-safe structural compression tier for Anthropic?
Full technical detail is in verification-notes §58; this page records the
durable conclusion and how it reshapes R2.6.

## What was verified, and how

Read the actual pinned package source (`headroom-ai==0.30.0`, matching
`src/compression/index.ts`'s pin) rather than relying on docs or the prior
introspection-only check. `uvx`-installing the `[proxy]` extra failed here —
Windows Defender quarantined a transitively-pulled `ast-grep-cli` binary,
unrelated to Golem, not worked around — so the wheel was fetched with `pip
download --no-deps` (no install, no script execution) and read directly.
Pure-Python wheel; full source available for the relevant modules.

## The finding

- The `compress()`/`CompressConfig` surface Golem's worker actually calls has
  no `read_lifecycle` switch — confirmed at the source, not just by an
  absent field: `_get_pipeline()` builds a fixed singleton pipeline
  (`CacheAligner` + `ContentRouter` only), and `compress()` has no config
  path down to `ContentRouter`'s `read_lifecycle` field.
- It **can** be disabled, but only by bypassing `compress()` and driving a
  custom `TransformPipeline` with `ContentRouter(ContentRouterConfig(
  read_lifecycle=ReadLifecycleConfig(enabled=False)))` — a real worker
  rewrite, not a config flag.
- Headroom's own `ReadLifecycleConfig` already splits this into
  `compress_stale` (files later edited — on by default) and
  `compress_superseded` (files later re-read unchanged — **off by default**,
  with the library's own comment reading "busts Anthropic prompt cache
  prefix"). The redundant-reread pattern most responsible for §34's measured
  53 elisions is already the part the library itself keeps disabled for
  cache reasons.
- The library's real answer to cache-safe redundant-read compression is a
  separate mechanism ("read maturation," holds a fresh Read out of the cache
  until it goes quiet, so no cached byte is ever mutated) — wired **only**
  into the stateful `headroom proxy` server, which needs persistent
  per-session state Golem's stateless per-request `compress()` call has no
  way to carry, and which Golem deliberately doesn't chain (per §34, a
  second Anthropic-facing proxy conflicts with Golem's own).

## What this means for R2.6

Disabling `read_lifecycle` outright isn't obviously the right lever — the
part that actually risked the cache is already off. The recommended R2.6
shape (not built this session): re-enable today's default `compress()`
behavior (stale-only + `CacheAligner` + `ContentRouter`, exactly what
already runs on non-caching upstreams) on Anthropic too, behind a new opt-in
tier, and prove it net-cache-safe using R1.1's already-built
`UsageSniffer`/`aggregateUsageByLevel` infrastructure before touching
`isCachingUpstream()`'s gate. This turns R1.1's shelved measurement
machinery into R2.6's actual gate, rather than building new telemetry.

See also verification-notes §58 and [[R1.1 — net-of-cache billed-`usage` A/B (level 1 vs level 3)]] (docs/wiki/syntheses/r1.1-net-of-cache-ab.md).
