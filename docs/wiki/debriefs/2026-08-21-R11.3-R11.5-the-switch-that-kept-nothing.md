# R11.3 + R11.5 — the switch that kept nothing, and the index that pointed nowhere

Shipped 2026-08-21. Two defects with one shape: state that existed, mattered, and
was visible to nothing.

## Outcome

- `golem on` / `golem off` now **persist** `proxy.bypass_all` and apply it live.
  "Off" survives a restart, and every status surface reports it, because they all
  read that setting.
- `golem wiki check` fails on a debrief `WIKI.md` does not list, and the 39 that
  had fallen out of the Index are back in it.

## Key lessons

**A control whose state nothing can read is worse than a missing control.**
`golem off` POSTed an in-memory flag on the running proxy. Two consequences, and
the second is the one that matters: it did not survive a restart *and*, while it
was in force, no surface said so. Every status surface — `status-collect.ts`,
`statusline.ts`, `watch.ts` — reads `proxy.bypass_all` from settings, so a machine
forwarding raw with **redaction off** rendered as a healthy pipeline with dials
beside it, and `REDACTION_OFF_WARNING` never fired. R11.1 had built the right home
for that state a day earlier; the switch just wasn't using it.

**Persisting is what made it honest, not what made it durable.** The obvious
framing was "the setting should survive a restart". The better one: put the state
where the surfaces already look. Writing `proxy.bypass_all` fixed the reporting
for free — no new status code, no fifth proxy state for R10.24's parity test to
pin. When a fix removes the need for a display, prefer it to the fix that adds one.

**Persisted and immediate are not a trade-off you have to accept.**
`proxy.bypass_all` is read where the proxy is constructed (`restart: "proxy"`), so
writing it alone would have cost the instant apply `golem off` always had. Doing
both — write, then POST the same state to the live listener — keeps them. The
cheap version of "durable" would have been a worse command.

**Nothing tested the two commands at all.** Not one case covered `golem on` or
`golem off`, which is exactly why R11.1's thorough sweep of the slider missed
them. The fix moved the logic out of the commander callback into
`pipeline-switch.ts` so it *could* be tested — a string built inline in an action
is a string no test will ever read.

**A checklist step with no check is a suggestion.** The close-out checklist says
to author a debrief; the wiki-first rule says the Index is the entry point. With
nothing joining them, 39 debriefs — every one from 2026-07-16 on, all of R9 and
R10 — had no Index line. They were still searchable via the vector index, but
unreachable by graph traversal from the Index, which is the half the wiki is for.
`golem wiki check` passed throughout, because it linted what a page *contains* and
never asked whether anything pointed *at* it.

**Reachability is a property of the graph, not of the file.** The pages were
present, valid, well-formed and indexed by the embedder. None of that made them
findable the way the wiki promises. Worth asking of any store: what can I reach
from the entry point, not what exists.
