Investigated integrating **Kimi K3** (Moonshot AI) as an upstream. Verified its
API first (verification-notes §79): it is **OpenAI Chat Completions compatible**,
so it already works via Golem's `openai` translating provider with **no new
provider code** — set `upstream_provider=openai`,
`upstream_base_url=https://api.moonshot.ai/v1`, `upstream_model=kimi-k3`,
`GOLEM_UPSTREAM_API_KEY=<key>`.

Because K3 is a **reasoning + vision** model, three gaps in the OpenAI translator
would have degraded it — closed here so it (and any reasoning/vision OpenAI-schema
backend) is first-class. User picked "all three".

## What landed

- **`reasoning_content` ↔ Anthropic `thinking`.**
  - Non-streaming (`openAIChatToAnthropic`): a leading `{type:"thinking",thinking}`
    block before the text.
  - Streaming (`OpenAIChatSSETranslator`): a `thinking` content block
    (`content_block_start type thinking` → `thinking_delta` → stop) before the
    text/tool blocks, integrated into the sequential-block state machine (added a
    `"thinking"` kind).
  - **No `signature`** is emitted — the block is synthesized from a non-Anthropic
    model (display-only), and the request-side translator drops `thinking` blocks
    so it never needs a valid signature upstream. Gated by
    `proxy.map_reasoning_to_thinking` (default on).
- **`reasoning_effort` passthrough** — `proxy.upstream_reasoning_effort`
  (`low`/`high`/`max`) → OpenAI top-level `reasoning_effort`; omitted when unset
  (non-reasoning backends may reject it). K3 defaults to `max` server-side.
- **Vision passthrough** — Anthropic `image` blocks → OpenAI `image_url` parts
  (base64 → `data:` URI; `url` → url; Files-API `file` sources dropped, no OpenAI
  equivalent). `OpenAIChatMessage.content` is now `string | OpenAIContentPart[]`;
  it becomes an array only when images are present (text-only stays a string, so
  existing behavior/tests are unchanged).

Wired through `proxy-runtime` for the `openai`/`ollama` translating provider
(reasoning_effort into the request, mapReasoning into both response paths). Gemini
has its own thinking/vision model and is untouched by this change.

## Verification

- **+7 unit tests**: request `reasoning_effort`, vision (base64/url/file), and
  non-streaming + streaming `reasoning_content`→thinking (incl. the
  `map_reasoning_to_thinking=false` off-switch). Suite **1244** green;
  tsc/biome/format clean.
- **Regression-smoked** the existing Ollama stream path (no `reasoning_content`
  from `qwen2.5-coder:7b` → no spurious thinking block; plain text unaffected).
- **Not live-tested for the new features** — my local Ollama model is neither a
  reasoning nor a vision model, so `reasoning_content`/image paths can't be
  exercised here. A live check needs Kimi K3 (+ a key). Same honest posture as
  the b3 tool-use path.

## Caveats (documented)

- Synthesized `thinking` blocks carry no Anthropic signature (fine for display;
  disable via config if a client objects).
- Multi-turn: Golem rebuilds each request from Anthropic history and drops
  `thinking` outbound, so the reasoning trace isn't preserved across turns (K3
  recomputes). The K3 doc's "feed the full assistant message back" is not honored.
- `reasoning_effort=max` (K3's default) is the priciest; set the config to `low`/
  `high` to cut cost.

## Scope / interfaces

No frozen `src/interfaces/` change; the Anthropic byte-faithful path and the
Gemini translator are untouched. Two new non-secret config leaves
(`upstream_reasoning_effort`, `map_reasoning_to_thinking`).
