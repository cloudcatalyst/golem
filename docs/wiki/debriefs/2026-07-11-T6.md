# T6 — file watcher (`golem index --watch`, `ingest` MCP tool `watch: true`)

`GolemKnowledgeBase.ingest(path, projectId, watch: true)` (`src/knowledge/knowledge-base.ts`)
threw `NotImplementedYetError` unconditionally — `golem index --watch` and the
`ingest` MCP tool's `watch` param were unimplemented promises (C2 follow-up).
[[ADR-0001-file-watcher]] is the required decision memo; this task builds what
it decided.

## What changed

- `src/knowledge/file-watcher.ts` (new): `watchPath(root, onBatch, options?)`
  returns a `FileWatcher` (`close()`). Backend picked per ADR-0001 —
  `fs.watch(root, { recursive: true })` on `win32`/`darwin`; a hand-rolled
  `TreeWatcher` (one non-recursive `fs.watch` per directory, added/removed as
  subdirectories appear/vanish) everywhere else. Both feed one shared
  debounce-then-re-stat layer: events collapse into a `FileChangeBatch`
  (`changed`/`removed`, classified by a fresh `stat`) after a quiet period
  (default 500ms), filtered through the existing `SKIP_DIRS`/dot-dir/
  `isChunkableExtension`/`MAX_FILE_BYTES` rules so watch mode never reindexes
  what a full `ingest()` would have skipped anyway. Every native `FSWatcher`'s
  `error` event fails open (drop that watcher/subtree, keep the rest running)
  rather than crashing the host process.
- `src/knowledge/ingest.ts`: exported `SKIP_DIRS` and `toPosix` (previously
  module-private) so the watcher and `GolemKnowledgeBase` could reuse the same
  skip-list and path-normalization instead of duplicating it.
- `src/knowledge/knowledge-base.ts`: `ingest()` now always does the full
  initial index first; if `watch: true` it additionally requires a deletable
  driver (fails fast at call time — the alternative, starting a watcher that
  can never actually reindex, would fail silently on every event instead),
  resolves the same `baseDir` `reindexFiles` expects, and starts `watchPath`.
  Each batch calls `reindexFiles`/`removeSourcePaths` (existing incremental
  machinery, unchanged) through a private `#applyWatchBatch`, whose errors are
  swallowed — a failed reindex must not crash the process; the next change
  event retries. Added `closeWatchers()` (extra capability, not part of the
  frozen `KnowledgeBase` contract) so callers/tests can stop watching.
- No changes needed in `src/cli/main.ts` (`golem index --watch`) or
  `src/mcp/server.ts` (the `ingest` tool's `watch` param) — both already
  called `knowledge.ingest(..., watch)` and reported `report.watching`,
  waiting on this task to make that call actually work instead of throw.

## Design notes

- The `platform` option on `watchPath` exists only so tests can force the
  Linux `TreeWatcher` branch (or, conversely, confirm the native branch)
  regardless of the host OS running the suite — it cannot make the real OS
  lie about native `recursive` support, only select which of our own code
  paths runs.
- Filtering (`SKIP_DIRS`, dot-dirs, extension, size cap) lives in the watcher,
  not the caller: the native recursive backend reports every path under root
  unconditionally (Node has no way to exclude `node_modules` from a recursive
  watch), so without this filter a `git checkout` or `npm install` would
  trigger a reindex storm.
- Directory-only change events are not classified as `changed` (a directory
  never matches `isChunkableExtension`), so `TreeWatcher` discovering a new
  subdirectory doesn't itself trigger a reindex — only the files that
  eventually land inside it do.
- Out of scope (unchanged): no wiring of `golem mcp serve` to auto-start
  watch mode on the whole project — this task ships the capability behind
  the two existing surfaces (`--watch`, `ingest` tool's `watch` param) that
  already called it; a project auto-watch-on-serve is a natural follow-up,
  not requested here.

## Verification

- New tests: `tests/unit/knowledge/file-watcher.test.ts` (7 — debounce/batch
  collapsing, removed classification, `SKIP_DIRS`/extension filtering,
  `close()`, the Linux `TreeWatcher` picking up a new subdirectory, and a
  `win32`/`darwin`-gated native-recursive nested-file case), plus
  `tests/integration/knowledge-watch.test.ts` (3 — real `GolemKnowledgeBase`
  end-to-end: watching:true, a live create is searchable, a live delete drops
  its chunks). Updated `tests/unit/knowledge/ingest.test.ts`'s old "watch:true
  is refused" case to match the new behavior (starts watching; a second case
  covers the still-refused non-deletable-driver path).
- Full gate: `tsc --noEmit`, `npm run lint`, `npm run format:check`, `npm test`
  (728 tests, 77 files) all clean. Rebuilt and restarted the proxy; confirmed
  `.golem/settings.json` still has `"level": 5`.
