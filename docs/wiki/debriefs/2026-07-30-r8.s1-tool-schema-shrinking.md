# R8.S1 — tool-schema shrinking, rejected by its own instrument

**Verdict: REJECTED. Nothing shipped to the request path; the instruments shipped.**

R8.S1 was the roadmap's "next by evidence", promoted twice. §89 closed with "the
target is the input schemas (~2900 tokens)". §95 raised the ceiling from ~3.8k to
**18,827 tokens** by measuring a real request and called the `tools` block the
largest single block in it. Both statements were true about their own subject. The
conclusion drawn from them was not, and one measurement ended the workstream.

## What was built

1. **The `tools` block decomposed, per definition** (`src/proxy/context-ledger.ts`).
   Owner (`golem` / other `mcp` / client `builtin`, read off Claude Code's
   `mcp__<server>__<tool>` namespacing), description tokens, input-schema tokens,
   everything-else tokens, and `defer_loading`. Surfaced in `golem stats --context`,
   which now leads with **who owns the tokens** before showing the biggest
   definitions. Optional in the zod schema so a ledger written by an older build
   still parses instead of being discarded as schema drift.
2. **Three cumulative schema transforms** (`src/tools/shrink.ts`): `schema-meta`
   (drop the `$schema` dialect URI), `schema-validation` (+ numeric/length bounds,
   `pattern`, `additionalProperties`), `schema-descriptions` (+ every per-property
   `description`). Structural keys — `type`, `properties`, `required`, `enum`,
   `items` — survive every mode, asserted per mode.
3. **Two new gates**, because reusing §89's harness unchanged would have been
   self-deception:
   - `--render full` shows the chooser each definition's schema. §89's prompt
     rendered `- name: description` and nothing else, so a schema transform scored
     against it shows a zero delta **by construction** — the harness would be blind,
     not the transform safe.
   - `runArgumentHarness` + `validateAgainstSchema` (`src/tools/arguments.ts`) score
     **argument construction**: show one tool's schema and a request, take the
     arguments, validate them against the **original** schema, and check the fields
     the prompt states outright. This is the failure mode a selection gate
     structurally cannot see — the model picks the right tool and then fills it in
     wrongly. Grading against the original and never the shrunk schema is the
     anti-self-deception property, and it has its own test: a transform must not be
     able to pass by relaxing the rules it is judged on.
   - The argument half can **veto**: an argument regression forces `REGRESSED` even
     when selection is untouched.

## What the measurement said

`golem stats --context`, live, 188 messages, ~139,327 tokens:

| owner | tokens | share | tools |
|---|--:|--:|--:|
| **client built-ins** | **17,473** | **93.9%** | 18 |
| **Golem MCP tools** | **1,130** | **6.1%** | 6 |

Golem's entire tools-block contribution is **1,130 tokens — 0.8% of the request**.
That was always the whole budget R8.S1 could work with. One client built-in
(`Workflow`, 5,264 tokens, 4,753 of them prose) is **4.7× Golem's total**.

Three corrections fell out of the same capture:

- **§89's "~2900 tokens of input schemas" was an artifact.** It subtracted
  descriptions from the `listTools` definition total and attributed the remainder to
  schemas. Golem's input schemas are **~1,128**; the missing ~1,800 is `outputSchema`
  (~1,522) plus `title`/`annotations`/`execution`/`_meta`. On the wire, `other keys`
  averages **~21 tokens per tool** — just `name` and `type` — so **Claude Code
  forwards none of that MCP metadata to the API.** It was never billed and there was
  nothing to reclaim.
- **On the wire, prose outweighs schemas 2:1** (12,146 vs 5,947), inverting §89's
  conclusion completely.
- **Claude Code's MCP deferral is client-side and genuinely shrinks the wire.** The
  forwarded array carries an entry named `DeferredToolPlaceholder` (51 tokens) and a
  client tool `ToolSearch`, with **no** `tool_search_tool_*` server tool; only the 6
  Golem tools this session had used appear as full definitions. The API docs
  (§89(1)) correctly describe the *API feature* transmitting every deferred
  definition — the client evidently does something else. Recorded as an
  **observation, not a contract**: undocumented, internal to the client, subject to
  change. But it means an unused Golem tool costs approximately nothing.

## The A/B, and why its clean result is not a pass

Chooser `qwen2.5-coder:7b`, temperature 0, `--role drafter`:

| transform | schema tokens | selection acc | args valid | fields correct |
|---|--:|--:|--:|--:|
| `schema-meta` | 1128 → 998 (−130) | 92.0% → 88.5% | 92.9% → 92.9% | 92.9% → 92.9% |
| `schema-validation` | 1128 → 854 (−274) | 92.0% → 92.3% | 92.9% → 92.9% | 92.9% → 92.9% |
| `schema-descriptions` | 1128 → **357 (−771, 68%)** | 92.0% → 92.3% | 92.9% → 92.9% | 92.9% → 92.9% |

**The argument columns are an instrument limit, not a clean pass.** They are
byte-identical in every mode, and the single failing case fails in *both* arms:
`arg-search-2` passes `k: 100` while `maximum: 50` sits in the schema it was shown.
A 7B coder model at temperature 0 answers from the prompt text and the tool name,
not from schema annotations — so removing all of them changes nothing it does. That
is evidence about the chooser. The production reader is Claude, and §89's caveat
holds with more force here: a null result from this harness is weak evidence of
safety, never proof.

So the rejection rests on arithmetic instead, which is stronger. Even `schema-meta`
— dropping a JSON-Schema dialect URI, provably invisible to any model — is worth
**~72 tokens on the wire** across Golem's 6 forwarded tools: **0.05% of the
request**, in exchange for mutating a cached prefix that otherwise bills at ~0.1×.
Not a trade worth making.

## What this closes

**R8.S1 is closed, and the tools-block line of work is de-prioritised** — third
promotion refused. Three separate transforms across two batches have now been
measured and none shipped: whitespace (zero saving), first-sentence (triples false
positives), and all three schema modes (0.05% at best). The remaining lever on this
block is Anthropic's own deferral, which is already GA, already relayed faithfully,
and already active here.

What ships is the instrument, so nobody promotes this a fourth time on an aggregate:
the per-definition decomposition, and two gates that are the right shape for judging
*any* future schema change — carrying the recorded caveat that the local chooser
cannot currently exercise them.

## Lessons

- **A ceiling is not a lever.** §95's 18.8k was correct and led somewhere wrong,
  because it never asked who owned the tokens. "Attribute before you optimise"
  belongs beside "measure before you build".
- **Build the gate for the failure mode you are about to create, not the one you
  already have.** Reusing §89's selection harness for a schema transform would have
  produced a confident zero delta and shipped the transform.
- **Say when the instrument is the thing that failed.** The flat argument columns
  look like a pass. Reporting them as one would have been the most expensive
  sentence in this batch.

## Standing gap (now twice-observed)

The tier-2 `classifier` model (`qwen2.5:7b`) has never been pulled on this machine,
so §89 and §100 both fell back to `--role drafter`. `golem devices` lists the tier's
*catalog*, not what Ollama has actually downloaded — the same class of gap as the
2026-07-17 judge bug. Worth a real check rather than a third caveat.

Also unrelated but noted: the `coder` MCP tool is disabled in this project
(`inference.local_coder_enabled`), so the local-coder-first rule could not be
followed for this batch's drafting.
