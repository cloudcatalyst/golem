# R1.4 — provider-key redaction rule gaps closed (T-C3)

Closes the residual gap noted in verification-notes §24: four provider
secret shapes had no dedicated rule and relied solely on the entropy-sweep
backstop, which can miss short or low-entropy instances.

## What changed

- `src/pipeline/redaction-rules.ts` — four new `REDACTION_RULES` entries:
  `google-api-key` (`AIza` + 35 chars), `stripe-key` (`sk_live_` + 24-99
  chars, the underscore variant the existing `sk-` `openai-key` rule can't
  match), `gcp-oauth-token` (`ya29.` + 20-120 chars), and
  `azure-account-key` (contextual, redacts only the `AccountKey=` value,
  `group: 1`, mirroring the existing `connection-password` rule's pattern of
  preserving surrounding legible context).
- `tests/unit/pipeline/redaction.test.ts` — one positive/negative `CASES`
  pair per new rule.
- `docs/verification-notes.md` — new §56 documenting the fix; §24 marked
  fixed with a pointer to §56.
- [[Redaction Stage]] — appended the four new rules to the "Known
  false-positive classes" narrative (append-only per wiki zone rules).

## Design notes

- Rule placement follows the file's existing most-specific-first ordering:
  the three prefix-based rules go after `slack-token`; `azure-account-key`
  goes after `connection-password` and before `credit-card` since it's
  contextual like the former.
- Scope is deliberately bounded to §24's named list (Google, Stripe, GCP,
  Azure) — not a claim of exhaustive provider coverage. Other providers stay
  on the entropy-sweep backstop, consistent with §24's original "add rules
  as needed" stance.

## Verification

- Fixtures built with deterministic `.repeat()/.slice()` construction
  (matching the file's pre-existing style, e.g. `sk-${"A1b2".repeat(9)}`)
  rather than hand-typed literals, so correctness doesn't depend on
  visually counting secret-shaped characters under the redaction escape
  hatch documented in §55 (this repo's own session is proxied through
  Golem's redacting proxy, so secret-shaped content I author myself can
  render back to me as `[REDACTED:...]` placeholders on the next turn —
  verify via test pass/fail or structure-preserving views, not visual read).
- One `biome format --write` pass was needed to reflow the
  `azure-account-key` negative fixture's long line before lint/format:check
  went clean.
- Full gate: `tsc --noEmit`, lint, format:check clean; `npm test` — 730
  tests (722 + 8 new), including every pre-existing negative case (repo
  paths, integrity hashes, ASCII byte dumps, git SHAs, UUIDs), all pass.
