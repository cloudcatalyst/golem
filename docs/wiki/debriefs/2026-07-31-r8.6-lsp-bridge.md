# R8.6 — the LSP bridge

**Verdict: shipped, off by default.** Golem can spawn a language server the user
already installed and ask it four questions — `diagnostics`, `definition`,
`references`, `hover` — as **modes of the existing `code` tool**. The map
([[Repo Map]]) says what exists; the language server says what refers to what.

## The two constraints that shaped everything

**§100: a tool definition is a permanent per-request bill.** Four capabilities meant
four tools in the OpenCode design this was drawn from. Here they are one tool with a
`mode`, and the census now shows what that decision is worth rather than asserting it:
**+333 full-definition tokens** for the four modes, against a fixed ~250–320-token
envelope *per tool* that four separate tools would each pay (`devices`, with a 9-token
schema, still costs ~318 full). See §109 for the table.

**Decision 53, tier 2: the user brings the server.** Golem ships no language server's
bytes, spawns only what is on `PATH`, and treats absence as a no-op. The registry row
(`typescript-language-server`) records the pin-free install line and — the field that
matters — a `gate` saying that *enabled does not mean running*: the server is spawned
lazily on the first LSP-mode call, pooled, and evicted when idle.

## The shape of the cost: zero when off

The LSP mode enum, the `file`/`line`/`character`/`symbol` parameters and the extra
prose are added to the tool's schema **only when the bridge is injected**
(`knowledge.lsp_enabled`, default `false`). A user who never enables it pays nothing
per request for it — measurably nothing: the default census is 22 tokens *cheaper*
than before R8.6, because making the map-only output fields optional shortened the
serialised schema.

`golem bench tools --lsp` exists so the on-state is measurable. The default census
keeps reporting the configuration users actually ship — the [[Cache Observability]]
rule that §104 had to re-learn the hard way.

## Lifecycle was the risk, not the protocol

A language server is a long-lived process with a handshake. In an editor a hung one
shows a spinner; in an agent tool call it burns the turn. So every wait is bounded:
the `initialize` handshake, every request, and the graceful `shutdown`/`exit` on the
way out, after which the process is killed. A dead server rejects pending work
immediately instead of leaving it pending, and the pool re-spawns on the next call.
`process.once("exit")` kills every pooled child synchronously, because a parent that
dies must not orphan a language server.

Two protocol details are load-bearing and both are covered by unit tests:
`Content-Length` counts **bytes, not characters** (a non-ASCII identifier in a hover
string desynchronises a char-counting encoder forever), and a chunk boundary can fall
anywhere — mid-header, mid-JSON, or between two complete frames.

## Verified with a fake server, on purpose

`tests/fixtures/fake-lsp-server.mjs` speaks just enough LSP to exercise the real spawn
path with this process's own `node`. Golem must depend on no language server, and CI
has none installed — but the risk is protocol and lifecycle, which are identical
whoever is on the other end. 17 integration tests cover the four modes, byte-at-a-time
framing, and every degrade path: binary absent, extension unclaimed, handshake
timeout, request timeout, mid-session crash, protocol desync, unreadable file, missing
position. Every one resolves to `available: false` plus a reason. None throws.

**What that does not prove:** `typescript-language-server`'s own behaviour — how long
a cold project load takes against the 15s default timeout, and whether the 400ms
diagnostics settle window suits its two-phase publish. Live-traffic questions, left as
such.

## The open question this shares with R8.5

Whether an agent handed `definition`/`references` actually *stops* grepping and
reading whole files. That displacement claim is the justification for both features
and neither has evidence yet — §101 measured retrieval accuracy for the map (+21.4
points), not avoided reads. It stays open, and it stays named.

## How to turn it on

```
golem config set knowledge.lsp_enabled true
npm i -g typescript-language-server typescript
# then reconnect the golem MCP server in Claude Code
```

Any other server (gopls, rust-analyzer, pyright) is a `knowledge.lsp_servers` row —
config, not a Golem release. A row Golem asserted but could not exercise would be
exactly the unverified claim the [[Managed Tools]] registry exists to prevent.
