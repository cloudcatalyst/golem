# R8.11 — the plugin surface (2026-08-01)

Third-party **pipeline stages**, **MCP tools** and **redaction rules** without forking.
The task named its own precondition — *"a plugin runs inside the process that sees
unredacted prompt content; write the threat model before the seam"* — so
[ADR-0004](../../decisions/ADR-0004-plugin-seams.md) was written first and accepted
before a line of seam code existed. Concept page: [[Plugin Seams]].

## The finding: the scary seam is the one that needs no code

The obvious framing going in was "plugins are dangerous, so sandbox them." That framing
does not survive contact with the actual demand. The seam people want is **redaction
rules** — every org has a private key format, and extending redaction today means
editing `src/pipeline/redaction-rules.ts`, i.e. a fork. It is also the seam pointed
straight at unredacted secrets.

But look at what such a plugin actually needs to express: a pattern, maybe a capture
group, maybe a checksum. **That is data.** So seam A accepts a descriptor —
`{id, description, pattern, flags?, group?, validate?}` — where `pattern` is a string
Golem compiles and `validate` *names* one of Golem's own validators rather than supplying
one. No third-party function is ever called on unredacted text, because there is nothing
to call. The exfiltration vector doesn't get mitigated; it doesn't exist.

The two seams that genuinely need code — stage and tool — got placed where running code
is survivable rather than wrapped in a boundary that wouldn't hold: a stage sees only
already-redacted content and runs only in the lossy slot; a tool is off the request path
entirely.

## What is enforced by construction, not by care

- **Append-only.** `REDACTION_RULES` stays a frozen const; plugin rules are a separate
  list applied after it. There is no remove/replace/reorder API. The contract test
  asserts the *exported names* of `plugin-rules.ts`, so a future `removeBuiltinRule`
  fails the day someone writes it — a stronger guard than a behavioural test, which
  would only catch the misuse and not the capability.
- **Seam B cannot break byte-fidelity.** Gated identically to semantic compression:
  `semanticCompression !== "off"` AND a non-caching upstream. At slider ≤1, and on
  Anthropic at any level, the block does not execute. Asserted at all four levels.
- **A plugin cannot impersonate a built-in** — ids namespace to `<plugin>/<id>`, tools to
  `<plugin>__<name>`.
- **Consent is per seam.** Listing a package grants nothing; `seams: ["redaction"]`
  grants exactly that, and an ungranted stage is dropped *and reported*.
- **Every failure is a described no-op.** `unresolved` / `import-failed` /
  `invalid-export` / `pin-mismatch` / `no-seams-enabled`, each a row in
  `golem plugin list`. A plugin that throws at import does not stop the next one loading.

## Two bugs the tests found, both in the over-redaction cap

The cap (ADR-0004 threat 5) drops plugin rules for a string they would swallow. The first
implementation measured the **change in length**, and it was wrong twice over:

1. **It misfired on ordinary use.** A placeholder is longer than most secrets, so three
   badge ids in a short string *grew* the text by more than the cap allowed — and the cap
   silently discarded a correct redaction. The determinism test caught it as "the rule
   didn't fire", which is exactly how this would have presented in production: not as an
   error, as a rule that mysteriously does nothing sometimes.
2. **It missed the case it existed for.** A rule replacing an entire 43-char string with
   a 28-char placeholder is a 15-char delta — under any sane threshold. Total swallow,
   undetected.

Both fixed by measuring **matched input characters** (`applyRule` now reports them), and
by only applying the cap to strings ≥200 chars — because a message that *is* one API key
is a legitimate 100% match, and clamping it would break the seam's main use. The ADR was
amended to record both, since the wrong version was written into it first.

## Named, not fixed

**ReDoS.** Node cannot interrupt a running regex, so a pathological pattern blocks the
event loop and no in-process check can prevent the first stall. Shipped: a static lint
rejecting nested unbounded quantifiers, quantified identical alternations and over-long
patterns, plus post-hoc per-rule timing surfaced in `golem plugin list`. The complete fix
is an out-of-process host under Node 22's `--permission` model; it was **declined
deliberately** (user decision, recorded in the ADR) because it would put an IPC
round-trip on every request's critical path to close a gap that only opens for someone
who installs a plugin, pins it, and enables the seam.

**No sandbox for seams B and C**, stated plainly rather than implied away. `worker_threads`
is not a security boundary and neither is `vm`. The mitigations are consent, pinning,
visibility, and Golem never installing anything.

## Shipped

`src/interfaces/plugin.ts` (frozen contract — zero dependencies, so a plugin needs
neither zod nor the MCP SDK), `src/plugins/` (loader, seam-A compiler, quarantine
adapters), `src/pipeline/plugin-rules.ts` (the installation point), `plugins.entries`
settings, `golem plugin list [--json] [--verbose]`. 43 new tests across a contract file
and an integration file that writes real ESM plugins to a temp dir and imports them with
the real loader — the import *is* the seam, so mocking it would have tested nothing.

The shipped default is an empty registry: nothing resolves, nothing imports, no tokens.
