# R1.2 — positioning call: universal pre-LLM processor (Decision 32)

R1.1 (see [[R1.1 — net-of-cache billed-usage A/B]]) found that levels 1 and 3
are pipeline-identical on Anthropic — Decision 23's claim that compression is
"situational, true mainly on non-caching upstreams" had no live traffic to
ever be true *on*, since Golem only fronts Anthropic today. That tension was
the R1.2 gate: the plan framed it as **assistant-for-Claude** (Decision 23's
current shape, R5.1 stays deferred, situational compression stays
theoretical) vs **universal pre-LLM processor** (Decision 22, commit to
building the Foundry/OpenRouter adapters so the situational claim has
somewhere real to land).

## The call

The user chose **universal pre-LLM processor**. Recorded as spec Decision 32
(`docs/golem-spec.md`).

## What it settles — and what it doesn't

- **Settles:** Decision 22 is now the active positioning, not a P3+ aspiration
  held at arm's length. `ROADMAP.md`'s R5.1 and `IMPLEMENTATION_PLAN.md`'s
  WS-F14 (provider-agnostic adapters, front Foundry/OpenRouter) are unblocked
  — the "product-positioning decision first" gate on both is now satisfied.
- **Does not settle:** whether/when R5.1/WS-F14 actually gets *built*.
  `R1_BATCH.md` §3 explicitly keeps all WS-F* work out of scope without a
  separate ask — Decision 32 unblocks the *positioning*, scheduling the build
  is a distinct future decision.
- **Does not touch:** the Anthropic byte-faithful guarantee (CLAUDE.md
  proxy-fidelity rule, Decision 31's `isCachingUpstream` gate) or Decision
  23's evidence that lossless compression is ~0% on cached Anthropic traffic.
  Foundry/OpenRouter adapters are additive, separate code paths per Decision
  22's own architecture note.

## What changed as a direct consequence

Positioning copy that predated this call now read narrower than the decided
scope, so it was revised in the same commit:

- `README.md` — was "edge offload **for Claude**," leading with compression
  ("cuts Claude token spend"). Now leads with the pillars (redaction / local
  tools / routing / honest observability), names Claude Code as the flagship
  integration rather than the whole identity, and keeps compression explicitly
  situational (cites R1.1's ~0%-on-Anthropic finding rather than a headline
  savings number).
- `CLAUDE.md`'s "What this project is" — same shift: universal pre-LLM layer
  first, Claude Code named as the flagship/most-verified integration, other
  gateways named as the not-yet-scheduled extension.
- `docs/plan/ROADMAP.md` / `IMPLEMENTATION_PLAN.md` — R5.1/WS-F14 rows updated
  to reflect the resolved gate; the decision/research backlog's #1 and #2
  items (R1.2, R1.1) marked resolved.

## Why this direction over the alternative

Grounded in verification-notes §30-37 and §54: Decision 23's honest-evidence
positioning (redaction/local-tools/routing/observability as the durable
pillars, compression demoted) doesn't change under either option — that
evidence stands regardless. What differs is whether Golem's *scope* stays
bounded to Claude (making the situational-compression claim permanently
theoretical, since Anthropic is always a caching upstream) or expands to
include non-caching gateways where that claim can actually be tested and, if
real, delivered. The user's call was to pursue the latter rather than let the
situational claim sit unfalsifiable.

## Open follow-ups

- R5.1/WS-F14 needs a design memo (adapter surface: auth, streaming, tool-use
  translation per provider) before any build ask, per `R1_BATCH.md` §3 and
  the WS-F9/F11/F12-style gating convention already used for other WS-F items.
- The situational-compression claim is still unverified even under the new
  positioning — it becomes *testable* once an adapter ships, not proven by
  this decision alone.
