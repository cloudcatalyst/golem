# R4.7 — drafter quality & catalog re-verification

Spike outcome for the co-developer thesis's foundation: is the per-tier coder
catalog still current, and how good are the local drafts in practice?
Full detail (sources, dated) in `docs/plan/verification-notes.md#§63`.

## Catalog re-verification (Decision 6, advisory) → no change

- **Qwen3-Coder** is the 2026 default for agentic/multi-file coding, but
  **Qwen2.5-Coder still narrowly leads on single-function/single-file code** —
  which is exactly the `drafter` role's job (cheap first draft, Claude refines).
- **`qwen3-coder` on Ollama only ships 30b/480b** — no small tags, so Golem's
  P_CPU/P_MIN/P_MID tiers have nothing to switch to. Kept qwen2.5-coder
  (1.5b/3b/7b/14b). Optional future upgrades noted but not made (unmeasured
  model swaps violate Decision 23's evidence-first rule): P_MAX → `qwen3-coder:30b`
  for 24GB+ agentic use; non-coder roles → qwen3 dense line.

## Measured draft-quality baseline (ungrounded, n=5)

Ran representative repo tasks through `coder`. The running MCP server predates
R4.2 grounding / R4.4 refinement, so these are the **ungrounded one-shot
baseline** [[R4.3 — Honest tool telemetry: measuring the co-developer]]'s
`tool_usage` bucket will track over time.

| verdict | tasks |
|---|---|
| accept (2) | small self-contained `clampSliderLevel` fn; a `union` vitest suite |
| revise (3) | the `/golem/plan` skill, `gatherGrounding`, `coder-refine.ts` — all project-integrated |
| reject (0) | — |

**2/5 accept, 3/5 revise, 0/5 reject.** The pattern is the finding: drafts are
**accept-quality for small self-contained code, revise-quality for anything
touching project conventions/APIs** (it invents plausible-but-wrong integration
details). This is precisely why [[R4.2 — Coder grounding: retrieval-augmented drafting]]
and [[R4.4 — Coder iteration loop: draft → judge → revise]] exist, and why
CLAUDE.local.md says skip `coder` for trivial edits and treat every draft as a
starting point.
