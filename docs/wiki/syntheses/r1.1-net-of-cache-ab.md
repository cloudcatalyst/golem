# R1.1 — net-of-cache billed-`usage` A/B (level 1 vs level 3)

Decision 23 (verification-notes §30-37) established that gross forwarded-token
reduction is not an honest savings metric on a caching upstream — only the
upstream's actual billed `usage` block is. R1.1 was the batch's #1 strategic
gate: capture that block from real Claude Code traffic and run a live A/B.
Full detail and numbers are in verification-notes §54; this page records the
durable conclusion and the reusable pattern, not the raw data.

## What shipped

- `ResponseUsage` + `UsageSniffer` (`src/proxy/usage-sniffer.ts`): a read-only
  `Transform` that forwards every response byte untouched while opportunistically
  extracting the Anthropic Messages API `usage` block, for both non-streaming
  JSON and SSE. Fails open throughout — never delays or alters what the client
  receives.
- `recordUsageEvent` / `aggregateUsageByLevel` (telemetry) and
  `effectiveInputTokens` / `usageReportRows` (`src/telemetry/usage-report.ts`):
  an additive `kind: "usage"` JSONL line, kept out of the existing gross-token
  `aggregate()` headline, rolled up per slider level with Anthropic's cache
  pricing multipliers (input 1×, cache write 1.25×, cache read 0.1×, §14).

## The bug that would have invalidated the whole measurement

Real Anthropic responses proxied through Golem are `content-encoding: gzip`
(the client's `accept-encoding` is forwarded transparently). The first
`UsageSniffer` sniffed raw bytes assuming plaintext — it silently found zero
usage on all real traffic while every fixture-based test passed (fixtures were
never gzip-encoded). Fixed with a side `zlib` decompression stream fed a copy
of each chunk; the bytes pushed to the client stay the original (compressed)
chunk. **This is the load-bearing reason R1_BATCH.md's Definition of Done
requires driving the real flow, not just green tests** — this bug was invisible
to the test suite by construction.

## The actual finding: there's currently nothing to A/B on Anthropic

The measurement ran, but the honest conclusion isn't "level 3 costs X% more/less
net of cache" — it's that **levels 1 and 3 are code-provably pipeline-identical
on this upstream**, so no such number is meaningful yet:

- `src/interfaces/policy.ts`'s `LEVEL_TABLE` gives level 1 and level 3 the same
  `redaction`/`losslessCompression` config.
- The one stage that does differ (`semanticCompression`) is unconditionally
  gated off by `isCachingUpstream()` in `src/pipeline/pipeline.ts` whenever the
  upstream host contains `anthropic.com` (Decision 31) — which this repo's real
  traffic always does.
- So the request bytes actually sent to Anthropic are identical between level 1
  and level 3, and the ~30% gap observed in raw telemetry is sampling noise plus
  one clear confound (this very conversation's own context-compaction event
  resetting the cache prefix mid-session, unrelated to the slider).

Decision 31's caching-upstream gate — built for a different reason (avoiding a
lossy stage that breaks the cached prefix) — already had the side effect of
closing the net-of-cache risk R1.1 set out to quantify. There is no live A/B
signal left to find at level 1 vs 3 on Anthropic until that gate's shape
changes.

## Where a real net-of-cache A/B would live

The open question already on record (§53): can Headroom's `read_lifecycle` be
disabled to build a **cache-safe structural** compression tier for level ≥2 on
Anthropic? If so, the meaningful comparison becomes *structural-only vs pure-
lossless*, both cache-safe — that's where a future net-of-cache A/B carries
signal, using the exact same `UsageSniffer`/`aggregateUsageByLevel` machinery
built here. This task's infrastructure is reusable as-is; only the two
conditions being compared need to change.

## Side discovery, not yet actioned

The redaction entropy sweep flagged a bare UUID path segment (this session's
own scratchpad directory name) as high-entropy and redacted it out of resent
conversation history mid-task, corrupting a bash command that referenced it.
`T7` (2026-07-10) already fixed the sweep eating *repo* paths via
`isPathLikeToken`; this is a related but distinct false positive outside that
fix's coverage. Logged in verification-notes §54 as a candidate alongside the
existing credit-card/Luhn false positive (ROADMAP R1.3) — not reproduced or
fixed here.
