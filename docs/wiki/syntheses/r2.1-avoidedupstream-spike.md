# R2.1 — avoidedUpstream measurement spike

Spec Decision 24 proposes proxy-side KB/web-cache answer substitution —
tokens that never have to round-trip upstream at all, a different metric
from compression's request-shrink. It was deliberately left "design memo
only, not built" pending a spike to see whether real usage data already
shows the opportunity is worth building for. Full detail in
verification-notes §59; this page records the durable conclusion.

## What was measured

This repo's own `.golem/telemetry/events.jsonl` (5644 lines) plus a source
read of every MCP tool call site (`src/mcp/server.ts`) to check whether
`search`/`fetch`/`ingest`/`wiki_read` invocations leave any durable trace.

## The finding

- **No telemetry exists yet for the thing Decision 24 actually needs
  measured.** `search`/`fetch`/`ingest`/`wiki_read` tool calls are not
  instrumented at all — there is no durable signal for how often a local
  KB/web-cache hit was good enough to have shortcut an upstream turn.
- The only real, instrumented proxy signal is the existing CCR
  reference-swap/retrieve mechanism (`[[Distillation Pipeline]]`-adjacent,
  but really the tool-output digest path from `CLAUDE.local.md`): across
  this repo's whole history, Golem swapped bulky tool output for a compact
  reference **1051** times, and the `expand` tool that would pull the
  original back was called **0** times.
- That 0-miss rate is encouraging but indirect — it's evidence that
  reference-substitution as a *shape* works (models don't reflexively pull
  back what they don't need), not evidence about KB-answer substitution
  specifically, which this repo has never built or measured.
- The local KB itself is non-trivial (two indices, ~4000 chunks total) so
  there's real material to substitute from; the web-cache is tiny (10
  entries) so re-fetch dedup is a small lever in this particular repo.

## What this means going forward

- **R2.2** (context-substitution, conservative sub-mode) should ship with
  its own `avoidedUpstream` telemetry bucket from day one, built the same
  way `recordRetrieval` already is — that shipped instrumentation becomes
  the actual measurement this spike couldn't produce, rather than
  retrofitting telemetry after the fact.
- **R2.3** (local-answer, aggressive sub-mode) has zero telemetry basis in
  this repo today. That's a real reason, not just sequencing convention,
  for R2_BATCH.md gating it behind both R2.1 and R2.2 landing first.
